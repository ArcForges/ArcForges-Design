# ArcForges Product and Engineering Design

ArcForges Design is the version-controlled home for product requirements, system architecture, significant decisions, delivery planning, and assurance criteria for the ArcForges product family.

This repository contains design artifacts, not product implementation. An accepted design does not mean that implementation, testing, performance validation, deployment, or release has been completed.

## Start here

- [`docs/governance.md`](docs/governance.md) defines document authority and lifecycle.
- [`docs/requirements/`](docs/requirements/) defines what ArcForges must deliver.
- [`docs/architecture/`](docs/architecture/) defines system structure and constraints.
- [`docs/decisions/`](docs/decisions/) records significant accepted decisions and their rationale.
- [`docs/planning/`](docs/planning/) will contain plans derived from accepted requirements and architecture.
- [`docs/assurance/`](docs/assurance/) defines traceability, risk, review, and acceptance.
- [`docs/inputs/`](docs/inputs/) preserves the source material used to create the canonical design.

## Repository map

| Area | Question answered |
|---|---|
| `docs/inputs` | What source material informed the design? |
| `docs/requirements` | What must the product family do, and for whom? |
| `docs/architecture` | How is the system structured and constrained? |
| `docs/decisions` | Why was a significant choice made? |
| `docs/planning` | In what dependency order will accepted work be delivered? |
| `docs/assurance` | How will completeness, quality, safety, and compliance be demonstrated? |
| `templates` | What common structure should new documents follow? |

## Current phase

The repository is being established from reviewed source material. Canonical requirements, architecture, and delivery work packages will be created through focused pull requests. No implementation sequence is accepted yet.

## Language and naming

Canonical requirements, architecture, decisions, planning, and assurance content is written in English. Names describe enduring responsibility rather than time, migration history, or a vendor. Informative source material may retain its original language so that it remains faithful to its origin.
