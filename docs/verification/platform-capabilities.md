# Platform capability verification register

Status: verified 2026-10-12 for the ArcForges flagship design (decision [AD-0001](../decisions/AD-0001-flagship-pivot.md)). V-W07–V-W11, V-L08 and V-A06, A-W04, A-W05 and A-A03, and F-W04, F-W05 and F-A03 were added on 2026-10-19 with the current-design corrections; the V entries rest on the primary sources linked in them, checked on 2026-10-18 and re-checked on 2026-10-19 (the Fedora PackageKit patch of V-L08 could not be re-fetched on 2026-10-19; V-L08 also cites a reachable Fedora discussion of the same rule).

This register separates three kinds of statement. The design cites them by ID.

- **V (verified):** confirmed against current primary documentation or source, with the source linked.
- **L (local probe):** observed directly on the development workstation (Windows 11 build 26300 and WSL2 Debian 13). A probe proves behaviour only for that environment, not for every deployment. The Linux probes (L-02 … L-12, L-22 … L-25) were measured in the workstation's WSL2 Debian 13 distribution and stay as historical evidence for that environment; since 2026-10-21 the Linux validation venue is a native Linux host ([AD-0018](../decisions/AD-0018-native-platforms-without-wsl-integration.md) §5).
- **A (assumption) and F (future validation):** an expectation the design relies on that is not yet proven. Each has an owner task in the delivery plan that must prove or refute it before dependent acceptance closes.

Mocked or simulated tests never upgrade an A/F item to V. Only a real run of the named mechanism does.

**Design consequences of L-26** ([04](../architecture/04-execution.md) §2, [16](../architecture/16-testing-strategy.md) §1–§2):
- Production behaviour is unchanged, and Credential Manager stays the node data key store. The design assumes no consistency of the OS store under concurrent modification. If the node data key is lost, the node fails closed: values sealed under that key are unavailable, nothing launches with a partial environment, and `RetryTask` fails with `STATE/secrets_unavailable`.
- Production read-back policy: production does not read back a node data key after writing it. The key stays in memory; a lost write surfaces at the next load (node restart) and fails closed as above. Read-back and absence checks are test verification only ([16](../architecture/16-testing-strategy.md) §1).
- Tests never depend on the store's behaviour under concurrency. Key lifecycle, sealing, failure injection and concurrency run against the isolated secret-store backend. A structural guard keeps routine tests away from the real store. Real-store tests are minimal and sequential, and verify absence after deletion, in the separate OS secret-store tier.

**Design consequences of L-27** ([AD-0005](../decisions/AD-0005-resource-enforcement.md) Linux §2, [03](../architecture/03-resource-control.md) §5.2, R-RES-007):
- Attempt units use `OOMPolicy=stop`. After the kernel kills a process at the unit's `MemoryMax`, systemd stops the whole unit through its ordinary stop: the end steps (`ExecStop`), then the stop signals to the remaining processes within `TimeoutStopSec` ([04](../architecture/04-execution.md) §3), and the exit record carries `oom-kill`. Unlike the stop after the root's own exit, this stop can start while the root process still runs: the end steps run first, and the forced phase then ends the root with the leftovers. The remaining processes therefore get the stop's short graceful phase instead of dying together with the victim. The per-attempt ceiling still holds: while the unit stays at `MemoryMax`, the kernel keeps killing inside it.
- No ArcForges unit sets `memory.oom.group`, through `OOMPolicy=kill` or directly, because any group kill can reach the user manager's spawn child. A test checks the value on every attempt unit.

## 2. Windows process and resource control

| V-W01 | A job object groups processes. Children created with `CreateProcess` join the job by default, unless breakaway is allowed (`JOB_OBJECT_LIMIT_BREAKAWAY_OK` with `CREATE_BREAKAWAY_FROM_JOB`, or `JOB_OBJECT_LIMIT_SILENT_BREAKAWAY_OK`). Nested jobs are supported from Windows 8. A hierarchy forms when a process already in a job is assigned to another job: assign it to the root job first, then to the child job, because a child must always hold a subset of its parent's processes or `AssignProcessToJobObject` fails. Jobs that set UI restrictions do not nest. A nested job's completion-port messages also reach every port in its parent chain. **Design consequences** (AD-0005 Windows):
- One named job per attempt, nested in a per-node named root job, with CPU rate control and a commit limit. **No** `KILL_ON_JOB_CLOSE` by default, so executions survive node restarts. Only `kill_with_node` tasks get it, and they run without a holder.
- A holder process per attempt keeps the jobs openable by name across node restarts (L-14) and writes the durable exit record with accounting.
- Memory pressure on Windows is a commit cap plus a notification-driven soft threshold, decided by the scheduler. Windows has no equivalent of Linux `memory.high`, and the design never claims one.
- Processes created through WMI, services, COM servers and the WSL VM are outside any job. ArcForges never reports them as controlled: the WSL VM is `GUEST_VM`, and the others appear as `UNMANAGED`, because their recorded ancestry does not pass through a job member, so the ancestry scan does not detect them as escaped ([03](../architecture/03-resource-control.md) §9; corrected 2026-10-19, it previously said "unmanaged or escaped"; A-W04).
- A process started with the parent-process attribute inherits the named parent's job (V-W10), so job membership alone does not contain same-user code. Named jobs and the ack event carry the default security descriptor (V-W11), so other processes of the same user can open them. Resource guarantees are therefore ENFORCED against accidental and over-privileged workloads and a GUARDRAIL against workloads that target ArcForges' objects ([03](../architecture/03-resource-control.md) §5; [11](../architecture/11-security-privacy.md) §1, T-22, T-23).
- UAC is not a security boundary (V-W07), and Administrator protection is off by default (V-W08). On an administrator account without Administrator protection, unconfined workloads may obtain administrator rights silently, although ArcForges never elevates ([AD-0005](../decisions/AD-0005-resource-enforcement.md) Process model; T-26).

**Design consequences** (AD-0005 Linux):
- **Node and executions.**
  - The Linux node runs as a systemd **user** unit (`arcforges-node.service`) and holds no executions in its own cgroup.
  - Each managed execution is a transient user unit in `arcforges.slice`, created over the user manager's D-Bus API. Limits are unit properties: `CPUWeight`/`CPUQuota`, `MemoryHigh`/`MemoryMax`, `OOMPolicy=stop` (L-27; formerly `OOMPolicy=kill`), `TasksMax`.
  - The node writes no cgroup file except `cgroup.freeze=0` to release a freeze that it or a dead node left (L-24). It pauses with `FreezeUnit`, signals with `KillUnit` in the graceful phase, kills a frozen unit process by process, and reads the cgroup files for statistics.

- **Keeping WSL alive** (*superseded 2026-10-21 by [AD-0018](../decisions/AD-0018-native-platforms-without-wsl-integration.md); kept as history: there is no bridge and no guest node*). - **Privileged changes without ArcForges elevating.** Requests over the system bus that polkit authorizes are not stopped by no-new-privileges (V-L08), so an unconfined workload may cause a privileged change although ArcForges never elevates ([11](../architecture/11-security-privacy.md) §1, T-26).

**Design consequences.**
- **Live connections.** Live node and viewer connections terminate in hibernating Durable Objects through a thin adapter. The C# container is needed only for business decisions, so it can sleep when idle.
- **Cost control.** Every metered cloud path is guarded by application-enforced quotas and operating budgets with kill switches. Cloudflare budget alerts are notification only and never count as cost control.
- **Telemetry storage.** Telemetry is local-first. D1 holds account, entitlement and registry data, never time-series telemetry.
