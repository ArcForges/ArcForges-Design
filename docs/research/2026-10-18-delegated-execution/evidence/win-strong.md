# Evidence record: Windows strong isolation, execution control and network control

Scope: research evidence of the 2026-10-18 delegated-execution study; evidence labels E1–E6 as defined in the study; not verification-register facts.

Date: 2026-10-18.

Source reports: the study report 10c (Windows strong isolation and control), including its inline verification markers and verification log, and the study's win-strong decision digest (section 1, mechanism fact sheet). Where a verification marker corrected the original report text, the corrected statement is used here.

Publication notes:
- **Publication:** curated 2026-10-19 for the public ArcForges-Design repository (`docs/research/2026-10-18-delegated-execution/`). Facts about the study's own workstation were removed or restated host-neutrally; no row describes a particular host.
- **Report section column:** names the section of the study report 10c the fact was drawn from ("study reconciliation" is the study's contradiction reconciliation). The study reports, digests and reconciliation are working files of the study and are not published; the primary-source column is the citable evidence.
- **Review corrections:** the study's review round of 2026-10-18 ruled some values in this file overstated or incomplete. The table at the end names each affected fact, the ruling and the corrected statement. Where a claim and its correction differ, the corrected statement governs. Claim text is left unedited so its provenance stays visible.
- "Analysis, no primary source" marks a claim that rests on the study's own reasoning.

Reading notes:
- "AF" means ArcForges and "WL" means the workload. P0 means no privilege beyond a normal user, P1 a one-time administrator action, P3 a kernel driver.
- Where several labels apply, the label list names the aspect each covers. "Experimental" means Microsoft still labels the API experimental, so no ArcForges guarantee may rest on it.
- Strength terms follow the study: ENFORCED (by the OS against the workload), PARTIAL, GUARDRAIL (cooperative), OBSERVED (detection only), NONE.
- "The study's VM plans" are documentation-only experiment plans; none was run. LAB-… IDs name entries of `lab-register.md` in this folder.

## Notes on unresolved items

- Which of these components a given Windows host carries (the `processmodel.dll` experimental sandbox and PSEC entry points, the Bound File System driver and its configuration tool, the agent registry tool, Windows Sandbox) depends on its build and its enabled features. It is host state for a read-only probe, not a fact of this record.
- Items the source report marks unverifiable and that this record does not rely on: the reported recursive ACL rewrite by MXC host preparation (mxc#648); the reported `bfscfg.exe` deadlock on 25H2; details of the pre-GA third-party analysis of the MXC Windows Sandbox backend; whether a desktop application uses HCS directly; the privilege needed to consume the LUA ETW events; whether the AppContainer loopback exemption needs an administrator; the 2026 Smart App Control changes.
- Open questions that need the study's VM plans: standard-user use of the experimental sandbox API and nesting of its processes in ArcForges root and attempt jobs (with and without UI restrictions); standard-user `wsb` operation and host-restart behaviour; placement of elevated and Secondary Logon children relative to the job; standard-user HCS calls from Native AOT C#; whether an agent-account process can reach the person's same-user endpoint.
- The privileged-modifications table (report §3) remains an open deliverable of the study.
