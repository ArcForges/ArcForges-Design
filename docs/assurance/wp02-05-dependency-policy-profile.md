Exact package-manager locks remain integrity authority. Existing reused-source and native checks still run through their current entry points. New JSON declarations alone are not completion evidence.

Candidate/stable distinctions follow the existing producer protocol. Exact first-party CI versions are permitted only as recorded foundation candidate inputs; they are not a general preview-package exemption. Stable core paths reject prerelease dependency closures. Contracts npm `latest` may point at the newest complete main candidate under the accepted producer protocol; consumers never restore that mutable tag. Public package access is not a declaration of production stability or permission for public clients to import internal contracts.

GitHub environment metadata confirmed DesktopPlatform `nuget` is restricted to main; Contracts `nuget`, `npm` and `maven-central` permit main and deliberate `v*` tags. DesktopPlatform already parses stable versions but has no stable workflow path. Add a deliberate canonical stable-tag path through the same candidate build/pack/publish chain, validating tag identity and membership in main and environment scope. No tag is created or stable publication executed for verification. Existing OIDC, package allowlists, signatures, immutable version collision rejection and single candidate handoff remain. Test/PR stages never receive publisher credentials.

Primary provider documentation verified on 2026-09-21: [NuGet trusted publishing](https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing) binds repository/workflow/environment; [npm trusted publishers](https://docs.npmjs.com/trusted-publishers/) binds package publisher identity; [npm publication](https://docs.npmjs.com/cli/v8/commands/npm-publish/) prohibits name/version reuse; [Central immutability](https://central.sonatype.org/publish/requirements/immutability/) and [SNAPSHOT publication](https://central.sonatype.org/publish/publish-portal-snapshots/) distinguish formal immutable releases from development snapshots. Source workflow and actual provider results establish configured operation; documentation alone does not prove account setup.
