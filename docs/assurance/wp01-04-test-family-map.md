## Policy correction and verification

WP01.04 no longer describes repository-policy tests as absent. WP05 retains its full AT/RP and invariant-accounting obligations, but its implementation input now identifies the current five-method DesktopPlatform suite and existing policy tooling. Historical 2,075-line/19-method counts and FixtureCompiler/ProjectGraph files are not current implementation proof. Existing specification-integrity tooling is extended when needed instead of requiring a duplicate project solely for its name.

Validation compares the discovered current test-source set with the map, checks all source/workflow hashes and clean heads, verifies one valid primary family per row, covers all eighteen families and all 28 historical paths/blobs, and resolves every future producer to an existing work package. Negative mutations remove a family/source/historical row, alter a source hash and introduce an invalid producer; each must fail. The full Design preview checks citations, links, glossary rules and work-package graph. No implementation changed and no package needed republishing.

No external prerequisite blocks this mapping. Physical devices, assistive-technology sessions, reference hardware and actual safe provider environments remain required by the named producers; assigning them does not waive their eventual evidence.
