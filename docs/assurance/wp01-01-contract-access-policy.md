# WP01.01 current contract access assignment

Authority: [WP01.01](../planning/work-packages/01-repository-reconciliation-and-target-layout.md#rule-wp-01.01), [contract/package boundaries](../architecture/01-solution-and-project-layout.md#3-contract-packages), [wire ownership](../architecture/contracts/04-protobuf-wire-registry.md#1-ownership-names-and-field-allocation) and [current repository inventory](wp01-00-implementation-evidence.md).

## Current assignment and implementation scope

Contracts owns the complete current contract-type assignment and its automated gate. Both public and internal sets use Apache-2.0; access restrictions are independent of licensing. At the verified WP01.00 source commit, the only authored wire definitions are `arcforges.hello.v1.SayHelloRequest`, `SayHelloResponse` and `HelloService`. All three remain public bootstrap contracts. There is no current internal contract project or schema to move, and no current public business type requiring reclassification. The retired ede43db authored C# DTO projects are historical evidence, not source to restore or relicense.

The current package sources comprise 15 generated C#/TypeScript/Java/Kotlin files and three authored distribution files: TypeScript exports, the Hello client factory and the Java public fixture accessor. Record every declared type, including nested generated builder/client/reflection helpers, under its containing public artifact. A private implementation helper in a public generated file is not a separate internal wire contract. Record the two function/export-only files explicitly rather than inventing types. No handwritten application behavior is admitted as a contract.

Use a closed, reviewed machine-readable inventory in Contracts. Bind the authored schemas, all distributed source files and their declared types to exact hashes and package owners. Existing regeneration and provenance checks remain authoritative for generator fidelity and retained notices. Any added/changed schema, generated file or authored distribution source requires renewed assignment review; a directory name alone cannot grant public access.

## Dependency verification

Compile all inventoried authored proto with the already pinned protoc, including imports, and inspect the resulting descriptors using the already locked protobuf runtime. Compare every message (including nested messages), enum and service to its recorded assignment. Validate imports and referenced message/enum/RPC types transitively. A public root must never reach an internal node, even through an intermediate public file or an unused import. Internal-to-public reuse is allowed. Reject missing/duplicate/unassigned definitions, unsafe or colliding source paths, unresolved references, source links and inventory/hash drift.

The current generated graph has no internal nodes. Real temporary proto fixtures must prove that direct and transitive public-to-internal dependencies fail, internal-to-public dependencies pass, and nested definitions cannot escape assignment. These are policy failure tests, not shipped private schemas. Verify the complete current distribution-source inventory and preserve immutable Hello fields, package IDs and generated bytes. The gate runs before candidate packing; existing clean package consumers and all registry publication gates still apply.

## Production handoff

WP03 generates the selected full schema/package split. Public foundation and domain projections, public extension messages and public SDK/fixtures belong to the public graph. Local helper/product-port/bootstrap records, operator/configuration records, CloudInternal and private AI HTTP schemas remain internal with restricted consumers, as specified in registry 04 and the CF/local/scope annexes. Internal schemas may import public definitions; public Web/Android packages cannot import internal operator/local/AI contracts. This step records the current assignment and enforces its closure; it does not replace the complete production schema inventory or claim WP03 generation complete.

The current native-grpc Kotlin Hello client remains a compatibility artifact until its already scheduled first-business-release retirement. No consumer lock, Android application/signing identity, transport selection or current public wire identity changes in WP01.01. The completion receipt must distinguish source/descriptor policy proof, actual packaged consumer execution and registry availability from later product/provider acceptance.
