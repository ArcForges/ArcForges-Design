### Canonical inventory.v1 definition

Annex08 previously fixed entry meaning and archive limits without fixing the JSON container/property names. This profile supplies that missing normative shape:

```json
{"schemaVersion":"inventory.v1","files":[{"path":"manifest.json","size":"123","sha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}]}
```

Both root and entry objects are closed: every shown property is required and unknown properties fail. `files` contains at most 10000 entries sorted strictly by ordinal path. `size` is a canonical unsigned decimal string (`0` or a nonzero digit followed by digits), within uint64, with each file at most 128 MiB and the checked total at most 1 GiB. `sha256` is exactly 64 lowercase hexadecimal characters. The example hash illustrates shape, not verified file content.

Paths use a portable ASCII profile: slash-separated nonempty segments containing ASCII letters, digits, underscore, hyphen and dot only. No segment is `.` or `..`, ends in a dot, or has a case-insensitive Windows device basename CON, PRN, AUX, NUL, COM1–COM9 or LPT1–LPT9 (including before an extension). Leading/trailing slash, backslash, colon, controls, non-ASCII characters and absolute/drive/UNC paths fail. Exact duplicates and ASCII case-fold collisions fail. This deliberately portable package path profile requires no locale-dependent Unicode folding.

Inventory entries cover payload files, including manifest.json and applicable licence/NOTICE files. Root inventory.json and signature.json are excluded to avoid self-reference; their names are reserved case-insensitively. The CLI validates this document's declared shape, paths and bounds only. It does not assert matching archive bytes, actual hashes, ZIP expansion bounds, symlink absence, manifest validity or signatures; those complete package-verification responsibilities remain with their later producer/consumer gates. Canonical signing serialization continues to use the existing registry04 canonical JSON profile.

Generation uses pinned existing tools after locked restore, runs without network, emits actual C#/TS/Java-Kotlin outputs where applicable and compares committed generated baselines. HTTP and validation generation are executable producer paths with meaningful fixtures, not directory markers. Full schemas and semantic vectors remain WP03.01/.03/.04/.05/.06/.07; AOT/registration and complete contract acceptance remain .02/.90. Starting the minimum complete dependency closure here does not mark any later substep complete.

## Publisher prerequisites and historical setup observations

Consequently, existing public-package publication success does not prove publishing rights for contract-fixtures, ai-internal or operator-client.
