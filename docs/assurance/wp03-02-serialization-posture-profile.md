## Selected decisions

| Subject | Selected posture |
|---|---|
| Binary business wire | Google.Protobuf generated C# and protobuf-es generated TypeScript remain the only business serializers. Unknown fields are retained by default and re-emitted; no production path discards them. Unknown enum numbers stay representable on read; existing validators refuse them in requests. No protobuf JSON mapping, `Any`, `Struct`/`Value`, descriptor/type-registry lookup or runtime schema loading appears in production source or authored proto. |
| Decode limits | Named constants in both languages: unary/helper message 4 MiB (4,194,304 bytes), inline list/event page 256 KiB (262,144), stream frame 32 KiB (32,768) and large read projection 64 MiB (67,108,864). A bounded decoder rejects input above the selected limit before parsing. Parsing permits the root message plus at most 100 nested message levels: C# uses `CodedInputStream` recursion limit 100 and TypeScript protobuf-es `recursionLimit` 101, which admit the same inputs. Encoding refuses a message whose serialized size exceeds its limit. Oversized, too deep and malformed input are distinct typed failures. |
| Service registration | Per-package generated service catalogues list the authored services for hosts and policy tests: C# exposes their generated `ServiceDescriptor` values alongside the plugin's explicit `BindService` methods; TypeScript exports the generated service descriptors as a static array. No gRPC server reflection service, assembly scanning or runtime discovery is registered. The retained Hello example remains a migration fixture. |
| HTTP-exception JSON | Only the declared exception schemas generate JSON records. Each C# `JsonSerializerContext` uses source-generation options that disallow unmapped members and duplicate properties, require strict number handling, respect required/nullable annotations, omit absent optional properties and use maximum depth 32. A generated codec checks the schema's declared byte limit, rejects a UTF-8 BOM, invalid UTF-8, comments and trailing commas, validates the closed schema, then deserializes through that context. Serialization writes through the same context and validates its output. TypeScript codecs apply the same byte, depth, duplicate-key, integer-lexeme and schema rules before accepting a value. |
| JSON byte limits | Each exception schema declares `x-arcforges-max-bytes`: `PartReceipt` and `CommitReceipt` 65,536 bytes, `PackageInventory` 4,194,304 bytes (its 10,000-entry bound). Integer fields accept only `-?(0|[1-9][0-9]*)` lexemes within their declared bounds; fraction or exponent forms refuse. Exact 64-bit values remain canonical base-10 strings. |
| Build posture | All C# projects set `JsonSerializerIsReflectionEnabledByDefault=false`. Every packed library remains AOT-compatible and trim/AOT analyzer diagnostics remain errors. A test-only Native AOT probe references the 13 C# libraries, publishes for `linux-x64` in CI and `win-x64` locally, and runs the binary/JSON/limit/registration vectors. It is not packed and does not replace WP06's real host/client AOT proof. |
| Forbidden inputs | A policy gate rejects reflection serializers and discovery dependencies in every NuGet, npm and Gradle lock, including Newtonsoft.Json, Refit, protobuf-net, gRPC server reflection, JSON transcoding, Castle dynamic proxies, protobufjs, google-protobuf, `@grpc/proto-loader` and full reflective `protobuf-java`. It also rejects reflection/discovery APIs in authored production source, forbidden well-known proto imports, missing strict JSON context options, missing AOT declarations, handwritten `IMessage` or JSON contract records outside generated owners, and service catalogues that differ from the authored proto. Negative tests cover each rule. |
| Admitted toolchain additions | Native AOT compilation adds only `Microsoft.DotNet.ILCompiler` and its `linux-x64`/`win-x64` runtime packages at `10.0.11`, the version selected by the pinned SDK `10.0.400` and already reviewed in DesktopPlatform. They are build-test tooling in an immutable dependency receipt, not a runtime dependency of any package. |

Kotlin/Connect client posture, native-auth and browser HTTP exceptions, complete operation/stream catalogues and transport frame enforcement remain in WP03.05, WP23, WP24 and WP30. The decode API gives those owners one limit vocabulary; it does not implement their transports.

## Independent fixtures and proportionate validation

`fixtures/public/wp03-02.json` is authored from this profile before implementation assertions. It describes each binary case by construction rule (target message, nesting pattern, unknown-field filler and exact byte total) so multi-megabyte boundary inputs are built rather than committed. It covers:

| Group | Required cases |
|---|---|
| Binary | Exact limit and limit+1 for every size kind; 100 accepted and 101 refused nesting levels; truncated and invalid-wire-type input; unknown field bytes preserved across C# and TypeScript re-encoding; unknown enum numbers retained on read; oversize encode refusal. |
| JSON exceptions | Canonical parse/serialize round trips for all three schemas; unknown, duplicate, missing, null and wrongly typed properties; fraction/exponent/string integers; BOM, invalid UTF-8, lone surrogate escapes, comments, trailing commas, depth above 32 and byte limit+1. |
| Registration and policy | Catalogue equality with authored services, explicit bind recording without a web host, and negative policy fixtures for every forbidden dependency/API/import/option rule. |

C# executes the vectors in the Native AOT probe; TypeScript executes the same file in the offline Node tests. Use existing locked tools and caches, serialize heavy local work and run each affected check once, repeating only after a relevant change or unresolved finding. Local Windows uses the existing SDK `10.0.401` and MSVC tools only as a recorded adapter; committed and CI SDK remains `10.0.400`. CI adds the Linux AOT publish and probe run to the existing candidate job; it adds no macOS, device, GUI/browser, live-service, inference, installed-consumer or public-release installation test. No public artifact download, repeated hash audit, verification-only tag or republication is authorized.
