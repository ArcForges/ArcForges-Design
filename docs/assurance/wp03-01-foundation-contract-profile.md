## Exact values and semantic boundaries

Domain-safe C# wrappers and TypeScript branded values/adapters distinguish IDs, Cloud revisions, local Notes tokens, native content revisions, sequences, cursors and exact decimals. Their constructors/converters validate the declared domain and fail explicitly; no implicit numeric or revision-kind conversion is allowed. Use generated protobuf messages for serialization, with explicit conversion to/from the safe values. A wrapper cannot become a second handwritten serializable business DTO. C# identifier domains and TypeScript brands prevent accidental cross-domain assignment at compile time; checked runtime conversion also rejects malformed external data.

IDs use exactly 16 nonzero bytes in canonical UUID network order, with defensive ownership of mutable byte buffers; platform Guid memory layout is not the wire format. Exact int64/uint64 values use C# long/ulong and TS bigint, never JavaScript Number. Preserve absent versus explicitly zero values; committed Cloud revisions are positive and zero is admitted only by an explicitly declared new-root context. Local sequence and native revision tokens cannot substitute for a Cloud revision. Cursors remain bounded opaque values; these adapters neither issue signed cursors nor grant authority from their content.

Exact decimals preserve the canonical string and checked coefficient/scale semantics: no floating-point intermediary or silent rounding. Apply at most 28 significant digits and nine fractional places, with each field's tighter rule. Notes numbers specifically reject trailing fractional zeroes, exponents, plus signs, leading zeroes and negative zero under notes.scalar.v1. Do not silently normalize an invalid incoming mutation literal into acceptance. Rational/time/range adapters use checked wide intermediates and retain the declared timebase and half-open bounds.

Validators distinguish mutation inputs from preservation of compatible read data. Required scalar presence, exactly-one oneof, named enum values and request profile keys are checked explicitly. Unknown response fields or values remain preservable and inert; they cannot activate an operation, silently become success or authorize a write. Semantic errors retain typed category, effect certainty, retry advice and declared detail variant; no English exception text or invented retry policy enters the contract.

The following clarifications close concrete ambiguities before generation:

| Subject | Selected meaning |

Validators enforce syntax, shape, bounds and self-contained relationships that the wire record supplies. They may validate definition-bound Notes literals against explicit supplied definition data and check internally supplied source/config/channel relationships. They do not query ownership, fetch objects, evaluate permissions, sign/issue cursors, apply persistence transactions, run Notes queries or compute measurements. Owner authorization, current revision availability, actual payload/hash correspondence and business effects remain the designated owner responsibilities. A valid resource reference is an address, never proof of access or byte availability.
