## Git reference verification

Validate a closed schema, unique and complete matrix/source IDs, source-to-matrix membership, expected row totals and full lowercase Git/SHA256 identities. Read the matrix documents from the pinned Design commit, verify hashes, row IDs and recorded source abbreviations, and reject a wrong repository or missing commit. Read committed Git objects rather than working-file content; report the actual root, origin, HEAD and dirty state separately. A locally modified reference can prove that a historical commit exists, but cannot be described as a clean baseline checkout.

The default CI registration check uses isolated bare repositories to fetch only the named immutable commits from their registered GitHub origins. It never checks out or executes reference code. Explicit local roots support offline/repeatable inspection and must have matching origins. Validate Git object type as commit, not just existence. Missing or inaccessible sources fail the registration result; do not silently substitute HEAD, omit an owner, or claim the unavailable reference was verified. On a network failure, stop and report the exact operation; do not retry or change network configuration or a recorded origin.

## Non-Git packaged observation

StartArcForges has no Git commit. Its [existing maintenance rule](reference-coverage/distribution-startarcforges.md#rule-mt-01) binds AFFiNE 0.27.2-stable, AionUi 2.1.35 and SiYuan 3.7.3 by installer filenames. Retain those versions and paths. Register a dated observation of the current six product directories: immediate child names and kinds, plus SHA256 values for explicitly listed bundled text notice files. Do not read binary contents, extract metadata from executable bytes, unpack, execute, or reverse engineer any artifact. Root-level directory shape and notices, not an entire binary-content digest, are the declared evidence boundary.

The original matrix's 2026-09-05 review and the new registration observation date stay distinct. The latter cannot retroactively prove historical bytes. The verifier compares the local packaged observation when an explicit root is supplied. CI validates its retained structure, versions and integrity; unavailable local packaged trees in hosted CI are explicitly marked as not re-observed, never passed as a live check. Local acceptance must re-observe the actual tree and retain the result. Missing roots, changed versions, added/removed entries, links/reparse points or changed/missing notices fail the corresponding observation check. This narrowly scoped identity replaces only the impossible requirement for a packaged-tree Git commit.

## Drift procedure and assessment

Compare the bound commit with an explicitly resolved candidate commit from the same source repository. Use Git tree entry metadata (path, mode, object ID) to report additions, removals, modifications and type changes deterministically; a rename is a removal plus an addition. No source expression or diff patch is read automatically. Report working-tree modifications separately, including untracked paths, without interpreting them as a committed candidate. A moving branch is resolved once to its full commit before comparison and the report records both endpoints. Do not fetch or update a user's reference checkout.

Newly introduced material includes new paths, replacement bytes, changed modes/submodule identities, licensing/notices, test/assets, and an altered accepted scope or matrix disposition. An unchanged path with a changed object ID still requires assessment. An unchanged commit with local edits is not a clean live-reference result. Preserve all matrix exclusions: AFFiNE proprietary source, Serial-Studio Pro expression and other excluded subtrees remain unread; directory metadata can identify their drift. The Licensing and Provenance Owner rechecks licensing evidence before any affected material is consumed, including AFFiNE's split and Serial-Studio's Pro-module list. A changed licence does not grant automatic reuse. ArcSlate's upstream attribution and library-surface assumptions remain in force.

The consuming Product/Architecture Owner assesses each relevant delta against accepted requirements and the matrix disposition; the Licensing and Provenance Owner resolves rights and authorship effects. Record the item/path, old/new identity, accepted-scope effect, exclusion or action, responsible role, date and reason. Conflicts block the affected consumer until a reviewed Design amendment or admissible disposition exists. An upstream capability never becomes a requirement automatically. Unrelated local build edits are recorded as excluded from the fixed input, with rationale; they cannot be promoted silently. A no-change comparison is a valid dry run, but tests must also prove that real changes are detected. A drift report is observation evidence, not automatic approval of changed material.

## Validation and limits

At registration, verify five matrices (30, 41, 31, 31 and 12 rows), all six Git commits, the actual packaged observation and at least one real drift invocation. Exercise missing/duplicate registrations, bad hashes, wrong origins, absent/non-commit IDs, changed matrices and packaged versions/notices, and added/changed/deleted Git paths. Run continuing CI on the actual registry plus these failure tests. Review the complete final diff and all applicable CI before merging implementation. Repeat the registration and real local observation after merge and retain exact commit/report identities.

Verified 2026-09-20 against official Git documentation: [revision verification](https://git-scm.com/docs/git-rev-parse), [tree listing](https://git-scm.com/docs/git-ls-tree) and [diff endpoint semantics](https://git-scm.com/docs/git-diff) support immutable commit/object comparison independently of working files. No SDK/provider upgrade or new licence grant is needed. This stage proves planning input identity and maintenance, not application runtime, distribution readiness or commercial activation.
