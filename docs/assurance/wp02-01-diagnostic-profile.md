## Verified baseline and decisions

Research on 2026-09-21 evaluated all 43 managed projects through their actual restored imports. All already enable nullable references, implicit usings, deterministic compilation and compiler warnings-as-errors. DesktopPlatform selects `latest-all`; the other five managed owners evaluate to `latest` from their pinned SDK. All evaluate `EnableNETAnalyzers=true`, but `EnforceCodeStyleInBuild=false`. Their editor configurations already select file-scoped namespaces; that policy must also run in ordinary builds.

Keep the existing analyzer breadth and exact SDK/package pins. Record the existing analysis selection explicitly at each managed root, enable code-style build enforcement and code-analysis warnings-as-errors, and express `IDE0161` severity explicitly in `.editorconfig`. Do not turn on an unrelated batch of style rules or weaken DesktopPlatform's existing `latest-all` policy. Full-solution diagnostic probes with code-style enforcement and MSBuild warnings-as-errors passed in all six owners before implementation. Each root owns these settings; no Build.Policy package API or consumer dependency upgrade is needed for this repair.

Cloud and Web already run Biome with `--error-on-warnings` and strict TypeScript checks. AI has strict TypeScript but its lint command omits that flag; its actual lint passes with the flag added. Contracts' generated TS packages retain strict typechecking and locked generation. No new linter package or dependency upgrade is required.

Mobile release lint already fails on warnings. Its app/shared Kotlin compilations and Contracts' generated Kotlin producer/isolated consumer builds must also use `allWarningsAsErrors`. Actual producer and Mobile app/shared probes passed with that setting. Contracts' Java producer tasks also receive javac `-Werror`; generated sources and Java 17 release targets remain unchanged. Contracts' existing `val codegen by configurations.creating` additionally emits an owned Gradle deprecation: replace it with explicit named configuration creation. Use Gradle's warning failure mode in the affected Contracts/Mobile roots and Cloud's Kotlin fixture, while preserving their existing compiler targets and dependency locks.

### Diagnostic scopes and waiver inventory

There are **no active authored-code diagnostic debt waivers** in the researched baseline. The implementation must finish with an explicit empty waiver list or fix any newly exposed finding. Do not introduce a blanket warning suppression to manufacture a pass. If a real unavoidable exception appears, it requires the existing quality-waiver fields, a named owner, an expiry and executable expiry enforcement before acceptance; an unowned or permanent exception fails this step.

The following existing tool/generator boundaries are inventoried separately from debt waivers:

- SDK `NoWarn=1701;1702` comes from `Microsoft.NET.Sdk.CSharp.props`, not owner-authored suppression.
- The pinned ILLink targets add `IL2121` for redundant-suppression reporting on trimmed projects. This is an SDK default, not evidence that the AOT diagnostic sweep is complete. WP02.02 owns evaluation of that reporting mode and the complete trim/AOT diagnostic set.
- Contracts' pinned generators emit their existing warning pragmas and generated-file markers. Do not hand-edit generated files; the generated boundary and regeneration checks remain explicit. No owner-authored trim/AOT suppression is introduced.
- Native vendor headers are isolated from owned wrapper warnings; existing owned C/C++ `/WX`/`-Werror` compilation remains enabled. Local native validation reuses the installed vcpkg dependency tree under [the accepted reuse policy](wp02-00-toolchain-profile.md#local-native-reuse-and-published-candidates).
- TypeScript's existing declaration-library checks and generated binding boundaries are distinct from strict checking/linting of authored implementation. No new `ts-ignore`, `ts-nocheck` or lint-disable escape is admitted.
