# macOS content runtime boundary and signing preservation

Date: 2026-10-07. Governing tasks: PLT.63, NAT.22 and NAT.25. This is a minimum production prerequisite, not evidence that a Mac build, signature, isolation profile or installed consumer has passed. The existing PLT.45, PLT.46, PLT.54, APP.03 and per-RID acceptance outcomes remain unchanged.

## 1. Actual ownership and dependency

PLT.63 was absent from the authoritative graph and ledger when this decision was prepared. The current production launcher refuses macOS; the entitlement file and offline tests do not implement XPC activation, process termination or native loading. PLT.63 owns the missing Mac launcher, helper entry/profile, statically linked first-party bridge, protected-install loader and portable lifetime core. It starts from the actual PLT.45 host and PLT.09/10/15 transport, identity and resource artifacts. It does not wait for their full all-platform acceptance. Its complete implementation, component validation and truthful publication handoff are required; an interface-only adapter or success stub cannot satisfy it.

NAT.25 remains the sole authenticated helper/native release, common bootstrap and release-signing orchestrator owner. Its completion includes integration of PLT.63, without a reverse start dependency on NAT.25 or the full PLT.45/54/46 acceptance. The actual accepted NAT.25 core supplies the existing internal native-load interface; no second common loader is introduced. NAT.22 remains the sole PE/ELF/Mach parser and Mach signature-transformation owner. It receives only the narrow additional source scope in section 6. PLT.64 installation credential custody is unrelated and gains no Mac prerequisite here.

## 2. Approved identity before resource transfer

Support is limited to actual osx-x64/osx-arm64 native AOT binaries on macOS 13 or later. The independently approved installation policy fixes the helper bundle/service identifiers, selected TeamID and signing certificate identity, designated requirement, actual CodeDirectory identity, closed entitlement dictionary and signed final helper digest. A valid OS signature or a response declaring its own identity is insufficient. Dynamic Security validation and strict signed bundle/resource validation must both pass, including the exact approved executable and bundle metadata; ad-hoc/linker-only signatures, debug exceptions, altered requirements and extra entitlements refuse production activation.

Use public C XPC and Security APIs. Set the incoming peer code-signing requirement before activation and validate each received activation message through SecCodeCreateWithXPCMessage and SecCodeCheckValidity against the independently selected requirement. Extract and compare the actual signed TeamID, identifier, CodeDirectory identity and entitlements. The helper authenticates the parent as well. Public message validation is explicitly based on the message's audit identity; the incoming requirement does not protect outgoing resources. Therefore the initial challenge contains only a fresh nonsecret nonce and bounded protocol metadata. No launch secret, input, slot, native policy or connected business stream is sent before the challenge reply is authenticated. A malformed requirement or denied/absent public API becomes security.isolation_unavailable, never a full-trust fallback. [Apple's public message API](https://developer.apple.com/documentation/security/seccodecreatewithxpcmessage(_:_:_:)) and [outgoing-message caveat](https://developer.apple.com/forums/thread/837286) support this ordering.

The exchange is one-shot, bound to the same authenticated activation, 32-byte nonce, closed protocol/build identity and total launch deadline. Reject extra, late, repeated or cross-connection provisioning. CFEqual on SecCode objects and equal CodeDirectory hashes identify code, not a process instance; they never substitute for the original kernel task binding. [Apple's implementation of code equality](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_codesigning/lib/Code.cpp) makes that distinction concrete. No private XPC audit-token accessor, PID-only lookup, or process-name inference is admitted.

## 3. Original kernel task rights and finite provisioning

Use a fresh activation-owned Mach receive right for a bounded, provisioning-only identity proof. Transfer its send right through the authenticated XPC activation. The helper sends a closed Mach message, at most 8 KiB, containing the same nonce/protocol identity and its original task-control send right. Receive with the public format-zero audit trailer; validate message length, complex descriptor count/types/dispositions, trailer bounds and all eight kernel audit-token words. No out-of-line memory or unrelated rights are accepted. Query TASK_AUDIT_TOKEN on the retained task right and require exact equality to the actual kernel trailer, including pidversion, then obtain and dynamically validate the audit-selected SecCode against the approved helper identity and the already authenticated activation. Reverse parent liveness provisioning supplies only an original task-name right, with its actual audit identity bound by the same mechanism; it never gives the helper parent task-control authority. These additional messages are finite OS provisioning, with no application method, result, callback, buffer grant or cancellation protocol. [Public Mach message/trailer definitions](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/mach/message.h), [task audit information](https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/mach/task_info.h) and [Security audit guest selection](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_codesigning/lib/SecCode.h) define the actual primitives. Missing rights, denied task inspection or inability to bind the actual instance refuse and quarantine uncertain activation.

Retain the original task-control right and an owned dead-name notification receive right until confirmed destruction. Terminate with task_terminate on that retained kernel object, and confirm its death through an actual matching dead-name notification. XPC invalidation, connection interruption, cancel acknowledgement, a reused PID, a new empty namespace and launchd service-name lookup are not exit proof. launchd reaps the XPC service; neither ChildProcessGuard/waitpid nor kill(PID) is reused. Cancel and timeout stop admission and drive this same idempotent physical termination/drain; they are not XPC business messages. Destroy every owned receive right and release every copied send right exactly once, including rejected messages and late callbacks. A parent-death monitor and native wall timer independently terminate the helper's own retained task object; unknown exit retains bounded quarantine rather than releasing the service lease.

After identity/task proof, transfer exactly the two already-connected Unix gRPC streams, read-only immutable input and 1..3 bounded output slots. The existing 64 MiB slot bound, role inventory and launch frame v2 remain unchanged. The helper duplicates incoming FDs, validates local type/access/size/nonduplication, and sends one bounded authenticated acknowledgement of the actual child-local descriptor numbers and roles. Only then does the parent call the existing HelperStartRequest.EncodeFrame(childEntries) and deliver that exact bounded frame on this activation. Reject any changed role/count/nonce/identity, FD alias, writable input or oversized backing file. Do not dup2 onto guessed fixed FDs, add a second launch-frame format, use a discoverable TCP listener, or transfer later gRPC ancillary descriptors. Frame/bootstrap/native trust bytes are cleared on every terminal path.

## 4. Lifetime, isolation and limits

The signed helper is independently App-Sandboxed before managed/native constructors. Require com.apple.security.app-sandbox=true and no inheritance, network, application-group, broad file, product-container, JIT/debug or library-validation relaxation entitlement. Exact authorized parent entitlement policy is separate; a parent policy cannot grant these powers to the helper. Verify actual running signed state and actual resource-denial probes, rather than trusting the plist alone. Native parser libraries may be admitted only from the approved protected installation before hostile parsing; profile checks and limits must already precede untrusted input processing.

The service runs one invocation and exits. Use a canonical per-user/service identity lock independent of caller-selected runtime directories, at most eight bounded admission slots, and a flushed nonempty pending journal before activation. Record the verified original task audit identity when available; preserve pending/nonempty state across partial writes. Repeated/concurrent activation cannot share a helper, retained mappings or persistent bundle-container data. After a crash, missing original task rights or ambiguous prior state is quarantine, not permission to reconstruct authority from a PID. A boot change can retire only the prior-boot process uncertainty, with bounded verified scratch cleanup. Never delete an arbitrary path or claim persistent XPC bundle storage is fresh invocation storage.

Apply hard CPU, process-count, file/core and descriptor limits before parser access, require nonroot execution, and bind the actual requested memory and wall budgets. RLIMIT_NPROC=1 must deny creation of another process under the actual nonroot profile; fork/spawn denial is an explicit real Mac acceptance test. Success/echo from setrlimit/getrlimit alone never proves memory enforcement on a supported kernel. The production capability check requires an independently approved actual OS/kernel capability and genuine enforced memory-limit observation; unavailable hard enforcement refuses. Current XNU has an address-space enforcement path, which does not prove older macOS 13 kernels have it. [Current kernel resource handling](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_resource.c) is a research input, not an all-version acceptance receipt. Parent loss, parser crash/hang, slot misuse and timer expiration require original-task termination and confirmed exit before lock/storage reuse. No descendant accounting or tree-kill success is inferred solely from SecCode validation; the actual no-spawn policy and denied attempts are mandatory.

Disposal caches one terminal task, rejects new admission atomically, and joins all in-flight native callbacks and owned stream/mapping/right/task/lock/scratch cleanup. No caller cancellation releases physical capacity early. Attempt each independent cleanup after an earlier fault, preserve original plus teardown errors, and retain only the minimum owned task/right/journal continuation needed for uncertain exit. Portable controlled tests exercise every partial acquisition, nonce/identity/descriptor mismatch, late callback, cancellation boundary, timeout, concurrency, persistent pending cut and repeated disposal. Only unavailable XPC/Security/Darwin results may be substituted; those tests establish core behavior, not OS isolation.

## 5. Protected installation and native bridge

The common native loader retains full signed Image/Pdf cohort checks before any dlopen. The Mac platform lease accepts only canonical absolute files beneath the approved root-owned installation, with nofollow openat traversal from a held trusted ancestor. Every ancestor and regular closure file must have UID 0, no group/other write permission and no extended ACL; the consuming process must not be euid 0. Retain directory/file descriptors and device/inode identities through hashing, load and reverse unload. Exact authenticated hashes and dependency paths remain mandatory. These protected ownership/permission rules close same-user path substitution; advisory flock, ordinary POSIX open, FileShare semantics and post-hash reopening do not. Privileged OS mutation lies outside this same-user boundary. Reject user-writable installation or unknown ACL rather than pretending a lease makes it immutable.

Use the actual canonical protected path with dlopen RTLD_NOW|RTLD_LOCAL|RTLD_FIRST, exact dependency order and owned export lookup; no cwd/environment search or assumed /dev/fd dyld support. Dispose native modules in reverse order before releasing vnode leases. PLT.63 implements only the Mac INativeRuntimeLoadPlatform adapter in helper Host/Mac; NAT.25 owns the narrow existing bootstrap dispatch/lifetime composition.

The first-party Objective-C/C17 bridge is statically linked into the actual signed Native AOT helper and parent through explicit DirectPInvoke/NativeLibrary inputs. It wraps public XPC/Security/Mach and protected-install primitives in bounded status/ownership operations, with distinct parent/helper export owners. No unverified dynamically loaded bridge is used to establish its own trust. Existing Broker package buildTransitive inputs may carry only actually built, source-bound per-RID static archives; unsupported/unbuilt archives remain inactive. The reproducible local Mac recipe records actual SDK/compiler/linker/tool/source/archive inputs and preserves complete unsigned outputs. No Mac CI, new toolchain installation or guessed compilation success is prescribed.

## 6. Mach signing transformation and release integration

NAT.22 alone extends the existing bounded Mach parser with verify_macho_signature_transform(original: bytes, signed: bytes, rid: str) returning the final immutable BinaryInfo after equivalence succeeds. This is descriptive body-preservation validation, never publisher authentication. Existing inspect/inspect_executable behavior and shared as_manifest serialized bytes remain unchanged. Accept only closed thin little-endian 64-bit x86_64/arm64 matching the selected osx RID and existing parser/file caps; no fat, alternate CPU, overlapping or unbounded structure is silently accepted.

Require exactly one bounded final LC_CODE_SIGNATURE blob, inside the unique nonexecutable __LINKEDIT and at the actual file tail; validate its SuperBlob/index lengths, unique nonoverlapping internal ranges and exact trailing allocation. Original compiler output may have one structurally valid linker/ad-hoc signature or none. A signature command may be replaced, or one exact 16-byte command appended only into verified original zero header padding without moving any existing command or section. Changes are limited to that command, the exact derived ncmds/sizeofcmds increment for insertion, the final signature tail with necessary zero alignment, and the unique __LINKEDIT filesize/vmsize fields justified by the actual new tail and architecture alignment. Preserve vmaddr/fileoff, segment protections, section layout, entry point, imports/install names/RPATH, all other load commands and every nonsignature byte at its original offset. Original signature data can be replaced only when it is the unique tail; no arbitrary truncation, relocation, command reordering, hidden gap, code/data mutation or new executable mapping is allowed. Reject transformations outside this deliberately closed recipe rather than guessing that every codesign rewrite is harmless. [Mach load-command layouts](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/loader.h) and [Apple's signature allocation/writing implementation](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_codesigning/lib/signerutils.cpp) are format references, not a blanket exception for their output.

NAT.25 consumes that seam from its existing Python stage/verifier and ReleaseSigner Mac verbs. Bind the whole original compiler receipt/inventory and selected original/final helper SHA, actual pinned protected codesign/tool payload, authorized certificate/TeamID, designated requirement, strict closed entitlements, actual timestamp/trust verification and exact signed bundle-resource inventory. Never infer authorized release trust from a self-hash or ad-hoc signature. Child verification hashes its held original and final snapshots before inspecting body or OS trust, using parent-selected digest arguments, preserving the repaired Windows command-data handoff discipline. Signing/verification has one total bounded deadline, controlled process cleanup, private protected staging, create-only promotion, file/directory flush and retained final bytes through promotion. Extra bundle files, altered Info.plist, entitlement substitution, rewritten nonsignature bytes and tool/input swap-restore refuse. No generic sign-raw or unrelated local credential is authorized. Missing approved signing enrollment/protected installation is a precise external release-authority requirement; source/adapters/components continue without fabricated success.

The private release signer owns its Mac Security verification bindings under its existing `eng/packaging/ArcForges.Native.ReleaseSigner/Mac` source, separate from the parent/helper bridge exports. Include those actual bindings in the existing closed production-owner test with exact source, symbol and marshalling rows; no wildcard, duplicate owner or unexamined private-tool import exemption is introduced. If the signer uses a statically linked wrapper, its distinct signer exports and actual native inputs remain owned by that non-packable tool. The Python orchestrator alone consumes the NAT.22 Mach body-equivalence parser over its selected snapshots; the signer verifies the same selected final digest and genuine OS identity, without a duplicate Mach parser.
