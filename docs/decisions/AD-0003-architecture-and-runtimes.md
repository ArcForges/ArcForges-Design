# AD-0003 — Components, runtimes and binaries (C#-first)

- Status: Accepted (2026-10-12)
- Reaffirms: the C#-first stack of ArcForges-Design-Parallel P2-021 (main `64173614`, `docs/decisions/phase-2-specification-decisions.md#rule-p2-021`) for the new product.

## Decision

1. **One multi-role native executable per platform: `arcforges`** (`arcforges.exe` on Windows), built with .NET 10 Native AOT for `win-x64`, `win-arm64`, `linux-x64` and `linux-arm64`. Its roles are selected by command:
   - `arcforges node run`: the node service (authority).
   - `arcforges <command>`: the CLI ([experience/cli.md](../experience/cli.md)).
   - `arcforges mcp serve`: the MCP adapter (stdio; a local HTTP transport is roadmap RM-05).
   - `arcforges hook <client> <event>`: the AI-client hook handler.
   - `arcforges bridge wsl`: the host-to-guest byte relay launched through `wsl.exe` (AD-0005).
   - Internal helper roles, never invoked by users:
     - `arcforges node exec-wrap` (Windows): the attempt's holder outside the job; launches the root process into the job, keeps the job handles until the node acknowledges, and writes the durable exit record with accounting;
     - `arcforges node signal` (Windows): attaches to an attempt's windowless console and sends `CTRL_BREAK_EVENT` (L-18);
     - `arcforges node exit-record` (Linux): the `ExecStopPost` recorder of transient execution units (AD-0005).

   **Windows supervisor.** `arcforges-supervisor.exe` is a small GUI-subsystem Native AOT executable (project `ArcForges.Supervisor`) with no window.
   - **Why:** a console-subsystem process started at logon would show a console window.
   - **What it does:** starts the node with `CREATE_NO_WINDOW`, restarts it after a crash, and performs the update switch, health watch and rollback ([distribution](../architecture/13-distribution-updates.md) §5).
   - **Linux:** systemd fills this role.

   **Rationale:** one signed artifact per runtime identifier, one set of contract bindings, one update unit and a smaller total footprint than four executables. Roles share code pages through the OS, so a CLI invocation does not run the node's service code. Startup and size targets are in [performance targets](../architecture/15-performance-targets.md).
2. **ArcForges Desktop** is a separate optional executable, `arcforges-desktop`. It uses Avalonia with compiled bindings, Native AOT on Windows and Linux (V-N04), and the DesktopPlatform design system and shell models. It is a pure client of the local node, holds no authoritative state, and closing it never stops the node.
3. **Cloud.**
   - The existing C# Native AOT host runs in Cloudflare Containers (ArcForges Cloud repository) and holds all cloud business logic.
   - TypeScript is limited to thin platform adapters:
     - the Worker router and gRPC-Web ingress already present;
     - the static-asset Worker (Web);
     - the relay Durable Object, which accepts hibernating WebSockets, validates signed tokens, fans out opaque protobuf frames and buffers within bounds.

     These adapters contain no business decisions (AD-0009).
4. **Web.** The arcforges.com public site uses the existing C# static generator. Account and fleet profiles are Blazor WebAssembly using generated C# gRPC-Web clients.
5. **Android.** .NET MAUI with the Mono runtime and AOT for release, R8, and gRPC-Web clients, as in the existing Mobile repository. Google Play Billing uses the official .NET binding of the native SDK (V-C06). Binding a native SDK is not a second business-logic stack.
6. **No Kotlin/Java application code and no TypeScript business logic** is introduced. Python stays limited to repository tooling (checks, generators). Native OS APIs are called through source-generated P/Invoke (`LibraryImport`): Win32 job objects, named pipes, DNS-SD and credential APIs, and Linux libc and cgroupfs. No C/C++ component is required for the node in this scope.
7. **Serialization.** Protobuf, generated by Grpc.Tools, on every wire. System.Text.Json with source generation for configuration files, MCP JSON-RPC and exports. No reflection-based serializers in AOT components.
