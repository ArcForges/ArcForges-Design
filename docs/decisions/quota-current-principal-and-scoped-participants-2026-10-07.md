# Quota current principal and scoped participants

Date: 2026-10-07. Effective only after independent paired Design/Plan review and both merges. This repairs the missing COM.07 current-principal integration; it does not assert implementation, publication or live acceptance.

## Closed targets and operations

Only `families.quota-accounting.publish-budget-native`, `families.quota-accounting.publish-budget-browser`, `families.quota-accounting.reserve-native` and `families.quota-accounting.reserve-browser` are admitted. The existing internal receipt operations are respectively `entitlement.quota-budget` and `entitlement.quota-reserve`. They are not new public RPCs or permission grants. The authenticated public ingress and owning domain must independently authorize the original published operation and bind the same immutable command, resource and approved grant. A quota actor contribution alone never authorizes upload, simulation or another domain effect.

COM.07 keeps its existing outcome, progressive start, single kernel writer and owned SQL. Add only completion integration on CLOUD.13's real current Session/Device/Installation participants. Missing production authority refuses with its typed unavailable or denied outcome; an ActorRef, context UUID, constructor-created SessionAuthority or preflight success is not authority. No COM.07-to-CLOUD.13 start edge or reverse completion edge is created.

## Actual owner handoff

CLOUD.13 remains the sole producer of Session and Device current contributions and the coordinated family registry/generated union. Reuse `SessionFamilyTarget` and raw `SessionCredentialReference`; extend the existing Identity operation-to-plan map only for the two internal operations and four targets above. Resolve current credentials again, require purpose1 and ACTIVE user state for quota, verify browser CSRF, match actual credential channel and exact actor Device/Installation/product, and sample server time. Never use target.AtMicros as expiry authority. Restricted-user security remedies in existing plans remain available.

Identity seals authorization `actor-current` with `[session,user,device,installation,product,purpose,kind,authEpoch,recoveryGeneration,sessionRev,serverMicros]` and `actor-user` with `[realm,user,state,userRev]`. Devices permits only ActorCurrent for these four targets and seals authorization `actor-device-owner [device,user]`, `actor-installation-binding [installation,device,product,keyVersion]`, revision `actor-device-revision [device,positiveDeviceRev]` and `actor-installation-revision [installation,positiveInstallRev]`. Product is the actual resolved arcscope/companion binding; native key eligibility uses the actual canonical key reader and does not claim signature possession from parsing.

Reuse Workspace's existing `WorkspaceSessionParticipant` and owned `workspace.workspace-load`; append only the four targets to its closed allowlist. It reads the actual personal Workspace and seals authorization `workspace-current [workspace:D,realm:D,user:D,Active1,positiveWorkspaceRev]`. Canonical workspace OwnerScope is separately issuer-bound by ContributeScoped. No second Workspace table reader, membership model, business writer or caller user alias is introduced.

Every new plan requires scoped contributions. Compose the genuine current C75 recovery contribution once, using the same trusted realm/generation snapshot and production executor, alongside Config's current head, the actual Entitlement snapshot/profile/selected-period predicates and the single kernel writer. Contribution sets must share exact registered family, plan and canonical workspace scope. The coordinator checks returned principal linkage against every participant and its immutable command. It never constructs another module descriptor or substitutes a status for a missing opaque contribution.

Add only two finite actor-current lifetime registrations: NativeSession on the two native quota plans with actual `identity_session.expires_at` and `access_expires_at`; BrowserSession on the two browser plans with `expires_at` and `idle_expires_at`. Preserve intrinsic `revoked_at IS NULL`, current captured/transaction-clock predicates, auth epoch/generation/revision checks and every existing profile/registration/hash. Do not add quota-accounting to an unrestricted actor-family allowlist. The generator and managed verifier must reject wrong channel, target, role, table, profile, parameter shape, unscoped plan or missing current participant.
