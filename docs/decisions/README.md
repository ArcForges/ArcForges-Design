## Effective architecture

Seven independent repositories integrate published NuGet packages, one retained internal npm codec package and immutable artifacts. C# (.NET 10 LTS) is the implementation language of all product and business logic, first-party business SDKs are generated C# NuGet packages, and Contracts remains the authored-proto wire authority ([P2-021](phase-2-specification-decisions.md#rule-p2-021)). ArcScope, the one professional desktop application, is C# on Avalonia and embeds its own application-owned assistant. Every public business client uses binary gRPC-Web; private child controls use generated gRPC over Named Pipe/UDS. The Cloud is one C# Native AOT host in Cloudflare Containers behind Cloudflare Workers, with D1 authority, coordination Durable Objects and R2. Its single Harness is C#, with durable execution on D1, Durable Object alarm wake, and Workers AI reached through a thin TypeScript binding adapter ([P2-021](phase-2-specification-decisions.md#rule-p2-021)). TypeScript is limited to those thin Cloudflare platform adapters, and Node to build tooling only (wrangler, the D1 migration runner and generators under P2-021 items 1 and 6). The Web is one Blazor WebAssembly application with Account, Chat, Operations and simulator profiles, and its public Site is static HTML generated by a C# generator. Android is a .NET MAUI Android-only companion. Native in-app PDF preview and local PDF parsing are retired, while ArcScope report export and generic attachments remain ([P2-022](phase-2-specification-decisions.md#rule-p2-022)). macOS is outside the delivery scope and is never claimed ([P2-023](phase-2-specification-decisions.md#rule-p2-023)). Cross-product collaboration is future-only.

## Conventions

Requirements define accepted behavior; architecture, contracts, data models, work packages and assurance implement the effective decisions together. Correct conflicting prose in place. New appendices cannot override an unchanged active body. Historical quotations and dated reviews keep their baseline and receive explicit supersession where needed.

[D-016](phase-1-foundation-decisions.md#rule-d-016) requires an owner, trigger, required evidence and failure consequence for a legitimately deferred implementation choice. It does not permit deferring missing business or correctness rules. [D-020](phase-1-foundation-decisions.md#rule-d-020) keeps proposed commercial and performance numbers distinct from approved/observed values. Deprecated inputs are excluded from current review; missing definitions belong in the current formal owners.
