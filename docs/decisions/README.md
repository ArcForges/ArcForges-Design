## Effective architecture

Seven independent repositories integrate published NuGet packages, one retained internal npm codec package and immutable artifacts. This is the target architecture; each mechanism that is not yet proven names its gate. C# (.NET 10 LTS) is the implementation language of all product and business logic, first-party business SDKs are generated C# NuGet packages, and Contracts remains the authored-proto wire authority ([P2-021](phase-2-specification-decisions.md#rule-p2-021)). ArcScope, the one professional desktop application, is C# on Avalonia and embeds its own application-owned assistant. The target public business transport is authored-proto gRPC-Web in binary mode, with a `grpc-web-text` server-stream variant that applies only if PRF.11 does not observe binary server streaming ([P2-021](phase-2-specification-decisions.md#rule-p2-021) item 2); binary server streaming is unverified until then. Private child controls use generated gRPC over Named Pipe/UDS. The Cloud is one C# Native AOT host in Cloudflare Containers behind Cloudflare Workers, with D1 authority, coordination Durable Objects and R2. Its single Harness is C#, with durable execution on D1 under an epoch lease and fenced writes. Two mechanisms are gated on proofs: Durable Object alarm wake (alarm retry and Queue delivery semantics are unverified, and the executor is gated on the HAR.40 proof) and Workers AI reached through a thin TypeScript binding adapter (the `ai.internal` path is not frozen until the Workers AI proof passes). TypeScript is limited to those thin Cloudflare platform adapters. Node is build tooling only, and its sole role is invoking wrangler; the D1 migration runner's schema lease, fence and gating logic move to C# (CLOUD.84). Local browser automation is Microsoft.Playwright for .NET, with no npm-hosted test tooling ([P2-021](phase-2-specification-decisions.md#rule-p2-021) item 8). The Web is one Blazor WebAssembly application with Account, Chat (assistant), ArcScope library, reports and simulator console, and Operations profiles. Its public Site is static HTML generated by a C# generator; the use of the first-party `HtmlRenderer` and the determinism of its output are unverified until PRF.11. Android is a .NET MAUI Android-only companion, and its transport and release proofs belong to PRF.12 and AND.40. Native in-app PDF preview and local PDF parsing are retired, while ArcScope report export and generic attachments remain ([P2-022](phase-2-specification-decisions.md#rule-p2-022)). macOS is outside the delivery scope and is never claimed as supported ([P2-023](phase-2-specification-decisions.md#rule-p2-023)). Cross-product collaboration is future-only. The active scope is ArcScope only ([P2-026](phase-2-specification-decisions.md#rule-p2-026)): ArcScope desktop, its Cloud, Web and Android companion surfaces, and the shared capabilities that have a concrete ArcScope consumer, are the active plan. Other products, the optional reranker, the official package catalog and extension platform, MCP connectors, the still-image decode route and macOS are out of scope; they are recorded as out of scope, not completed, and their legacy code is left unchanged.

## Conventions

Requirements define accepted behavior; architecture, contracts, data models, work packages and assurance implement the effective decisions together. Correct conflicting prose in place. New appendices cannot override an unchanged active body. Historical quotations and dated reviews keep their baseline and receive explicit supersession where needed.

[D-016](phase-1-foundation-decisions.md#rule-d-016) requires an owner, trigger, required evidence and failure consequence for a legitimately deferred implementation choice. It does not permit deferring missing business or correctness rules. [D-020](phase-1-foundation-decisions.md#rule-d-020) keeps proposed commercial and performance numbers distinct from approved/observed values. Deprecated inputs are excluded from current review; missing definitions belong in the current formal owners.
