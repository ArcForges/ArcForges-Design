## 1. Exact independent source and settings

The host receives exactly three additional optional private strings: `AF_OPERATOR_PROVIDER_POLICY_JSON`, `AF_OPERATOR_PROVIDER_POLICY_SIGNATURE_JSON`, and `AF_OPERATOR_PROVIDER_POLICY_TRUST_JSON`. Missing or malformed configuration makes this producer unavailable; no default, network key lookup, generated signing key or candidate Configuration document supplies it. These are distinct from C19's `AF_OPERATOR_ASSERTION_SIGNING_JSON` and `AF_OPERATOR_ASSERTION_TRUST_JSON`.

The first setting is the original UTF8 body of the published `internal/identity/v1/provider-policy.schema.json`, schemaVersion `operator.provider-policy.v1`, at most65536 bytes. The producer uses the actual published CloudInternal344.1 generated `OperatorProviderPolicyJson.TryParse` and preserves the exact original body bytes and their SHA256. It neither reserializes before signature verification nor widens the generated shape policy.

The second setting is a closed object with exactly `algorithm`, `kid`, and `signature`. Algorithm is exactly `RS256`; kid is a nonempty canonical ASCII key identifier of at most128 bytes; signature is canonical standard Base64 of the detached PKCS1v1.5 SHA256 signature over the complete original body bytes. Its entire UTF8 input is at most4096 bytes; decoded signatures are256..1024 bytes, exactly the selected RSA modulus length. There is no untrusted embedded key, JWT header, remote reference or candidate-provided algorithm selection.

The third setting is a closed public-only object with exactly `schemaVersion`, `deployment`, and `keys`. SchemaVersion is `operator.provider-policy.trust.v1`; entire UTF8 input is at most32768 bytes. Deployment has exactly realmId, environment, tenantId, clientId, accessApplicationId, issuer, operatorOrigin, redirectUri, requiredAuthenticationContext, and credentialVersion. IDs are canonical nonzero lowercase UUID D strings; environment and credentialVersion use the published body bounds. Context is exact c1..c99. Issuer is the exact tenant-specific Microsoft v2 issuer; operatorOrigin is an exact configured HTTPS443 origin without userinfo/path/query/fragment; redirectUri is an exact configured HTTPS443 callback without userinfo/query/fragment, under that origin. No loopback/IP literal or common/organizations/personal-account issuer is supported. All URL lengths are bounded by the actual provider/body profile, never normalized into another original string.

Keys is a unique1..8 list of closed objects with exactly kid, publicKeySpki, notBefore, and notAfter. Kids use the same bounded canonical key syntax. PublicKeySpki is canonical standard Base64 of canonical public-only RSA DER-SPKI, at most12288 decoded bytes, with exact whole-input import and re-export equality, RSA2048..8192, supported odd exponent and no private/trailing/other-algorithm material. Validity uses canonical UTC instants with actual1..9 nanosecond precision, a strictly positive interval, and exact lower-inclusive/upper-exclusive checks. Duplicate IDs, unknown fields, duplicate JSON keys, invalid UTF8/escaped surrogates, excessive depth or overbounds refuse before expensive cryptography. There are no arbitrary JSON or object-resolver extensions.

Deployment is independently configured trust, not a property accepted from the body. The body's complete realm/environment/tenant/client/access-application/issuer/origin/context/credentialVersion tuple must match it exactly. Signed policy IDs must be unique canonical IDs; the generated body parser and already admitted supported-policy rules remain required. CapturedAt must be at or before the current clock; NotAfter must be strictly after capture and the current clock. CredentialVersion is actual independently configured credential metadata associated with the existing `ARCFORGES_OPERATOR_ENTRA_CLIENT_SECRET` binding, never inferred from the secret value or the signed body. The host captures those four actual configured strings once into one immutable configured snapshot. The secret remains in its existing private configured credential owner; the policy source port exposes no secret/token getter. Missing secret/version association is unavailable, not successful trust.
