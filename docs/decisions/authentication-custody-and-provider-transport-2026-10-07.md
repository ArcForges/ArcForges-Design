## 2. Initial flow and durable proof binding

CON.31 publishes real internal typed authentication flow, step-up proof snapshot and immutable Operator evidence messages. CLOUD.12 encodes and validates those generated messages; it cannot store private JSON in a column named payload_proto. A shape-valid message is not authentication authority. Actual current configured realm, positive AuthEpoch, nonnegative recovery generation and current recovery revision are captured when a flow begins, including an anonymous flow. Anonymous actors/users remain absent rather than fabricated.

The initial envelope binds flow ID, exact purpose/method/provider, origin and RP separately, optional genuine actor/user, installation/device, and at most one existing native/browser row reference. It does not duplicate authorization code/hash, PKCE/state/challenge/session secrets, attempt counters or consumed state. At successful proof/code mint, it additionally captures actual User, Device and Installation revisions applicable to the proof. Issuance consumes those original revisions with the existing row and same-family guards; a later read cannot upgrade old proof after logout, key rotation or epoch change. Fresh independently verified authentication may establish new revisions. Native session-derived pending grants also bind the actual source session revocation guard.

Existing browser_auth_flow has attempts, max_attempts and consumed_at with its one-way terminal update trigger; it has no state/rev. Existing security_flow has neither state nor rev. Existing native_authorization has a real rev. Preserve these facts and use the actual immutable payload/nullable-consumed precondition/trigger rather than invented columns. CLOUD.12 expands the browser purpose check from authenticate1/enroll2/recover4 to those values plus cancelDeletion5, retaining exclusion of stepUp3. Only a new forward migration changes this check. Purpose5 issuance still requires the actual persisted CLOUD.79 grace/deletion authority and the restricted CLOUD.13 session; no old trusted-device resurrection or normal-session authority follows.

Step-up Begin co-commits an actual Identity-owned security_flow row of kind stepUpProof, flow ID equal to the real challenge ID, containing the exact original binding and method-specific credential inventory. A bounded inventory of at most64 original credentials is one typed row, not a variable number of fictitious fixed role slots. Prove loads this original snapshot and the actual current credential, checks original membership/revision/binding and consumes the snapshot atomically with the genuine method effects and challenge. Recomputing an outward challenge or using only a proof hash cannot reconstruct original membership after restart.

Synced passkey backup/counter changes require independently verified additional proof and audit under the same captured user/epoch/revisions; they cannot authorize themselves. Non-backup counter rollback refuses. Pre-login additional proof uses the actual authentication-owned typed flow and one-use consume, without inventing an ordinary session merely to enter the session-bound step-up table. Unavailable additional proof refuses.

## 4. Independently provisioned provider policy and evidence

Bootstrap trust is independent of candidate/current Config approval. CLOUD.12 owns a required immutable configured operator.provider-policy.v1 artifact and its trusted detached signature/key association. CON31 publishes the closed policy body schema. It binds schema/version, realm/environment, tenant/client/provider issuer, exact required authentication context, at most16 configured CA policy IDs, complete supported-policy projection hash, source identity and capturedAt/notAfter. Canonical body bytes and SHA256 are preserved. The signature uses the existing configured fixed RS256/kid trust profile; exact approved public key/signature association is verified before use, without an arbitrary algorithm/JWKS or candidate-supplied key. Missing/expired/untrusted policy refuses; a caller boolean is not enforcement evidence.

Read the complete configured Graph policy objects at flow start and completion, without a projection hiding predicates. The minimum supported policy is enabled, targets the exact authentication context, covers the intended configured users without exclusions, requires MFA under an AND grant (a sole MFA grant is equivalent), and uses everyTime primaryAndSecondaryAuthentication. Reject unsupported predicates/strengths or incomplete policy evidence. An authentication-context policy targets that context; do not impose a simultaneous application-resource target that the provider does not support. Token tenant, issuer and configured client GUID audience remain separately verified. [Actual Graph policy read](https://learn.microsoft.com/en-us/graph/api/conditionalaccesspolicy-get?view=graph-rest-1.0), [authentication-context targeting](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-cloud-apps#authentication-context).

The closed policy body requires schemaVersion=operator.provider-policy.v1, version (Key<=128 UTF8), realmId (nonzero canonical UUID), environment (configured Key<=64), tenantId/clientId/accessApplicationId (canonical GUIDs), issuer/operatorOrigin (exact HTTPS<=2048), requiredAuthenticationContext (c1..c99), sorted unique policyIds (1..16 GUIDs), supportedPolicyProjectionSha256 (lowercase64 hex), sourceReference (printable<=256), credentialVersion (Key<=128), capturedAt/notAfter (exact UTC Instants with notAfter>capturedAt). Unknown fields refuse; body<=65536 UTF8. Hash/signature use exact registry04 canonical JSON body bytes without Unicode normalization; detached fixed RS256 signature is RSA/SHA256 PKCS1 over those bytes and trusted configured kid/public key, not an algorithm/key supplied by the body. The full supported-policy projection excludes only provider diagnostic fields, retains every policy predicate/control, rejects unknown predicates and is independently vector-tested; a schema-valid policy artifact is not observed Graph enforcement.

Signed auth_time is the last user-authentication instant, not a separately attested factor timestamp. acrs alone is insufficient and iat/now/callback is never MfaAt. Require signed auth_time no older than five minutes together with the actual validated independent policy observations and context binding; preserve the provider's documented everyTime skew. A sensitive operation requiring a stronger guarantee refuses if this evidence cannot establish it. CON31 evidence retains exact signed seconds, token expiry, signing kid, metadata/JWKS hashes, policy begin/completion observations, assertion digest, verified oid/sub and original flow/current authority. It has no success/MFA boolean or raw token.

Published ConfigurationOperatorIdentity.audience remains the HTTPS private server-assertion resource audience. C12 ID-token aud is the canonical configured client GUID; the private assertion issuer is distinct from Entra provider issuer. accessApplicationId identifies the configured application ID; actual Graph lookup resolves a distinct resource service-principal object ID. No label-based role authority or schema widening follows.
