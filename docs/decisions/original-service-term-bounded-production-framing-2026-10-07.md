# Original service Term bounded production framing

Status: proposed; source changes require both reviewed planning repositories to merge.

## 1. Actual gap and owner

COM.16's delivered D1 store prepares a complete `TermsJson` scalar and its fixed `entitlement.commit` plan uses `json_each`. The generated private ExecutePlan request and response envelopes each allow 262144 UTF8 bytes. A valid 262144-UTF16-unit `period_ref`, or nullable `subscription_ref`, can exceed that request after UTF8 conversion and JSON escaping. P68 copies and reopens a retained original Term for COM.07; a direct SQLite fixture does not prove that the production creation path can create the longest original.

COM.21 is a separate minimum Entitlement-owned producer. It preserves COM.16's completed delivery, existing grant rules, original fifteen Term columns, natural identity `(realm_id,kind,period_ref)`, snapshot encoding, seven-day command receipt, and single guarded writer. Its independently implementable core starts from COM.16 and CLOUD.72. Production composition with CLOUD.21/75/82, the current-definition writer and P68 protection is required completion, not a cyclic core-start barrier. COM.07 completes integration with this producer; its current start and historical accounting remain unchanged. No arbitrary staging, public RPC, caller permission Boolean or new SQL interpreter is added.

## 2. Captured original and bounded representation

The actual Entitlement producer captures the complete immutable original command and append before its first await. It validates the existing fifteen Term fields and normal domain constraints, a maximum of 100 appended Terms, strict well-formed UTF16 and the published 262144 UTF16-unit maximum for each reference. `subscription_ref` remains nullable only under the existing kind rule. It computes the complete original command hash using the existing COM.16 normalization, streamed without changing escaping or field order; it never accepts a caller hash as proof. Source/source-command identities, workspace, realm, expected Entitlement revision, actual configured recovery generation and the retained definition association remain exact. A term-only transport digest is not the complete command hash.

Each present reference is strictly encoded as UTF8 and divided at scalar boundaries into chunks of at most 16384 bytes. The maximum 786432 UTF8 bytes per field follows the unchanged UTF16 bound. A present empty field has zero parts and an explicit zero length/hash; NULL is a distinct manifest flag, not an empty field. `field_kind` is closed to 1=period and 2=subscription. Chunk positions start at zero, have no gaps, and a field has at most 48 parts. The exact original reference byte length and SHA256, part count and every per-part hash are owner-computed. Both references, NUL, quotes, backslashes, non-ASCII and supplementary characters retain all original bytes.

The complete ordered Term metadata manifest excludes reference contents and individual part hashes. It contains exactly the original fifteen-field facts, the two exact complete reference descriptors, sequential Term ordinal and original command/context association. Its canonical UTF8 encoding is bounded to 131072 bytes and at most 100 Terms; it travels as a BLOB, whose actual base64 envelope is independently serialized and checked before dispatch. Part hashes belong to the immutable part rows and are verified from actual reopened bytes. The bounds are tested against the worst valid fixed metadata; no silent row truncation or shortened public reference is allowed. Full business command semantics remain retained by the original command hash and immutable input custody. A finite ChangeRecord contains original command/input/Term identities and hashes within its existing 65536-byte limit; it does not carry the long references or replace their durable custody.

## 3. Exact owner physical state

Add only two Entitlement tables through an integration-numbered, forward-only expand migration; never rewrite accepted DDL:

- `entitlement_term_input`: `input_id:id` PK, `realm_id:id`, `workspace_id:id`, `command_id:id`, `request_hash:hash`, `expected_rev:int64`, `recovery_generation:int64`, `manifest_bytes:bytes` 1..131072 (strict owner-validated canonical JSON object), `manifest_hash:hash`, `term_count:int` 1..100, `state:enum` Preparing1/Ready2/Consumed3/Expired4, `created_at:instant`, `expires_at:instant`, `consumed_at:instant?`, `rev:rev`. UQ `(realm_id,workspace_id,command_id)`; expiry index `(expires_at,input_id)`. The original tuple and manifest are immutable. Initial rev=1/state=Preparing, no consumed time, lifetime positive and at most ten minutes. Only monotone Preparing→Ready, Preparing/Ready→Expired, and Ready→Consumed are permitted, each with rev+1; Ready→Consumed occurs solely in the final atomic writer. Expired and Consumed cannot be rejuvenated or replaced.
- `entitlement_term_input_part`: `input_id:id`, `term_ordinal:int`, `field_kind:enum`, `part_index:int`, `part_bytes:bytes` 1..16384, `part_hash:hash`, `created_at:instant`; PK `(input_id,term_ordinal,field_kind,part_index)`, FK input_id restrict. Rows are immutable. A fixed insert guard checks the current parent Preparing/original descriptor/index/deadline and exact tuple; identical part replay preserves the first bytes, changed replay refuses including INSERT OR REPLACE with recursive triggers OFF/ON. No foreign owner/table can opt into this discipline.

The producer does **not** rejuvenate expired input custody. It returns typed Expired/Stale for an expired unused command input, preserving its original command identity; callers needing a fresh attempt supply a genuinely new command after definitive original receipt reconciliation. A committed original command remains replayable from its seven-day receipt even if preparation deadline has passed. This rule does not shorten a previously committed command's receipt retention.

A closed `serviceTermInputOriginal` profile validates the exact two table shapes, PK/UQ/FK/indexes/enums, original columns and transition predicates before `validateSchema`, `tableSql` or `triggerSql` emits SQL. It emits fixed owner predicates, never a supplied SQL expression. Preserve P68's `serviceTermOriginal`, COM20/18/basis preserveExisting, C79 and the exact frozen C83 security profiles through the shared-helper owner handoff. Input state mutation and original insert protection are covered by actual recursive OFF/ON replacement and direct-builder hostile tests. A seven-day expiry index and bounded owner cleanup delete parts then input only after the original command receipt retention boundary, never while a command can reconcile or a final transaction can consume it. Cleanup is storage custody, not Term permission.

## 4. Actual asynchronous producer and final writer

Publish a cycle-free Entitlement-owned `PrepareAsync` seam returning either a sealed immutable prepared mutation or typed Invalid/Conflict/Expired/Unavailable/UnknownOutcome. Replace the existing synchronous prepared-store integration in `Resolver/Application/Ports.cs`, `Persistence/D1EntitlementStore.cs` and `Resolver/Definitions/Application/CurrentDefinitionEntitlementStore.cs` with real awaited producer composition; never block async I/O or install an available fake fallback. Ordinary short appends retain equivalent complete request hashes, result classification, receipt identity and snapshot effects. The actual Entitlement service/grant adapter consumes this seam; no foreign module obtains a writable preparation implementation.

Named Entitlement plans are closed to begin, put-part, bounded metadata/text/part reads, seal-ready, expire, retention cleanup, final input-current guard and final Term append. They use only Entitlement/Platform owned tables and the existing generic signed private plan transport. Each operation has nonblocking bounded admission and a thirty-second total deadline including waits; the complete preparation has the original immutable deadline, no retry rejuvenation. Only one final command per workspace may be prepared into the writer; bounded production configuration fails closed if absent, never guesses a realm/generation/key.

Begin is an immutable owner write with exact original command hash/context, not customer or paid-operation authority. Put-part is an idempotent owning storage write; it cannot create a Term. The host reopens every actual part through bounded BLOB reads, checks strict UTF8/UTF16 length, ordinal and field counts, no gaps/extra parts, all part hashes and complete field hashes, and independently reconstructs the complete original command normalization. Seal-ready repeats actual stored counts/lengths and original manifest identity; SQL does not implement SHA256. A ready seal is an observation of immutable custody, not a current permission grant.

The real existing Entitlement single writer joins the exact scoped current-definition/Config/Workspace/domain authority, current recovery and final clock guards, the original workspace Entitlement revision and exact Ready input identity/hash/revision. Fixed SQL selects the verified immutable manifest and ordered original reference bytes, reconstructs both fields without returning their full contents through a private response, and inserts all original fifteen Term fields. It consumes that exact input and appends all grants/actions, snapshot, Entitlement revision, original receipt/outbox and archive in the **same** guarded batch. Missing parts, stale input/source/current permission, expiry, natural-key conflict or concurrent first writer cause no partial Term/snapshot/input consumption. No detached staging write authorizes Term admission. C82 capability scope and actual producer instance are retained; an asynchronous check alone never closes final authorization.

Reconstruction uses a fixed ordered owner query per original field (bounded complete bytes) and a tested SQLite BLOB/text concatenation path preserving embedded NUL. It neither uses SQL SHA nor caller concatenation SQL. Generated complete request serialization, not only individual scalar size, must remain ≤262144 bytes; the final parameter vectors contain finite manifest/input/hash identities. Reopened responses, including escaping/base64, are checked against the actual generated 262144-byte envelope. All writes use the real signed executor and named factory; no Foundation/probe transport or generic object upload alias.

## 5. Cancellation, unknown response, concurrency and retention

No blind write redispatch occurs after an unknown response. Begin/part/seal response loss first reopens exact immutable custody with the same original command/part identity; only a definite missing observation permits that identical write. Final response loss reads the exact original command receipt before retrying the same immutable prepared mutation. A persisted success is replayed without additional revision/outbox/Term; an expired unused input cannot manufacture a new command. Unknown/unavailable reads propagate typed refusal and do not justify rollback or a new identity. The existing seven-day stable command identity remains intact.

Caller cancellation wins immediately after each buffered dependency and before every result/refusal or prepared capability. After an acknowledged or unknown final write it may still throw, while exact receipt replay preserves the committed effects; no rollback is claimed. Shutdown cancels active/queued work, disposes owned handles and releases permits once. Queue overflow is typed Unavailable before payload copies. Exact repeated Begin/parts/seal, transposed fields/context/hash, concurrent differing commands, lost responses, late deadline/recovery/revision/Config authority and cleanup races are exercised through actual owner stores/Worker SQLite. Actual current authorities may be unavailable external fixtures only when the test explicitly proves refusal; successful joined effects use real owner contributions.
