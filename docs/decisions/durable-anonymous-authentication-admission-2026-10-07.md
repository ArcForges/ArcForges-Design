This decision admits CLOUD84 as the missing durable anonymous authentication admission producer. Pat owns the complete Identity policy, bucket core, persistent adapters and actual guarded issuance integration; Provider owns the authentication consumer facade; Root owns only the closed final transaction-clock compiler profile. Existing authentication, recovery, mail delivery and deployment acceptance remain required.

## 4. Genuine edge source and private request binding

For the configured Cloudflare public ingress, capture the actual platform-provided edge source only in the deployed Worker. Parse its canonical address/source group, then immediately HMAC it with the exact singleton key/domain; do not persist or log the address. A public header is not independently trusted by the Container. Cloudflare documents that cross-zone Worker subrequests have a shared fixed source address and same-zone subrequests reflect the owning Worker's behavior; this profile treats such a verified platform source as its actual source group, not a claim about an end user's identity. The configured zone/route and own Worker code remain the trust boundary. Unsupported self-host/proxy paths require a genuine independently authenticated source adapter and otherwise return typed unavailable; no local or caller-IP fallback.

The Worker discards caller-supplied internal evidence/signature headers and constructs one closed bounded private evidence frame for only the registered admission routes. It binds the fixed profile domain, actual configured realm, exact registered operation/method/path, SHA256 of the complete already-bounded original gRPC-Web frame bytes, source digest, singleton policy/key identity, cryptographic nonce, original request identity and original server-issued short lifetime. Sign/verify with the existing actual W2C HMAC primitives/key lifecycle and bounded encoding; preserve those primitives' existing signing format and every Foundation default. The new profile is anonymous-admission-source.v1. A canonical closed UTF8 JSON evidence object<=2048 bytes carries schema, realmId, operation, method, path, bodySha256, sourceDigest, policyVersion, policyKeyId, policyKeyDigest, requestId, nonce, issuedAtSeconds and expiresAtSeconds; IDs/digests use the existing canonical shapes and timestamps are canonical positive decimal strings. Transfer only its canonical unpadded base64url in X-AF-Admission-Evidence. Require evidence requestId/nonce/issuedAtSeconds to equal the actual private signature header fields; expiry is strictly later and at most60 seconds, with host now inside the original lifetime. Sign the exact evidence object's SHA256 as the selected profile digest using existing W2C sign/verify and the actual original method/path, without changing the shared six-line signing primitive. The evidence contains the separate actual whole gRPC-Web body SHA256, independently recomputed and compared by the host; the profile digest is not falsely labeled as that raw body hash. The profile domain prevents reuse as a Foundation/body-transfer signature. Existing W2C current/previous key parsing, disposal and configured deployment forwarding remain unchanged. The host verifies every original byte/tuple before decoding an admission request, owns the immutable verified observation and preserves the request bytes for the generated handler. Mismatched body/path/realm/key/time, absent evidence, duplicated fields/headers or untrusted source refuse before bucket or flow effects. Evidence lifetime is at most60s and is never renewed by a replay. HMAC verification is transport integrity, not a user/session grant or proof that a flow committed.

Required policy/key/source configuration is lazy: missing or malformed configuration makes security operations typed unavailable while unrelated health/Hello remain constructible. Forward only the exact private configured names required by this producer, with strict owner parsing and no generic secret resolver. No secret/address/request body in logs, workflow checkpoints, receipts or public errors. Preserve original private body262144 and per-route request/response bounds, deny-by-default routing, workers_dev=false and configured routes.
