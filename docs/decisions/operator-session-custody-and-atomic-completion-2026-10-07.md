This decision supplements the accepted authentication custody and scoped-family decisions. CLOUD.12 owns the provider ceremony, original protected material and generated evidence; CLOUD.19 owns the separate Operator cookie, CSRF, current session and private assertion. CLOUD.13 remains the sole downstream family-union writer. CLOUD.78 owns the closed final-statement clock profiles. These additions do not authorize a customer bearer, a caller-created authority DTO, or an unavailable provider. Existing progressive starts, account surfaces, published wire contracts, acceptance obligations and immutable history remain intact.

Add two immutable fields to the actual Identity-owned `identity_operator_provider_flow`: `begin_policy_proto` is a non-null BLOB of 1..65536 bytes containing the actual published CON31 OperatorPolicyObservation; `begin_policy_sha256` is a non-null 32-byte SHA256 of those exact bytes. Completion retains the original Begin observation verbatim and independently captures the genuine Complete observation. Neither incomplete completion evidence nor private JSON substitutes a restart-safe Begin fact.

Preserve the accepted 41 original fields, their nullable groups, one-way state/revision rules and real uniqueness. A fixed modeled `operatorFlowOriginal` insertion invariant rejects an existing flow ID, state hash, preauth hash, non-null attempt ID, non-null code hash with the same realm/provider, or non-null completion-handle hash before SQLite conflict replacement can delete an original row. These are the actual six uniqueness conflicts; nonce is not unique. The rule operates with recursive_triggers OFF and ON, preserves ordinary new inserts and rejects replacement/UPSERT attempts without changing the original row. No arbitrary predicate, extra-trigger waiver or default trigger change is admitted. The actual physical generator retains the exact modeled trigger SQL in expected-shape verification.

Flow deletion is `none` for this producer. Prepared/Dispatched expiry erases custody and records the terminal outcome while retaining dispatch/code fences and evidence needed by sessions. Completed/Consumed evidence is not expired as an unused ceremony. CLOUD.12 owns a future bounded physical-retention/purge producer coordinated with CLOUD.19's actual evidence references and current75 authority; its policy, guards and source admission require a separate review before activation. This decision supplies no success-returning purge port or implemented purger claim. Preserve all accepted migration bytes; use the actual pending expand and integration-assigned numbering.

## 3. One atomic completion family and session rotation

Register only `operator-authentication`, required Identity and Platform, exact owner-resolved configured Realm UUID scope, RequiresScopedContributions=true. Every security-effect plan uses the actual privileged current75 realm/authEpoch/recoveryGeneration/recoveryRevision contribution. Expiry uses an explicitly closed operational current-realm/expired-row authority, not a user/session grant. Anonymous login never invents customer User, Device or Workspace rows.

The fourteen exact plan IDs are `families.operator-authentication.` followed by each of `prepare`, `claim-exchange`, `complete-exchange`, `refuse-exchange`, `mark-exchange-unknown`, `consume-completion`, `expire-flow`, separately suffixed `-login` and `-step-up`. Each has genuine phase-specific owner effects, no universal no-op roles. C12 prepares fixed-purpose Prepared1/rev1 plus original observation and custody; claim atomically records Dispatched attempt/code uniqueness before one external token POST. Complete requires the exact dispatched attempt/revision/original binding and genuine current configured token/signature/policy evidence, then records Completed, erases custody and stores immutable generated evidence/digests/completed time and a random outward handle HASH once. Refuse/Unknown record the exact dispatched outcome even after its transport deadline, erase custody, and never reset or redispatch. Unknown commit or transport result is reconciled read-only; empty reconciliation never authorizes another POST.

Every step-up security transition binds the original C19 old session ID, positive sidecar revision, evidence ID/hash, tenant/oid/sub/origin/realm and current unrevoked/unexpired association. No later read upgrades the original proof. `consume-completion-login` atomically consumes the C12 completion and creates one genuine C19 base/sidecar/independent CSRF binding. `consume-completion-step-up` atomically consumes completion, revokes the exact old base session and increments its sidecar revision, and issues a fresh base session/handle/CSRF/sidecar rev1 with the same verified tenant/oid/sub/origin/realm. The new absolute deadline must not exceed the old original absolute deadline. Earlier stolen handles cannot inherit new assurance.

The generated evidence retains its original old-session step-up witness; the actual consumed-flow/new-issue association proves the new binding. Do not substitute the new sidecar revision for the original witness. Emit raw new handle and CSRF only after genuine success. Lost acknowledgement cannot reconstruct either secret from a safe command receipt; keep the old session revoked and require a fresh ceremony. Completion consume never commits before a separate session write, and sealed contributions never cross families.

Register `operator-session` only for `families.operator-session.touch` and `.revoke`, required Identity plus actual privileged Platform contribution and exact Realm scope. Touch checks current base/sidecar/origin/CSRF/realm/evidence/expected revision and final absolute/idle expiry, monotonically extends within the bound and increments rev. At most two benign touch retries may re-resolve fresh facts; never replay a business operation. Revoke checks the actor's genuine current binding and atomically makes base revoked_at one-way plus sidecar rev+1. Missing/expired authority cannot revoke another subject. No duplicate create/step-up family is admitted.
