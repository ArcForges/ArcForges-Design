# Design Policy Export and Integrity

Authority: [P2-016](../decisions/phase-2-specification-decisions.md#rule-p2-016), implementing [WP-00.01](../planning/work-packages/00-specification-naming-and-rights-freeze.md#rule-wp-00.01). Design remains the authored authority. DesktopPlatform owns the AGPL-3.0-only exporter, derived policy data and continuing corpus check; Contracts retains the separate Apache-2.0 [naming authority](28-product-naming-policy.md).

## Immutable input and ownership

DesktopPlatform records an exact Design commit and the hashes of its policy sources. Its portable Python check reads that committed documentation snapshot, either from an explicitly supplied clean Git worktree or an isolated checkout fetched at that exact commit. It never follows a moving branch, reads deprecated input bodies, runs Design code blocks, changes another repository or adds product source/project references. CI obtains the same pinned documentation input and retains its identity with the check results. Ordinary product consumers read the checked-in policy data without a Design checkout; later build-policy distribution belongs to WP02/WP05.

The exporter emits `eng/policy/glossary-terms.json` and `eng/policy/invariants.json`. JSON records contain source paths, section/row locations, exact Markdown cell values and parsed fields; records cannot be silently dropped, merged or rewritten. The tool compares fresh generated bytes with both tracked outputs. Extra, missing, duplicated or edited records fail. Source changes require a reviewed pin and export update. A read-only check of a proposed Design worktree is also available before its documentation PR merges; preview evidence records its dirty state and is not an immutable export release.

## Vocabulary and invariant records

The glossary sections 1–5 are the canonical term table source. Every row has explicit term spaces. A retired row has no active spaces and retains its disposition. All explicitly marked spellings in a term cell are preserved as names sharing that row's definition; a product-qualified spelling never loses its prefix. A pair of distinct names in one row does not make them runtime aliases or the same type. Prose examples and lifecycle values are context, not additional implicitly inferred term definitions. The named simulator objects are explicit table rows.

Section 8 supplies every forbidden-alias row, including its contextual prohibition, reason and replacement/disposition. Contextual phrases such as a bare product-local term are not a global substring ban on ordinary prose. WP05 implements the corresponding contextual checks. The six naming bans already enforced by Contracts remain in force.

Each catalogue row is joined by its stable invariant ID to exactly one coverage section 7 row. The export preserves the catalogue statement, architecture home, exact mechanism, planned verification, owning packages and completion gate. Statements must agree after Markdown presentation normalization, owners must identify active work packages, and mechanism totals are recomputed from rows. Retired rows remain present with absence tests. The export records planned verification only: it cannot mark an invariant implemented or close [PG-11](../assurance/open-gates-register.md#rule-pg-11).

## Complete corpus and graph checks

Enumerate Git-tracked Markdown documents, excluding deprecated input bodies before reading them. Their filenames may remain historical link targets. Validate every local link, fragment and document-scoped rule definition; regenerate a report identifying each citation's source location, defining document and stable anchor. Identically spelled rules in different documents stay distinct. A citation with the wrong named rule anchor, missing home, ambiguous home or duplicate definition fails. Current rule citations use explicit defining-document links. Historical review identifiers, preserved quotations, reserved allocations and standard names require explicit classifications; an exact occurrence classification records the file, source-line hash, token, reason and review owner, so it cannot become a blanket file or directory exemption. The reviewed [occurrence register](../assurance/citation-classifications.json) is the sole classification input; unused or changed entries fail. Fenced historical program examples are parsed as examples, never run or counted as current rules.

Validate the [delivery graph](../planning/delivery/delivery-graph.json) under [P2-018](../decisions/phase-2-specification-decisions.md#rule-p2-018): unique task identifiers and lanes, known repositories, typed edges with stated need and reason, prerequisites satisfiable under [DLV-24](../planning/delivery/README.md#rule-dlv-24), every active substep and package obligation mapped to at least one task, exactly one adoption slice per repository and lane, no start prerequisite on a package acceptance task from outside that package ([DLV-35](../planning/delivery/README.md#rule-dlv-35)), substitutes classed value or behavior whose removing task depends on the real producer and every consumer, and generated views (lane catalogues, traceability, substitutes, shared resources, schedule analysis and each package's section 9 block) byte-identical to a fresh generation. Require unique numbered top-level sections, all nine mandatory work-package sections and exactly one owned `.90` evidence row in each active package's section 7. Future WP20 and retired WP27/WP29 have no tasks. The active obligation packages used to validate invariant owners are those with delivery tasks. The retired package-level tables, serial execution list and declared edge counts are no longer checked; DesktopPlatform replaces its package-graph check before moving its pinned Design commit, as recorded in the [adoption stage](../planning/delivery/adoption.md).

Negative fixtures must actually remove, duplicate or corrupt source/export records, rule homes/anchors, citation targets, task edges, obligation mappings, substitute replacements, generated views and evidence rows. Their failing diagnostics must identify the affected source or output. A passing current corpus alone is not sufficient evidence that the check rejects drift.

## Derived declarations and the naming scan

The glossary export is generated AGPL policy data, not a second authored product-name authority. Contracts may recognize only DesktopPlatform's exact `eng/policy/glossary-terms.json` forbidden-alias array as a derived declaration. The naming registration binds the Design commit, source document SHA-256 and canonical JSON SHA-256 of that array. Validate the closed export envelope and exact registered declaration digest before omitting those declaration values from substring scanning. Scan every other value and path normally. Unknown fields, modified declarations, copied files and declarations in another repository fail. This is declaration validation, separate from the unchanged hash-bound reference-provenance exception rules. Registrations may precede the dependent export PR; the nine-root acceptance check must exercise the actual exported file before WP00.01 completes.

## Verification facts and limits

Checked 2026-09-18: GitHub documents [heading and custom-anchor links](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links) and [fenced code blocks](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-and-highlighting-code-blocks). The checker supports the corpus's explicit inline-link, table and stable-anchor conventions, rejects unsupported reference-link syntax rather than silently omitting it, and tests duplicate heading suffixes and fence lengths. It does not claim to implement a general Markdown renderer. Historical counts and old embedded checker programs do not override the current computed graph or catalogue. No package capability, provider, device or commercial activation is proven by policy checks.
