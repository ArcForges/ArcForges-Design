# Architecture

This directory defines system architecture, runtime topology, component boundaries, data ownership, communication protocols, and security models for ArcForges.

All content here is **authoritative**. It is governed by the frozen Phase 1 decisions in [`../decisions/phase-1-foundation-decisions.md`](../decisions/phase-1-foundation-decisions.md) (D-001 … D-023) and by the verification record in [`../assurance/phase-1-official-verification.md`](../assurance/phase-1-official-verification.md) (V-01 … V-09). Architecture realises the requirements in [`../requirements/`](../requirements/README.md); where the two appear to disagree, the requirement states *what* must be true and the architecture states *how*, and any genuine conflict is a defect to be resolved, not a choice to be made at implementation time.

## Reading order

Read [`00-architecture-overview.md`](00-architecture-overview.md) first — it establishes the five controlling constraints, the runtime topology, the layering rules and the single write path that every other document assumes. Then read [`01-solution-and-project-layout.md`](01-solution-and-project-layout.md) and [`02-contracts-and-protocols.md`](02-contracts-and-protocols.md), which fix where code lives and how components speak to each other.

## Conventions

- Every architectural rule carries a stable identifier (`AB-nn`) scoped to its document, so requirements, assurance and work packages can cite it precisely.
- A rule states an obligation that a reviewer or a test can check. Where a rule is machine-checkable, the corresponding architecture or repository-policy test is named in [`01-solution-and-project-layout.md`](01-solution-and-project-layout.md) or in the document's own testing section.
- Citations to Phase 1 decisions use **D-nnn**, verification findings use **V-nn**, and deferred gates use **F-nnn**.
- Citations to preserved inputs use `I1`–`I4` with a section reference. Those files are historical evidence and are never modified.
- Superseded product names (`ArcCanvas`, `ArcMusic`, `ArcImage`, `ArcVideo`) and the superseded payment provider never appear as current, per **D-002** and **D-005**.
