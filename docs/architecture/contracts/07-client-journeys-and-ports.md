# Client Journeys, Owner Ports and Recovery

Authority: [P2-010](../../decisions/phase-2-specification-decisions.md#rule-p2-010); [numbered wire registry](04-protobuf-wire-registry.md) owns exact fields, [operation catalogue](00-operation-catalogue.md) owns errors/replay, [security](../08-security-architecture.md) owns authentication and grants. These are complete bindings for existing product behavior, not parallel APIs. Every normal business operation is generated proto; the listed auth/file/CF/provider exceptions are closed standard protocols. UI text may be localized without changing the behavior.

## 1. Identity and session paths

`AuthFlow` is server-owned: flowId, realm, purpose, method/provider, installation claim, originating browser Origin/RP when applicable, recoveryGeneration, issuedAt/expiresAt, challenge hash, attempt count, proof-consumed state and limited credential replacement challenge. A flow is not a user session. Begin is anonymous/rate-limited/no-store and reveals no account existence. Maximum 5 proof attempts; email flow 10 minutes, OIDC receipt 60 seconds, local enrollment grant 15 minutes. Native/Browser result shaping cannot be selected by a spoofed body flag: the listener/edge profile fixes it.

RecoveryMethod is emailCode/recoveryCode/passkey/adminGrant. Account hints identify a configured realm account without treating email as universal authority. Administrator CLI creates a hashed scoped grant through the audited Identity application service, not direct password/DB edits. It never prints existing credentials.

Browser standard-auth mappings under `/session/v1` are: GET bootstrap; POST authentication/begin, authentication/complete, enrollment/complete, recovery/begin, recovery/complete, step-up/begin, step-up/complete and logout; GET providers/{providerId}/callback for OIDC only. Request fields mirror their exact numbered Identity records as JSON precise-value projections. Response uses AuthChallenge, StepUpEvidence, Receipt or SessionView with Set-Cookie, never NativeSession. Pre-auth Origin+CSRF flow applies to every POST, authenticated CSRF applies after login, all responses no-store. Credential/profile/email/PAT management remains ordinary cookie-auth gRPC-Web with safe secret-display rules. C# adapters call the same handlers/transactions. No unspecified `/auth/*` endpoint is needed.

Each application installation completes its own native browser ceremony and stores its own protected session. There is no DeviceSsoBroker, device SSO RPC, shared desktop credential source or cross-product session transfer.

### Native browser authorization and PAT completion

Native clients may redeem email codes through the existing generated Identity methods. For browser login, generate a 32-byte random state and PKCE verifier (RFC7636 S256, 43–128 unreserved characters); persist only a short-lived pending flow in OS secure storage. Open the system browser, never an embedded webview. GET `/session/v1/native/authorize` takes client_id, redirect_uri, response_type=code, code_challenge, code_challenge_method=S256, state and installationId; all required, state ≤128 ASCII bytes. client_id is the closed product/platform client registry below; exact redirect matching, no wildcards. Server binds the browser login/explicit account confirmation, realm, installation and requested client, expires the flow after 10 minutes and issues a random 32-byte code valid 60 seconds. Store only the code hash plus verifier challenge. Callback contains only code and state; failure contains error and state, never tokens.

POST `/session/v1/native/token` is a standard form-urlencoded exception (≤16 KiB), fields grant_type=authorization_code, code, code_verifier, client_id, redirect_uri, installationId. No client secret in a public native app. Atomic guarded consumption verifies all original bindings and returns native access/refresh tokens and expiries (NativeSession field semantics) with Cache-Control:no-store. Wrong verifier never consumes a valid code; attempts are capped at 5 then the flow is invalidated. Redeemed/expired code cannot issue another session; a lost token response requires a fresh authorization flow, not code replay. State mismatch/canceled callback discards the flow. Native refresh remains generated Identity.RefreshSession with rotation/reuse detection. Browser cookies are never copied to the app. Session rows remain per installation/product even if the browser reuses a login.

Official passkey RP ID is `arcforges.com`; web origins are exactly https://account.arcforges.com and https://chat.arcforges.com. Android Credential Manager uses the RP's assetlinks.json at https://arcforges.com/.well-known/assetlinks.json with the same package/certificate. Server verifies challenge, RP hash, allowed browser/Android origin, credential ownership and user verification. Native desktop passkeys run in the system-browser ceremony. Self-host advertises its own HTTPS RP/origins; clients never send official credentials/cookies to it. Development fingerprints/redirects exist only in development realms. WP22 produces minimal authorization UI/handlers plus native fixtures; WP47/48 integrate public/account static assets; WP53 registers desktop URI handlers.

PATs are generated in the account portal after step-up, displayed once, stored hash-only and given explicit expiry and exact operation scopes from catalogue 00. CLI sends Bearer on eligible gRPC-Web calls and never passes a PAT in a URL or browser cookie. Revocation takes effect on the next authorization check; no agent/extension actor may elevate itself using a human token.

Each professional application starts from its own account state. On a second product’s first launch, show its own sign-in action; never show a sibling-discovered account chooser. Browser-held authentication may shorten the ceremony but does not copy ArcForges sessions.

## 2. ChatTurn and AgentTask

| Trigger | Durable owner and path | Completion / recovery |
|---|---|---|
| Plain append without generation | chat.appendMessage with no TurnOptions | One user message commit, no model/admission or Task. |
| Ordinary generated reply | TurnOptions ordinary + caller turnId; Chat owns ChatTurn, Resource pins and shared Entitlement/Commerce admission | Sole RunWorkflow uses ExecutionOwner.turnId. chat.getTurn plus canonical conversation reconciles. Read-only tools only; output commits once. |
| Agent mode | TurnOptions agent + caller taskId or task.create | Task owns plan/steps/attempts/approvals. task.get/getDetails reconcile; ordinary Task policies apply. |
| Write proposed in ordinary mode | Store TurnPromotionPreview; return waiting reason promotion.required; no write tool dispatch | Explicit chat.promoteTurn creates one linked AgentTask at matching preview/revision. It still requires ordinary approval/authorization. Decline/cancel leaves a read-only completed/interrupted reply, never a hidden effect. |
| Temporary reply | ChatTurn with temporary conversation; no ordinary history/list/knowledge projection | Body only in bounded encrypted transient execution storage,≤24 hours absolute; explicit close cancels and purges text within 1 hour. Client temporary drafts and compaction summaries are volatile. Crash can interrupt temporary work; metadata-only financial/security receipt survives. |
| Save temporary content | Explicit saveTemporary with new conversation ID and selected current authorized messages | Creates new durable content with origin; no execution/charge identity is copied or re-run. Missing/expired temporary content refuses, never fabricated. |
| Cancel/pause/retry | cancelTurn for ordinary/temporary; existing Task controls for agents | Control requested/acknowledged is separate from outcome. Known completed usage settles normally; uncertain dispatch is reconciled, not treated as zero or repeated. |

CF uses the same RunWorkflow, InferenceWorkflow, RunStream and fenced C# owner ports for both owner kinds. `ExecutionOwner` replaces Task-only identity in execution lease/command, provider attempt, stream and owner output/admission receipts. A compatibility taskId is present only when that owner really is a Task. ToolProposal/ToolRequest carries executionOwner; a pure read under ChatTurn uses ordinary grant checks and no forged Task. A write requires actual AgentTask. There is no second AI planner or Node sidecar.

Temporary source/output blobs and chunks are encrypted, purpose-scoped and excluded from backup/history/search/export. CF step input/return stores only reference IDs and metadata, never prompt/output/summary plaintext. Temporary compaction summary exists only within the active Worker step; loss before the next model dispatch is context.interrupted, no automatic duplicate compaction. Business/financial audit retains IDs/hashes/counts/reasons under normal retention, not content. UI states that the model received data; temporary is not a claim of zero provider processing.

Compaction uses the sole protected-set and refusal definition in [Harness HC-09](../17-agent-harness.md#rule-hc-09) and the window algorithm/vectors in [model 05](../data-model/05-application-history.md#context-window-and-compaction). The summary is untrusted derived context, not a replacement for user/system authority. Compaction is operator-funded under [HC-08](../17-agent-harness.md#rule-hc-08); no duplicate protected list or alternative refusal code is defined here.

## 3. Source consent and Web search

Cloud knowledge projection requires its existing permanent source policy. Explicit per-turn local input is a different route: user selects immutable bytes/range, sees purpose/size/egress, source.createConsent records actor/workspace/operation/source versions/policy revision/maximum bytes and 15 minute expiry. Upload uses Resource purpose=transientInput and the normal verified/hash/owner pin lifecycle; unconsumed transient bytes expire within 24 hours, consumed bytes when the declared owner retention/pins end. It neither enrolls sync nor indexes knowledge. Permission/revoke/generation is rechecked when consumed; a stale context needs a new snapshot/consent. One-time permission can only narrow the explicitly accepted source override scope, never override credential/ownership/privacy prohibition.

First-party capability `web.search.v1` binds WebSearchRequest/Result to the AI Worker provider adapter, not a new public arbitrary-fetch endpoint. Use Brave `GET https://api.search.brave.com/res/v1/web/search`, server X-Subscription-Token, strict safe search, offset 0, count 1–10(default 5), query 1–512Unicode scalars, allowlisted language/country, timeout 10 seconds, response≤256 KiB. Map ordered web results to rank/title/absolute http(s) URL/snippet≤2048 scalars/fetchedAt/provider=braveWebV1; reject malformed URL/nonfinite/control data, strip HTML markup from display. No fetch of returned pages, redirect to user URLs, executable snippets or hidden local context in the query. Duplicate URLs normalize scheme/host/default port only and retain first rank.

Search requires explicit enabled Web-search choice and query egress disclosure. It is a pure-read tool with external cost; operator-funded supplier budget reserves a bounded one-request charge, and the normal model answer remains customer-metered. Known response releases/settles operator exposure; unknown acceptance stays supplier reconciliation, never automatic second paid request. Result unavailable/capacity/timeout is visible and the answer cannot invent citations. Provider account, contractual data terms, tariff snapshot/budget and real response test are WP43/52 gates. [Provider API](https://api-dashboard.search.brave.com/app/documentation/web-search) documents the transport; this review created no account or live request.

## 5. Realm transfer and data health

`realm-transfer.v1` closes the accepted export-then-import migration. It is service owner-data interchange, distinct from the ordinary Markdown/Chat-JSON user export and not a native editable Notes file or a sync authority shared between realms. It cannot be substituted for an independent disaster backup.

Included roots: current Notes notebook/folder/document blocks/inline/property definitions/options/values/saved views; Chat projects/conversations/branches/messages/memory/artifact references; synced Scope sessions/capture manifests/analysis/reports and Slate project/sequence/asset metadata; managed blobs referenced by included roots. Source provenance, revision, exact values and hashes are included. Historic Task results may appear as inert content summaries associated with messages/artifacts, never a runnable Task. External native files are explicit missing/external references unless uploaded with consent. Keep user content and its reference mapping; unsupported version/kind is an issue, never silently skipped.

Excluded authority: credentials/tokens/device trust/remote grants, payment/credits/service terms/quotas, active execution/leases/outboxes, runnable automation schedules, operator/security audit, policy and deletion tombstones. Export a manifest of exclusions and per-root fidelity; no source deletion. The receiving realm assigns new owner IDs and rewrites every internal reference using a recorded mapping. External links keep origin identity and show unresolved availability. It never imports a deleted source into an existing destination root or revives a source tombstone.

Transfer API requestExport or previewImport uses caller transferId and immutable manifest/body resource. Preview validates version/hash/license/source scope/root references and destination permission/quota, calculates complete mapping and issue list, freezes previewHash≤24 hours. commitImport requires current previewHash/revision and each accepted omission code. Quota is rechecked per commit; actual unsupported mandatory fields block, optional explicitly acknowledged omissions yield partiallySucceeded. Import writes one bounded root and its mapped references/reservation/receipt atomically in owner lock order. Chunked batch≤100 roots uses stable mapping; dependent roots remain hidden until their required mappings commit. Final visibility marks the complete imported subtree; failed partial import is a visible resumable job, not a successful empty workspace. Cancel stops new roots and retains already committed content with receipts. Retry resumes exact target IDs; never duplicate source content.

Job states and paged mappings/issues are in wire 04. Each receipt records source hash/new ID/new revision/fidelity. Source stays unchanged even on success. Transfer package downloads expire after 24 hours unless renewed by current owner policy; bytes follow explicit export retention. A user may export again with a new snapshot/ID. Missing mandatory blobs blocks import; if all backup/source copies are lost, data-health outcome is irrecoverable. Preserve metadata/evidence and offer export of remaining data or explicit replacement/deletion. Never label missing bytes repaired.
