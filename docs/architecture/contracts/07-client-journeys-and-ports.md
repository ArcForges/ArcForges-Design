# Client Journeys, Owner Ports and Recovery

Authority: P2-010; [numbered wire registry](04-protobuf-wire-registry.md) owns exact fields, [operation catalogue](00-operation-catalogue.md) owns errors/replay, [security](../08-security-architecture.md) owns authentication and grants. These are complete bindings for existing product behavior, not parallel APIs. Every normal business operation is generated proto; the listed auth/file/CF/provider exceptions are closed standard protocols. UI text may be localized without changing the behavior.

## 1. Identity and session paths

`AuthFlow` is server-owned: flowId, realm, purpose, method/provider, installation claim, originating browser Origin/RP when applicable, recoveryGeneration, issuedAt/expiresAt, challenge hash, attempt count, proof-consumed state and limited credential replacement challenge. A flow is not a user session. Begin is anonymous/rate-limited/no-store and reveals no account existence. Maximum5 proof attempts; email flow10minutes, OIDC receipt60seconds, local enrollment grant15minutes. Native/Browser result shaping cannot be selected by a spoofed body flag: the listener/edge profile fixes it.

| Journey | Exact sequence and owner commit | Failure / client outcome |
|---|---|---|
| Official account creation | identity.beginAuthentication(purpose=enroll,method=email,installation,loginHint) → requestEmailCode(same flow) → completeEnrollment(email proof, profile, optional passkey credential made against the flow creation challenge). Identity+Workspace+Device+Entitlement configured initial grants+Notification commit together. | Used/expired proof never replays a session; fresh authentication recovers a successfully created account. No duplicate workspace or initial grant. Email-only account remains usable and can add passkey after login. |
| Email login | beginAuthentication(authenticate,email,installation,hint) → requestEmailCode(same flow) → redeemEmailCode or completeAuthentication, not both. Success issues NativeSession or cookie-only SessionView. | Bad/unknown account proof has the same bounded denial shape. Email retry references the current challenge intent; unknown provider delivery never authorizes duplicate account creation. |
| Passkey login | beginAuthentication(authenticate,passkey,installation) returns RP/allowed credentials/challenge → platform assertion → completeAuthentication. | Validate challenge, origin/RP, UV, signature, credential binding and replay. Unsupported platform offers another enabled method, never a weaker fake passkey. |
| Add/remove/rename passkey | Fresh step-up when adding to an existing account → beginPasskeyRegistration → platform creation → completePasskeyRegistration; listAuthIdentities/renameAuthIdentity/removeAuthIdentity. | Complete is one-use proof consumption, not a generic replayable write. Removal cannot delete last usable credential/recovery route. Lost secret or proof response requires a new flow. |
| Self-host password enrollment | Operator CLI creates audited one-use local enrollment grant → beginAuthentication(enroll,password,installation) → completeEnrollment(localCode, password replacement, profile). | Official realm rejects password provider. Password hash/attempt/rate policy stays in security08. Grant possession cannot reset an existing account without a distinct recovery grant. |
| OIDC login/enrollment/link | beginAuthentication with configured provider → standard browser redirect → C# GET `/session/v1/providers/{providerId}/callback` verifies code/state/nonce/PKCE/issuer → one-use receipt → completeAuthentication or completeEnrollment. Linking to an existing account additionally uses fresh step-up and both authenticated identities. | Receipt bound to original flow/installation; exact configured redirects, no caller URL. Same email never merges accounts. Callback contains no IdP/access/refresh token for a client. |
| Recovery | beginRecovery with RecoveryMethod and email or self-host account hint → prove email/recovery code/registered passkey/audited administrator grant → completeRecovery with passkey or enabled local password replacement. Creation challenge is part of the recovery flow; old credentials never supply a replacement public key without proof. | Commit consumes proof, invalidates recovery-code set, revokes sessions/PAT/device SSO and changes credential atomically. Returns receipt only; ordinary login follows. No security question or email requirement for a non-email realm. |
| Step-up | beginStepUp(operationClass,method,targetHash) → completeStepUp(proof) → target operation carries returned evidence through declared authenticated metadata. | Evidence binds actor/session/generation/class/hash,≤5minutes and one sensitive action. A different proposal or session cannot reuse it. Biometric app unlock is not this proof. |
| Refresh | Native only identity.refreshSession, single-flight per installation; atomic spent-token record and replacement. | Old token reuse revokes family. Lost rotation response requires login; never repeat old refresh automatically. Browser cookie uses its own12hour/30minute lifecycle, not refresh tokens. |
| Session/device logout | revokeSession/revokeAllSessions, device.signOut or device.revoke; locally invalidate generation before callbacks. | Offline logout clears local credentials immediately and records best-effort revocation for a later same-owner session. Device revocation also removes trust/remote authority/push, signOut retains registration. Pending work is quarantined, not silently transferred. |
| Email/profile/recovery codes/PAT | Existing profile/email-change/credential/recovery-code/PAT operations, exact step-up and one-show secrets. | Lost PAT/recovery code display never fetches plaintext later. Generate replacement invalidates prior codes; PAT replay returns safe summary only. |
| Account deletion/cancel | Preview requirements and fresh step-up → requestAccountDeletion; grace access uses fresh purpose=cancelDeletion only → get/cancelAccountDeletion. | Old ordinary sessions remain revoked after cancel; fresh login needed. Grace session cannot query ordinary content or spend credits. Paid subscription cancellation remains a separate explicit operation. |

RecoveryMethod is emailCode/recoveryCode/passkey/adminGrant. Account hints identify a configured realm account without treating email as universal authority. Administrator CLI creates a hashed scoped grant through the audited Identity application service, not direct password/DB edits. It never prints existing credentials.

Browser standard-auth mappings under `/session/v1` are: GET bootstrap; POST authentication/begin, authentication/complete, enrollment/complete, recovery/begin, recovery/complete, step-up/begin, step-up/complete and logout; GET providers/{providerId}/callback for OIDC only. Request fields mirror their exact numbered Identity records as JSON precise-value projections. Response uses AuthChallenge, StepUpEvidence, Receipt or SessionView with Set-Cookie, never NativeSession. Pre-auth Origin+CSRF flow applies to every POST, authenticated CSRF applies after login, all responses no-store. Credential/profile/email/PAT management remains ordinary cookie-auth gRPC-Web with safe secret-display rules. C# adapters call the same handlers/transactions. No unspecified `/auth/*` endpoint is needed.

Local device SSO uses `IDeviceSsoBroker.GetEligibleAccounts` and `SignChallenge` on the private DesktopPlatform local.security service. Safe eligible account summaries carry source installation/product/account display identity, never tokens. The target asks Cloud identity.beginDeviceSso with its InstallationClaim; selected source broker verifies OS peer product/installation/signature and signs the exact server challenge. identity.completeDeviceSso consumes it and creates a distinct target session. The source session/device must remain current at completion. Broker is available through any installed authorized Arc app, not only ArcChat. No eligible source means ordinary login. This native desktop facility is absent from browser/Android remote companion.

## 2. ChatTurn and AgentTask

| Trigger | Durable owner and path | Completion / recovery |
|---|---|---|
| Plain append without generation | chat.appendMessage with no TurnOptions | One user message commit, no model/admission or Task. |
| Ordinary generated reply | TurnOptions ordinary + caller turnId; Chat owns ChatTurn, Resource pins and shared Entitlement/Commerce admission | Sole RunWorkflow uses ExecutionOwner.turnId. chat.getTurn plus canonical conversation reconciles. Read-only tools only; output commits once. |
| Agent mode | TurnOptions agent + caller taskId or task.create | Task owns plan/steps/attempts/approvals. task.get/getDetails reconcile; ordinary Task policies apply. |
| Write proposed in ordinary mode | Store TurnPromotionPreview; return waiting reason promotion.required; no write tool dispatch | Explicit chat.promoteTurn creates one linked AgentTask at matching preview/revision. It still requires ordinary approval/authorization. Decline/cancel leaves a read-only completed/interrupted reply, never a hidden effect. |
| Temporary reply | ChatTurn with temporary conversation; no ordinary history/list/knowledge projection | Body only in bounded encrypted transient execution storage,≤24hours absolute; explicit close cancels and purges text within1hour. Client temporary drafts and compaction summaries are volatile. Crash can interrupt temporary work; metadata-only financial/security receipt survives. |
| Save temporary content | Explicit saveTemporary with new conversation ID and selected current authorized messages | Creates new durable content with origin; no execution/charge identity is copied or re-run. Missing/expired temporary content refuses, never fabricated. |
| Cancel/pause/retry | cancelTurn for ordinary/temporary; existing Task controls for agents | Control requested/acknowledged is separate from outcome. Known completed usage settles normally; uncertain dispatch is reconciled, not treated as zero or repeated. |

CF uses the same RunWorkflow, InferenceWorkflow, RunStream and fenced C# owner ports for both owner kinds. `ExecutionOwner` replaces Task-only identity in execution lease/command, provider attempt, stream and owner output/admission receipts. A compatibility taskId is present only when that owner really is a Task. ToolProposal/ToolRequest carries executionOwner; a pure read under ChatTurn uses ordinary grant checks and no forged Task. A write requires actual AgentTask. There is no second AI planner or Node sidecar.

Temporary source/output blobs and chunks are encrypted, purpose-scoped and excluded from backup/history/search/export. CF step input/return stores only reference IDs and metadata, never prompt/output/summary plaintext. Temporary compaction summary exists only within the active Worker step; loss before the next model dispatch is context.interrupted, no automatic duplicate compaction. Business/financial audit retains IDs/hashes/counts/reasons under normal retention, not content. UI states that the model received data; temporary is not a claim of zero provider processing.

Ordinary compaction is operator-funded and keyed by exact input snapshot. Protected system/safety/opening/correction/refusal spans are preserved verbatim and in order. Pack them first then newest complete turns within the model's pinned budget. If they cannot fit, stop with context.protected_overflow (state.invalid_transition reason) and offer an explicit new-conversation handoff. No hard truncation of protected text. Summary is derived untrusted context and cannot overwrite user/system authority.

## 3. Source consent and Web search

Cloud knowledge projection requires its existing permanent source policy. Explicit per-turn local input is a different route: user selects immutable bytes/range, sees purpose/size/egress, source.createConsent records actor/workspace/operation/source versions/policy revision/maximum bytes and15minute expiry. Upload uses Resource purpose=transientInput and the normal verified/hash/owner pin lifecycle; unconsumed transient bytes expire within24hours, consumed bytes when the declared owner retention/pins end. It neither enrolls sync nor indexes knowledge. Permission/revoke/generation is rechecked when consumed; a stale context needs a new snapshot/consent. One-time permission can only narrow the explicitly accepted source override scope, never override credential/ownership/privacy prohibition.

First-party capability `web.search.v1` binds WebSearchRequest/Result to the AI Worker provider adapter, not a new public arbitrary-fetch endpoint. Use Brave `GET https://api.search.brave.com/res/v1/web/search`, server X-Subscription-Token, strict safe search, offset0, count1–10(default5), query1–512Unicode scalars, allowlisted language/country, timeout10seconds, response≤256KiB. Map ordered web results to rank/title/absolute http(s) URL/snippet≤2048scalars/fetchedAt/provider=braveWebV1; reject malformed URL/nonfinite/control data, strip HTML markup from display. No fetch of returned pages, redirect to user URLs, executable snippets or hidden local context in the query. Duplicate URLs normalize scheme/host/default port only and retain first rank.

Search requires explicit enabled Web-search choice and query egress disclosure. It is a pure-read tool with external cost; operator-funded supplier budget reserves a bounded one-request charge, and the normal model answer remains customer-metered. Known response releases/settles operator exposure; unknown acceptance stays supplier reconciliation, never automatic second paid request. Result unavailable/capacity/timeout is visible and the answer cannot invent citations. Provider account, contractual data terms, tariff snapshot/budget and real response test are WP43/52 gates. [Provider API](https://api-dashboard.search.brave.com/app/documentation/web-search) documents the transport; this review created no account or live request.

## 5. Realm transfer and data health

`realm-transfer.v1` closes the accepted export-then-import migration. It is service owner-data interchange, distinct from the ordinary Markdown/Chat-JSON user export and not a native editable Notes file or a sync authority shared between realms. It cannot be substituted for an independent disaster backup.

Included roots: current Notes notebook/folder/document blocks/inline/property definitions/options/values/saved views; Chat projects/conversations/branches/messages/memory/artifact references; synced Scope sessions/capture manifests/analysis/reports and Slate project/sequence/asset metadata; managed blobs referenced by included roots. Source provenance, revision, exact values and hashes are included. Historic Task results may appear as inert content summaries associated with messages/artifacts, never a runnable Task. External native files are explicit missing/external references unless uploaded with consent. Keep user content and its reference mapping; unsupported version/kind is an issue, never silently skipped.

Excluded authority: credentials/tokens/device trust/remote grants, payment/credits/service terms/quotas, active execution/leases/outboxes, runnable automation schedules, operator/security audit, policy and deletion tombstones. Export a manifest of exclusions and per-root fidelity; no source deletion. The receiving realm assigns new owner IDs and rewrites every internal reference using a recorded mapping. External links keep origin identity and show unresolved availability. It never imports a deleted source into an existing destination root or revives a source tombstone.

Transfer API requestExport or previewImport uses caller transferId and immutable manifest/body resource. Preview validates version/hash/license/source scope/root references and destination permission/quota, calculates complete mapping and issue list, freezes previewHash≤24hours. commitImport requires current previewHash/revision and each accepted omission code. Quota is rechecked per commit; actual unsupported mandatory fields block, optional explicitly acknowledged omissions yield partiallySucceeded. Import writes one bounded root and its mapped references/reservation/receipt atomically in owner lock order. Chunked batch≤100roots uses stable mapping; dependent roots remain hidden until their required mappings commit. Final visibility marks the complete imported subtree; failed partial import is a visible resumable job, not a successful empty workspace. Cancel stops new roots and retains already committed content with receipts. Retry resumes exact target IDs; never duplicate source content.

Job states and paged mappings/issues are in wire04. Each receipt records source hash/new ID/new revision/fidelity. Source stays unchanged even on success. Transfer package downloads expire after24hours unless renewed by current owner policy; bytes follow explicit export retention. A user may export again with a new snapshot/ID. Missing mandatory blobs blocks import; if all backup/source copies are lost, data-health outcome is irrecoverable. Preserve metadata/evidence and offer export of remaining data or explicit replacement/deletion. Never label missing bytes repaired.
