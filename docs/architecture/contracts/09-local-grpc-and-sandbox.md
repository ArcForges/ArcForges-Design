# Local gRPC, Peer Bootstrap and Restricted Helper Profile

> Status: **Authoritative** — Phase 2; P2-011
> Scope: parent-owned parser/extension/connector children only under P2-012. Ordinary application operations are in-process; remote control uses the Cloud bridge.

## 1. Closed transport and ownership map

| Path | Contract / endpoint owner | Transport and authority |
|---|---|---|
| Product UI/assistant → own application handler | Generated typed product records and static delegates | In-process only; no local product service or discovery. |
| Native sign-in and connector broker | Each application uses its own Cloud session; standard system-browser/OS authentication may reuse existing login state | No cross-product DeviceSsoBroker endpoint. Connector children remain parent-restricted. |
| Local state hints | Application event subscription in process; LocalEventsService only for admitted child boundaries | Bounded listeners and authoritative reread, no product network endpoint. |
| Executable extension ↔ host | Public ExtensionHostService descriptors | Same native gRPC on restricted launch-bound streams. Host receives Handshake/RenewLease and approved host-capability Invoke; extension receives Invoke for its admitted contributions and Stop. Each direction registers only its role's methods; wrong-direction call refuses. |
| Parent → ContentSandbox | Internal ContentSandboxService | Native gRPC over parent-provisioned Named Pipe/Unix stream, restricted launch identity. All parser/control results use proto. No XPC application command, JSON-RPC or custom framed control remains. |
| Shared-buffer/input provisioning | OS launcher and buffer owner only | Inherited/duplicated descriptors are OS resources, not RPC messages. The closed provisioning rule in §4 is the only handle sideband. All session/grant/seal/ack/cancel operations are gRPC. |
| Same-process C#/C ABI | Selected native library in its owning process/helper | Direct C ABI; not a process protocol. Pointer layout never appears on gRPC. |
| External MCP, device and provider adapters | Existing named owner adapters | Preserve their standardized stdio/HTTP/device protocols. They are not first-party control channels or a fallback local business protocol. |

No local business/helper listener binds TCP, loopback or a public interface. Mobile/Web never connect here. The dummy HTTP authority required by GrpcChannel is `http://arcforges.invalid`; ConnectCallback always returns the verified OS stream and never falls back to DNS/TCP. Do not enable client load balancing or GrpcChannel connectivity-state tracking on ConnectCallback channels. Observe actual call/connection/lease failures. [Microsoft's IPC support](https://learn.microsoft.com/en-us/aspnet/core/grpc/interprocess?view=aspnetcore-10.0) supports these transports and custom IConnectionListenerFactory; actual ArcForges AOT proof remains WP06/08/11-owned.

Contracts owns `internal/proto/arcforges/local/platform/v1` and `.../sandbox/v1`, generated as ArcForges.Contracts.LocalRpc.Platform and .Sandbox. Product-port records are in-process; only helper/extension transport packages import Platform bootstrap bindings where required. Public SDK extension schemas import neither package. DesktopPlatform ArcForges.LocalRpc implements transports; ContentSandbox.Contracts is a thin compatibility facade referencing .Sandbox, not a second DTO/generator authority. WP03 publishes all descriptors, methods, validation and independent fixtures before consumers. No internal local schema enters public NuGet/npm/Maven client closure.

## 2. Discovery, peer verification and bootstrap

Parent-owned helper listeners use HTTP/2 only. Windows uses asynchronous Named Pipes with explicit current-logon-user ACL, remote clients denied, no Everyone/anonymous access, and verifies actual client/server process through OS pipe APIs. Linux/macOS use a current-user private runtime directory0700/socket0600 with pathname<=100 UTF-8 bytes; Linux verifies SO_PEERCRED, macOS peer UID/PID and signed code identity. Never trust a wire PID, endpoint string or AppId. Compare live process start identity, executable identity and hash against the installed signed release manifest before accepting its application role. Linux uses the signed installed inventory and opened executable identity; absence of Authenticode is not absence of verification. Denied verification refuses, never same-user-only fallback.

Each parent writes a child EndpointManifest protobuf atomically only after its listener is ready: create a private temp file, flush, then rename under an owner-only runtime directory. The manifest is a discovery hint, not authority. Validate schema/size<=16KiB, instance ID and path prefix; reject symlink/reparse escapes. Endpoint names include a random instance ID; never take over a guessed shared name. Cleanup uses exclusive directory lock and exact manifest/instance identity. A connect failure alone cannot justify deleting a live peer's socket. Retire an endpoint only after proving its recorded process-start identity is no longer live and the entry still matches; otherwise ignore and report stale discovery. PID reuse does not match the old start identity. AppId/build/contracts claims must agree with the verified peer on connect.

For explicitly launched parent/child peers, complete generated LocalBootstrap.Challenge and Confirm on the **same verified HTTP/2 connection** before ordinary methods. Challenge carries the caller instance/manifest and32 random client bytes; reply carries challengeId,32 random server bytes, expiry<=5seconds and the verified server manifest. There is one outstanding challenge per connection. Confirm.proof is SHA256 of UTF-8 `arcforges.local.bootstrap.v1` followed by canonical16-byte challengeId, clientChallenge32, serverChallenge32, clientInstanceId16 and serverInstanceId16. This is transcript confirmation, not authentication by a self-asserted hash: OS/build verification and connection binding supply trust. Compare in constant time, consume once, and return random32-byte peerNonce plus an expiry30seconds ahead. Invalid, expired, repeated or cross-connection challenge refuses before dispatch. No secret goes in endpoint files, process arguments or logs.

Every ordinary call carries `x-af-peer-bin` (32-byte nonce), `x-af-instance-bin` (canonical16-byte caller instance) `x-af-contract-set` (descriptor-set SHA256), and `x-af-call-bin` (serialized LocalCallContext, <=4KiB). These bind to the actual accepted transport connection, its server instance and allowed role. The contract-set hash identifies the caller's verified descriptor inventory, not a requirement that caller and server hashes be identical. Admit each requested service major and operation through WP03's compiled compatibility manifest; a common numeric major alone does not authorize an absent/incompatible service. Compatible additive differences retain the catalogue window; unsupported calls refuse before dispatch. Service adapters propagate validated actor/correlation, never caller-asserted privilege. LocalBootstrap.Renew authenticates that connection, rechecks current process/role and extends peer expiry by30seconds; renew every10seconds, independently of Cloud application presence. Lease lapse denies new calls. HubRegistry.RenewLease renews routing only; it cannot mint a peer credential. Reverse channels have independent OS verification/bootstrap/nonce. application runtime absence does not prevent direct product or SSO use.

The generated interceptor decodes exactly one LocalCallContext; duplicate/malformed metadata refuses before dispatch. RequestMeta remains the sole correlation/command/workspace/recovery envelope. Product business calls require actor; infrastructure may omit it and is then limited to the authenticated connection/launch role. The scope roots (max32) narrow the request, never grant them; collection queries with no named roots are still filtered by the owner. FrozenContext.actor and Invocation invocation/approval/lease fields, where present, must agree with the header. A decoder/forwarder preserves the original actor, invocation and execution owner across the typed product call; it cannot relabel an agent/automation/extension as human. An extension/helper launch fixes its role at the receiver regardless of supplied metadata. A verified first-party UI adapter may originate a human context only from its current local/account identity; foreground presence and step-up still require owner-verified evidence.

ApprovalId, leaseId and delegationId are opaque record references, not signed permission tokens or caller assertions of success. The receiving owner resolves its local grant/approval state, checks the exact command/proposal hash, actor, resource version, lifetime and revocation before effect. A Cloud ToolRequest/ApprovalView or another product's receipt is evidence for the owner's existing local approval flow; it never substitutes for that owner's permission/approval. Missing/unavailable authority refuses or enters the declared approval flow, never permissive cache fallback. A returned result cannot widen the context. Bootstrap and peer renewal do not require a business actor and cannot create one.

Use one HTTP/2 connection per authenticated channel (`EnableMultipleHttp2Connections=false`), no automatic RPC retries/hedging, no periodic pool recycling under a live lease. A new transport connection cannot reuse the old nonce: infrastructure creates a fresh channel, bootstraps and reconciles before owner calls. Never replay a mutation merely because gRPC reconnects. Queries may retry after fresh authorization; writes use the same CommandId and owner idempotency/unknown-effect rules. Reconnect backoff starts250ms, doubles to30seconds with full jitter, resets after a successful lease; explicit foreground retry may start immediately.

## 3. Bounds, event recovery and sensitive brokers

Ordinary request/response<=4MiB, default deadline10seconds (declared synchronous measurement<=30seconds),16 active calls and64 queued per peer. Reserve two separate control slots for bootstrap/renew/cancel/health so a saturated work lane cannot starve lease/cancellation. Refuse excess before dispatch. No domain lock held across peer calls; service dispatch never blocks the UI thread. Cancellation or timeout after a mutation was sent preserves unknown-effect semantics. Long jobs return an owned ProductJob, then GetJob/status; never extend the general unary deadline to run a render.

LocalEvents.Poll has limit default50/max128 and response<=256KiB. Each owner retains at most256 hints or60seconds, whichever bound is reached first, per authorized subscriber scope. Cursor is opaque, connection/instance/lease/actor/scope-bound with sequence; no global ordering. Missing/expired/disconnected cursor returns resetRequired and a new cursor. Caller re-reads capabilities/health/current context/resource or ProductJob state before continuing. Foreground polls at1second, background10seconds, exponential failure backoff up to30seconds. Hints are IDs only; duplicates coalesce by kind/target, loss has no business effect. This replaces unschematized local interface events; a transport callback is not required for correctness.

DeviceSsoBroker descriptors are future-only and never registered. ConnectorBroker uses existing Connector records, definition-hash-bound origins/scopes, consent, step-up and secret protection. Its Revision is an owner-local connection row revision, not a Cloud revision or sync root. List/Get are Q/R1/AO; Begin is CC/R3/FR; Complete NI/R3/FR, reconcile Get after a lost response; Revoke DE/R2/FR at expectedRev. Only the verified owning parent acting for its foreground human reaches connector child mutation/signing methods. Agent/automation/extension actors cannot consent or retrieve credentials. Local connector state and encrypted secret references remain with the owning product, never copied from Cloud.

## 4. Restricted launch and OS resources

ContentSandbox is the existing signed C# Native AOT helper. Windows uses a parent-created duplex Named Pipe stream; Linux/macOS use an already-connected Unix socket stream. The trusted launcher establishes streams and the finite resource inventory **before** entering the restrictive profile or invoking any parser. A custom Kestrel IConnectionListenerFactory accepts only these supplied streams and speaks ordinary HTTP/2 gRPC; Grpc.Net.Client uses the matching stream callback. No restricted child needs to create/connect a network socket or obtain a general product listener. Helpers receive only parent-to-helper RPC; a child cannot register as a product or call SSO. Extension bidirectional control uses a separately provisioned stream for each declared receiver direction.

Windows attaches the verified suspended child to its AppContainer/Job profile and supplies only the explicit pipe/input/mapping handles. Linux creates the socket/input/mapping descriptors before Landlock/seccomp/no-new-privs restrictions and closes every extra descriptor. macOS keeps a separately signed App-Sandbox helper; XPC may activate it and transfer the initial connected Unix stream and descriptor inventory once. **XPC carries no application request, result, callback, buffer grant or cancellation.** Subsequent control is gRPC over the supplied stream. The launch adapter is an OS-interop shim, not a second service implementation. [Apple descriptor transfer](https://developer.apple.com/documentation/xpc/xpc_dictionary_set_fd(_:_:_:)) does not itself prove the full sandbox/AOT profile; WP11's signed-artifact test must do that.

Inherited socket peer credentials can describe the creating parent, not the consuming child. Do not misidentify them as child PID evidence. For these launch-bound channels, trust derives from the parent's verified child process handle/start/code identity, exclusive descriptor handoff, restricted handle inheritance and one-use launch secret32bytes delivered in a private inherited bootstrap resource (never argv/environment). Confirm.proof uses HMAC-SHA256 with that secret over the §2 transcript; the launch context selects this mode before accepting bytes, so an untrusted normal peer cannot request it. Destroy the launch secret after confirmation. Only the exact child/parent pair can obtain the resulting connection credential; no discovery manifest is published for a restricted child.

For each invocation preallocate at most3 output slots, each<=64MiB, and the read-only immutable input descriptors. Input identity is parent-minted inputId plus exact length/SHA256. Transfer handles once through the OS launch allowlist (inheritance/duplication/SCM_RIGHTS or macOS descriptor handoff); a process cannot request arbitrary paths, handle numbers or a new mapping. Never interleave ancillary descriptor messages with HTTP/2. Replacing input/profile or expanding budgets requires a new invocation/launch. Output slots are inert storage, not RPC channels. Content controls reference only parent-minted IDs; all grant/seal/ack/cancel/status traffic is generated gRPC.

Slot state is free→writing→sealed→reading→free. Parent grants(slotId, nextSequence, capacity), helper may fill only that grant; returned SandboxBufferDescriptor seals that exact invocation/lease/generation/sequence. Parent checks bounds, geometry/stride, format and nonoverlapping coverage. Because a hostile child can still write a shared mapping, copy the declared bytes into a privately owned bounded parent buffer and verify the digest on that copy before using it. Never parse/use memory that the child can race after verification. At most one64MiB copy per active helper is admitted in addition to the three mappings; full-frame reconstruction has its separately admitted memory budget. Parent acknowledges the matching copied digest before reuse. Duplicate identical ack succeeds; stale/different sequence refuses. No slot can be silently recycled on seek/cancel; invalidate outstanding frame IDs and wait for their disposition or terminate the invocation.

## 5. Helper operation semantics

All numbered ContentSandboxService methods in registry04 are internal peer-infrastructure, R1, no user approval by themselves, FR compatibility, same-machine parent/child only. Their caller must already hold the owning product's resource/source authorization. Session/grant/close/cancel are IW on their parent-minted IDs and sequence; queries and non-consuming copy/probe are Q. ReadMediaFrame advances a reader: CommandId and a per-reader command receipt retain the returned frame until acknowledged/released, so a lost reply never skips a frame on same-command retry. One unresolved read receipt per reader is retained until frame release; subsequent consuming reads wait for that disposition. Released command IDs remain bounded tombstones for the session; a receipt evicted at the256-entry limit refuses an older sequence instead of advancing the reader. Commands carry the expected monotonic read sequence in their helper request. Open methods are CC with parent-supplied reader/document ID; mismatch on repeated ID refuses. No helper result commits product state.

OpenSession verifies launch invocation/input/slot inventory and limits, chooses only parser libraries from the signed helper profile, and returns an invocation-scoped session. No arbitrary library path/function selector. Use native06 limits and numeric keys; caller cannot raise the launch budget. Session lease30seconds renewed10seconds; Expired→closed and process termination. Active parser deadline comes from admitted limits and cannot extend the session after parent death. Cancellation uses a reserved control slot and native cancellation token, then5second forced termination if unresponsive; pipe closure/parent death triggers OS tree cleanup. Lost child state returns resource.parser_failed, discards frame IDs and slot leases, and the owner may reopen the immutable input under a new invocation without retrying a product mutation.

ProbeMedia/OpenMediaReader/ReadMediaFrame/SeekMedia and CopyVideoFrame/CopyAudioFrame map to the corresponding native media functions; reader/frame IDs are random mapped RPC IDs, never the native uint64 token. EOF is an explicit result. Seek requires the current reader sequence and completed disposition of its outstanding frame/slot, then discards old decoder generation and returns the next monotonic read sequence (never reset on seek). A same-command seek returns its retained receipt without repositioning a reader again; stale/evicted commands refuse by sequence. CloseFrame/CloseReader are idempotent at the RPC level while the native close remains single-owner. Probe metadata is decoded inside the helper into the typed records; native private JSON never becomes a generic protobuf Bytes business payload.

OpenImage/GetImageInfo/ReadImageTile and OpenPdf/GetPdfPage/ExtractPdfText/RenderPdfTile use the fixed image/PDF profiles. ReadImageTile/RenderPdfTile/Copy* require a parent slot grant and return a seal descriptor, not bulk pixel bytes. PDF page and text positions are zero-based; text is<=64KiB per call with next UTF16 position; geometry uses finite points and boxed UTF16 ranges. Text extraction truncation is always explicit pagination. The helper converts native scalar-based positions to the wire UTF16 offsets with a bounded page index; start must be0 or a previously returned next position for that page/session. It cuts both text and box coverage before either response bound, preserves surrogate boundaries and makes progress, otherwise returns resource.parser_failed. RenderPdfTile page geometry must match GetPdfPage and requested dimensions/region must fit the admitted output; reject mismatched geometry rather than infer scaling from untrusted fields. Image dimensions/types/metadata are bounded before allocation. CloseImage/ClosePdf remove the session mapping idempotently. PDF script/actions stay disabled. Encode/write paths receiving only validated parent-owned pixels can remain in the product process under native06; hostile format parsing cannot.

ReadOtio/WriteOtio consume the parent-brokered input (OTIO bytes or the exact canonical slate.project.v1 projection). They run the selected official codec and produce an immutable bounded result read through OtioReadChunk(offset,length<=64KiB), returning the existing proto LocalChunk bytes/hash envelope; the receiver validates total length/hash and the existing typed Slate/fidelity schema. The RPC controls and per-chunk envelope are proto; an OTIO file remains an OTIO file. External media paths stay inert and require subsequent owner relink consent. No helper follows arbitrary external references. Final import/export commit remains the product's validated command.
