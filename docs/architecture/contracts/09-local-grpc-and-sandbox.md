# Private Child gRPC and Restricted Helper Profile

> Status: **Authoritative** — Phase 2; [P2-011](../../decisions/phase-2-specification-decisions.md#rule-p2-011)
> Scope: parent-owned parser/extension/connector children only under [P2-012](../../decisions/phase-2-specification-decisions.md#rule-p2-012). Ordinary application operations are in-process; remote control uses the Cloud bridge.

## 1. Closed transport and ownership map

| Path | Contract / endpoint owner | Transport and authority |
|---|---|---|
| Product UI/assistant → own application handler | Generated typed product records and static delegates | In-process only; no local product service or discovery. |
| Native sign-in and connector broker | Each application uses its own Cloud session; standard system-browser/OS authentication may reuse existing login state | No cross-product DeviceSsoBroker endpoint. Connector children remain parent-restricted. |
| Local state hints | Application event subscription in process; LocalEventsService only for admitted child boundaries | Bounded listeners and authoritative reread, no product network endpoint. |
| Executable extension ↔ host | Public ExtensionHostService descriptors | Same native gRPC on restricted launch-bound streams. Host receives Handshake/RenewLease and approved host-capability Invoke; extension receives Invoke for its admitted contributions and Stop. Each direction registers only its role's methods; wrong-direction call refuses. |
| Parent → ContentSandbox | Internal ContentSandboxService | Native gRPC over parent-provisioned Named Pipe/Unix stream, restricted launch identity. All parser/control results use proto. No platform IPC side channel (XPC or equivalent) may carry application requests, results, callbacks, buffer grants or cancellation; no JSON-RPC or custom framed control remains. |
| Shared-buffer/input provisioning | OS launcher and buffer owner only | Inherited/duplicated descriptors are OS resources, not RPC messages. The closed provisioning rule in §4 is the only handle sideband. All session/grant/seal/ack/cancel operations are gRPC. |
| Same-process C#/C ABI | Selected native library in its owning process/helper | Direct C ABI; not a process protocol. Pointer layout never appears on gRPC. |
| External MCP, device and provider adapters | Existing named owner adapters | Preserve their standardized stdio/HTTP/device protocols. They are not first-party control channels or a fallback local business protocol. |

No local business/helper listener binds TCP, loopback or a public interface. Mobile/Web never connect here. The dummy HTTP authority required by GrpcChannel is `http://arcforges.invalid`; ConnectCallback always returns the verified OS stream and never falls back to DNS/TCP. Do not enable client load balancing or GrpcChannel connectivity-state tracking on ConnectCallback channels. Observe actual call/connection/lease failures. [Microsoft's IPC support](https://learn.microsoft.com/en-us/aspnet/core/grpc/interprocess?view=aspnetcore-10.0) supports these transports and custom IConnectionListenerFactory; actual ArcForges AOT proof remains WP06/08/11-owned.

Contracts owns `internal/proto/arcforges/local/platform/v1` and `.../sandbox/v1`, generated as ArcForges.Contracts.LocalRpc.Platform and .Sandbox. Product-port records are in-process; only helper/extension transport packages import Platform bootstrap bindings where required. Public SDK extension schemas import neither package. DesktopPlatform ArcForges.LocalRpc implements transports; ContentSandbox.Contracts is a thin compatibility facade referencing .Sandbox, not a second DTO/generator authority. WP03 publishes all descriptors, methods, validation and independent fixtures before consumers. No internal local schema enters the public NuGet client closure.

## 2. Launch verification and bootstrap

There is no peer discovery, shared socket directory, published EndpointManifest or product listener. The parent launches exactly one of these child kinds, supplies connected streams and verifies the process handle/start identity and installed signed inventory before dispatch. Installation manifests authenticate executable bytes; wire claims cannot authenticate a process.

| Child kind | Exposed services and identity |
|---|---|
| ContentSandbox | ContentSandboxService and LocalBootstrap; exact first-party signed helper, parser profile and invocation. |
| Executable extension | ExtensionHostService and LocalBootstrap, plus explicitly granted LocalEvents/ResourceAccess methods; verified package digest/publisher, admitted extension role, never a first-party product identity. |
| Connector | Owned connector adapter child and LocalBootstrap; ConnectorBroker methods for its exact parent. An external MCP subprocess uses standardized MCP stdio behind this adapter, never an invented ArcForges gRPC server. |

§4 supplies Windows Named Pipe or connected Unix streams without TCP. Both directions of an extension use separately provisioned streams. The parent hands the child a one-use 32-byte secret in a private inherited bootstrap resource, never argv/environment/files. LocalBootstrap.Challenge sends the launch manifest, instanceId and 32 random client bytes; response has challengeId, 32 server bytes, expiry ≤5 seconds and the launch-bound server manifest. Confirm.proof is HMAC-SHA256(secret, UTF-8 `arcforges.local.bootstrap.v1` || challenge UUID bytes || client bytes || server bytes || client instance UUID || server instance UUID). Compare constant-time, consume once on that same connection and destroy the secret. Return a random 32-byte nonce valid 30 seconds. §4's inherited-descriptor identity caveat applies to every child. No unauthenticated SHA-only mode exists.

Every ordinary call supplies x-af-peer-bin (nonce), x-af-instance-bin (16-byte caller UUID), x-af-contract-set (descriptor SHA256) and one x-af-call-bin (LocalCallContext ≤4 KiB). Validate the connection/launch role, installed descriptor compatibility, original actor, invocation, approval/grant and narrowed roots (max 32). Headers never create a human or product role. Approval/lease/delegation IDs resolve current owner records; unavailable authority refuses. RequestMeta remains the sole command/correlation/revision envelope.

Renew every 10 seconds extends the lease by 30 seconds after verifying the pair still lives. One HTTP/2 connection per channel, no hedging/automatic mutation replay and no periodic recycling. A broken stream relaunches/reconciles under a new launch identity; it never inherits the nonce or grants. Queries can retry after authorization; mutations preserve their command ID and uncertainty. Full-jitter reconnect starts 250 ms, doubles to 30 seconds. Parent death closes the channel and kills its process tree.

### Bootstrap operation authorization metadata

Challenge, Confirm and Renew use the launch-bootstrap-only profile: capability `null`, risk `R1`, approval `none`, stepUp/localPresence `false`, egress `none`, patEligible `false`, and scope class `private-helper`. The closed export uses `actorKinds: {"from":"verifiedLaunchProfile.actorKinds"}`, `launchRoles: {"from":"verifiedLaunchProfile.callerRoles"}` and `requireLaunchRole: true`, admitted only for these three bootstrap methods under `launch-bootstrap-only`. Actor kinds and transport direction are derived only from the exact verified OS launch-pair role and the declared child-kind/listener stream profile, never a human/customer identity or a new grant. Parent-to-ContentSandbox calls require the verified owning parent; extension directions use only their separately provisioned, explicitly declared receiver roles. There is no wildcard both-directions permission and no global child-to-parent bootstrap assumption. Challenge and Confirm are `NI` with one-use transcript semantics; Renew is `IW` only under the same-command/input, same-recorded-expiry rule below. All process, secret, nonce, connection and current live-pair guards remain required.

### Extension operation authorization metadata

The operation export for the public extension transport uses closed, source-bound profiles. This declaration describes the launch and capability checks above; it grants no additional customer authority. The `delegated-invocation` profile remains exclusive to `IExtensionHost.Invoke` on the private-helper surface with its launch-role check; the registered product-handler profile in [catalogue 02](02-local-rpc-operations.md#closed-in-process-authorization-profiles) is distinct and cannot inherit or bypass that launch authority.

| Methods | Authorization and retry profile |
|---|---|
| Handshake, RenewLease | Verified extension-child to its owning host only; capability `null`, risk `R1`, approval `none`, stepUp/localPresence `false`, egress `none`, patEligible `false`, actor kind `extension-child`; scope class `private-helper`, idempotency class `IW`. |
| Stop | Verified owning host to its admitted extension-child only; the same fixed fields as lifecycle maintenance above with actor kind `owning-parent`; scope class `private-helper`, idempotency class `IW`. |
| Invoke | `delegated-invocation`: capability derives from `admittedCapability.operationId`; risk, approval, stepUp, localPresence, egress and idempotency derive from the corresponding admitted descriptor fields, never a fixed low-risk default. `patEligible` is `false` on the launch-bound transport. Effective actor kinds are the intersection of the admitted descriptor, frozen original actor and current grant. Receiver direction is separately verified: host to admitted extension contribution, or extension-child to approved host capability. |

Lifecycle `IW` is a checked duplicate-command property, not authority to replay mutations automatically. The same command ID and canonical input return the same recorded result and lease expiry; a duplicate RenewLease never extends expiry again. A fresh renewal uses a new command ID while the verified pair remains live, at the existing renewal cadence. An expired or revoked pair cannot be revived or regranted. Duplicate Handshake can only return the identical immutable admitted binding; Stop is idempotently terminal. The launch, connection, nonce, direction and current-grant checks remain mandatory. Bootstrap Challenge/Confirm retain their one-use transcript semantics: their idempotency class is `NI`, with no automatic replay, and neither is classified as lifecycle `IW`. Bootstrap Renew is `IW` only while the verified launch pair is live: the same command ID and canonical input return the same recorded expiry without extending it again, and expiry/revocation requires a new verified launch rather than revival.

For delegated fields, the manifest export uses a closed expression object such as `{"from":"admittedCapability.risk"}` with its defining source profile. Only the named descriptor fields above are allowed; unknown expressions, absent descriptors, missing current grants and unclassified metadata fail validation. The actor intersection and receiver role checks are evaluated before invocation; a descriptor or wire claim never elevates an actor. Domain-owned `eng/operations/<domain>.json` exports aggregate into the operation-scope manifest without requiring pending unrelated operations to exist.

## 3. Bounds, event recovery and sensitive brokers

Ordinary request/response<=4 MiB, default deadline 10 seconds (declared synchronous measurement<=30 seconds),16 active calls and 64 queued per peer. Reserve two separate control slots for bootstrap/renew/cancel/health so a saturated work lane cannot starve lease/cancellation. Refuse excess before dispatch. No domain lock held across peer calls; service dispatch never blocks the UI thread. Cancellation or timeout after a mutation was sent preserves unknown-effect semantics. Long jobs return an owned ProductJob, then GetJob/status; never extend the general unary deadline to run a render.

LocalEvents.Poll has limit default 50/max 128 and response<=256 KiB. Each owner retains at most 256 hints or 60 seconds, whichever bound is reached first, per authorized subscriber scope. Cursor is opaque, connection/instance/lease/actor/scope-bound with sequence; no global ordering. Missing/expired/disconnected cursor returns resetRequired and a new cursor. Caller re-reads capabilities/health/current context/resource or ProductJob state before continuing. Foreground polls at 1 second, background 10 seconds, exponential failure backoff up to 30 seconds. Hints are IDs only; duplicates coalesce by kind/target, loss has no business effect. This replaces unschematized local interface events; a transport callback is not required for correctness.

DeviceSsoBroker descriptors are future-only and never registered. ConnectorBroker uses existing Connector records, definition-hash-bound origins/scopes, consent, step-up and secret protection. Its Revision is an owner-local connection row revision, not a Cloud revision or sync root. List/Get are Q/R1/AO; Begin is CC/R3/FR; Complete NI/R3/FR, reconcile Get after a lost response; Revoke DE/R2/FR at expectedRev. Only the verified owning parent acting for its foreground human reaches connector child mutation/signing methods. Agent/automation/extension actors cannot consent or retrieve credentials. Local connector state and encrypted secret references remain with the owning product, never copied from Cloud.

### Connector operation authorization metadata

All local ConnectorBroker methods require the verified owning-parent launch role acting for its human; mutation/signing methods require that human in the foreground. Effective `actorKinds` is `[human]`, capability is `null`, `patEligible` is `false`, and `localPresence` is `false` (foreground consent is not the separately defined local-presence gate). Agent, automation, extension and PAT actors cannot use these methods to consent, obtain or revoke credentials. Every method remains `private-helper`; no private endpoint becomes public.

| Methods | Risk / idempotency | Approval / step-up | Egress |
|---|---|---|---|
| ListDefinitions, ListConnections, GetConnection | `R1` / `Q` | `none` / `false` | `none`; bounded non-secret metadata only |
| BeginConnection | `R3` / `CC` | Foreground human consent bound to the exact definition hash, provider origins and scopes / `true` | Exact definition-hash-bound provider origins/scopes under the broker checks |
| CompleteConnection | `R3` / `NI` | The original valid foreground consent / `true` (validate the original still-valid step-up flow), one-use and origin/scope bound; no fresh authority inferred from callback metadata | Only the exact provider origins/scopes authorized by that original flow |
| RevokeConnection | `R2` / `DE` | Foreground human confirmation bound to `expectedRev` / `false`, unless stricter current owner policy requires step-up | Exact definition-hash-bound existing-provider revocation only, best effort after local invalidation |

Revoke contracts authority; it does not request new scopes or destinations. Local invalidation is final before the provider attempt and never waits for that attempt to succeed. Returned connection metadata never includes raw secrets. Consent/flow identity, expected revision, definition hash, origins/scopes, current grant and receiver direction remain mandatory checks, independently of the exported metadata. The egress values are the explicit operation-catalogue boundaries, not unrestricted outbound permission.

## 4. Restricted launch and OS resources

ContentSandbox is the existing signed C# Native AOT helper. Windows uses a parent-created duplex Named Pipe stream; Linux uses an already-connected Unix socket stream; macOS has no launch profile because it is out of scope ([P2-023](../../decisions/phase-2-specification-decisions.md#rule-p2-023)). The trusted launcher establishes streams and the finite resource inventory **before** entering the restrictive profile or invoking any parser. A custom Kestrel IConnectionListenerFactory accepts only these supplied streams and speaks ordinary HTTP/2 gRPC; Grpc.Net.Client uses the matching stream callback. No restricted child needs to create/connect a network socket or obtain a general product listener. Helpers receive only parent-to-helper RPC; a child cannot register as a product or call SSO. Extension bidirectional control uses a separately provisioned stream for each declared receiver direction.

Windows attaches the verified suspended child to its AppContainer/Job profile and supplies only the explicit pipe/input/mapping handles. Linux creates the socket/input/mapping descriptors before Landlock/seccomp/no-new-privs restrictions and closes every extra descriptor. There is no macOS launch profile, App-Sandbox helper, XPC adapter or Keychain adapter, because macOS is out of scope ([P2-023](../../decisions/phase-2-specification-decisions.md#rule-p2-023)). Shared Unix-socket launch code stays for Linux, whose opt-in runtime checks run in WSL2 ([P2-024](../../decisions/phase-2-specification-decisions.md#rule-p2-024)). No platform IPC side channel (XPC or equivalent) may carry application requests, results, callbacks, buffer grants or cancellation; subsequent control is gRPC over the supplied stream.

Inherited socket peer credentials can describe the creating parent, not the consuming child. Do not misidentify them as child PID evidence. For these launch-bound channels, trust derives from the parent's verified child process handle/start/code identity, exclusive descriptor handoff, restricted handle inheritance and one-use launch secret 32 bytes delivered in a private inherited bootstrap resource (never argv/environment). Confirm.proof always uses HMAC-SHA256 with that secret over the §2 transcript; no normal-peer bootstrap mode is admitted. Destroy the launch secret after confirmation. Only the exact child/parent pair can obtain the resulting connection credential; no discovery manifest is published for a restricted child.

For each invocation preallocate at most 3 output slots, each<=64 MiB, and the read-only immutable input descriptors. Input identity is parent-minted inputId plus exact length/SHA256. Transfer handles once through the OS launch allowlist (inheritance/duplication/SCM_RIGHTS); a process cannot request arbitrary paths, handle numbers or a new mapping. Never interleave ancillary descriptor messages with HTTP/2. Replacing input/profile or expanding budgets requires a new invocation/launch. Output slots are inert storage, not RPC channels. Content controls reference only parent-minted IDs; all grant/seal/ack/cancel/status traffic is generated gRPC.

Slot state is free→writing→sealed→reading→free. Parent grants(slotId, nextSequence, capacity), helper may fill only that grant; returned SandboxBufferDescriptor seals that exact invocation/lease/generation/sequence. Parent checks bounds, geometry/stride, format and nonoverlapping coverage. Because a hostile child can still write a shared mapping, copy the declared bytes into a privately owned bounded parent buffer and verify the digest on that copy before using it. Never parse/use memory that the child can race after verification. At most one 64 MiB copy per active helper is admitted in addition to the three mappings; full-frame reconstruction has its separately admitted memory budget. Parent acknowledges the matching copied digest before reuse. Duplicate identical ack succeeds; stale/different sequence refuses. No slot can be silently recycled on seek/cancel; invalidate outstanding frame IDs and wait for their disposition or terminate the invocation.

## 5. Helper operation semantics

All numbered ContentSandboxService methods in registry 04 are internal peer-infrastructure, R1, no user approval by themselves, FR compatibility, same-machine parent/child only. Their caller must already hold the owning product's resource/source authorization. Session/grant/close/cancel are IW on their parent-minted IDs and sequence; queries and non-consuming copy/probe are Q. Open methods are CC with parent-supplied image/document ID; mismatch on repeated ID refuses. No helper result commits product state.

OpenSession verifies launch invocation/input/slot inventory and limits, chooses only parser libraries from the signed helper profile, and returns an invocation-scoped session. No arbitrary library path/function selector. Use native06 limits and numeric keys; caller cannot raise the launch budget. Session lease 30 seconds renewed 10 seconds; Expired→closed and process termination. Active parser deadline comes from admitted limits and cannot extend the session after parent death. Cancellation uses a reserved control slot and native cancellation token, then 5 second forced termination if unresponsive; pipe closure/parent death triggers OS tree cleanup. Lost child state returns resource.parser_failed, discards frame IDs and slot leases, and the owner may reopen the immutable input under a new invocation without retrying a product mutation.

OpenImage/GetImageInfo/ReadImageTile use the fixed image profile. The five PDF methods are published but retired ([P2-022](../../decisions/phase-2-specification-decisions.md#rule-p2-022)) and are answered with the closed retired refusal; no PDF profile runs. ReadImageTile/Copy* require a parent slot grant and return a seal descriptor, not bulk pixel bytes. The PDF text, page-geometry and UTF-16 position rules are retired with the PDF methods (P2-022), and no PDF helper parser runs. Image dimensions/types/metadata are bounded before allocation. CloseImage removes the session mapping idempotently (ClosePdf is retired). Encode/write paths receiving only validated parent-owned pixels can remain in the product process under native06; hostile format parsing cannot.
