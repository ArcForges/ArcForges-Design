# Cloudflare Execution and Object Integration

> Authoritative under P2-009. Contracts repository owns internal HTTP schemas in internal/ai-http/v1/schema.json (AGPL); public AI/object presentation schemas in public/http/v1/schema.json (Apache). This document fixes their semantics. PostgreSQL remains business authority; CF checkpoints and streams are disposable execution/projection state.

## 1. Deployment and authority

One ArcForges-AI Worker deployment exports the HTTP router, RunWorkflow, fixed-stage InferenceWorkflow and object-verification Workflow, and RunStream Durable Object. Use the platform Workflow class for the only model/tool loop; use a plain DurableObject with WebSocket hibernation for connection coordination and the bounded tail. No Agents SDK default chat loop, automatic tool execution, Node sidecar, D1/KV business store or second agent service. Direct env.AI.run invokes selected Workers AI models. Object routes in this same deployment use separate bindings/handlers and do not enter the AI loop or require AI credits.

| Record | Authority and store | Constraint |
|---|---|---|
| Task/Run/Step/Attempt, approvals, occurrences, tool requests/results | C# Task module / PostgreSQL | Existing state vocabulary and owner transactions; client never writes CF checkpoints |
| Conversation, immutable iteration output, final message | C# Chat/Task ports / PostgreSQL and verified Resource bodies | Output before settlement; final Task/message/Sync atomic |
| Admission, policy head, usage/settlement | C# Entitlement/Commerce/Agent/Configuration | No CF customer ledger or client-computed allowance |
| Execution lease | task.execution_lease / PostgreSQL | PK run_id; holder workflow_id, worker_version, epoch bigint, expires_at, recovery_generation; monotonic epoch under row lock |
| Workflow checkpoint | CF Workflow storage | Only IDs, ordinal, receipt hashes, wait handles and selected version; <128 KiB per step result |
| Stream projection | RunStream DO SQLite | Key realm/workspace/run; stream ID per provider attempt; no shared global object |
| Objects and multipart bytes | R2 private buckets | Resource metadata/permissions/quotas stay C#; separate immutable backup copy below |
| Model attempt dispatch marker | commerce.provider_attempt plus task.execution_command | Durable intent before external I/O; no absent-result inference |

Add task.execution_command(command_id PK, run_id, epoch, operation, request_sha256, state, result_ref, created_at), unique(run_id, operation, command_id); task.run carries workflow_id, worker_version, recovery_generation, last_iteration_receipt. task.execution_lease has one current holder. Intent/output transactions lock the existing Task/Commerce records in [SU-04](../data-model/00-data-model-overview.md#rule-su-04) order. C# outbox run.dispatch carries run_id and required_worker_version; duplicate delivery creates/gets the same CF workflow ID af-<run UUID>-<recovery_generation>. Workflow creation acknowledgement is not Task completion.

## 2. HTTP framing and authentication

All routes HTTPS. JSON uses the precise-value registry: int64/uint64 and Decimal as canonical strings, bytes as unpadded base64url, IDs lowercase canonical UUID; typed object schemas are closed for requests. Application envelope is {version:"1", requestId:Id, correlationId:Id, workspaceId:Id?, body:<route-specific record>}. Responses {requestId, result:<typed record>} or {requestId,error:ArcError}, never both. Max body 256 KiB; large content uses authorized ResourceRef. Unknown versions fail validation. Query/list and idempotent commit HTTP requests use 10-second deadlines; retry idempotent infrastructure receipts with exponential jitter 1/2/4/8 seconds up to30 seconds, then suspend/reconcile.

Private routes carry X-AF-Key-Id, X-AF-Time (UTC epoch seconds), X-AF-Nonce (128 random bits), X-AF-Request-Id and X-AF-Signature. Signature = base64url HMAC-SHA256 of UTF-8 lines METHOD, exact encoded path+query, time, nonce, requestId, hex SHA256(body), with LF separators and no trailing LF. Direction-specific 256-bit secrets, audience route allowlist and deployment realm pinned at each endpoint. Verify signature constant-time and time skew <=60 seconds before parsing; bind peer through TLS and an ingress allowlist. Nonces stored for 120 seconds; exact retry returns recorded response, changed-body reuse refuses. Private endpoints are not browser CORS routes and accept no client-supplied effective actor. Current/previous key overlap15 minutes, purge previous afterwards; restore rotates both.

C# validates a forwarded native bearer or origin-bound browser cookie through identity.authorize; CF does not cache a grant for future business effects. Cookie never reaches JavaScript. Browser /ai/v1 and /objects/v1 stay on the exact Account/Chat origin; gateway routing sends those paths to Worker and /rpc, /session, /webhooks to C#. Unsafe cookie calls require X-AF-CSRF and exact Origin. POST /ai/v1/connect validates browser cookie/CSRF/Origin or native bearer and returns a one-use connection nonce. WebSocket upgrade checks exact Origin for browsers; its first application frame is {kind:authenticate, connectionNonce, taskId}, <=4096 bytes within five seconds. Until validation no content is delivered; any other frame closes the socket. Nonce expires in30 seconds and is consumed once at binding. Neither bearer nor nonce is put in URL/subprotocol/log.

identity.authorize checks current user, workspace, session, device/installation, absolute/idle expiry, resource/Task permission, policy head and recovery_generation. Passive streams never renew session idle expiry. Authorization is checked before each live frame and every object range/part. A revocation prevents further frame/range authorization; bytes released before the revocation commit cannot be recalled. Durable revocation outbox closes matching connections promptly, but a lost notification cannot bypass the next live check. If C# cannot validate, CF stops delivery and new effects; no stale positive cache. Existing accepted in-flight effects use the cancellation/unknown-effect rules.

The additional late receipt port POST /internal/ai/v1/late-outcome takes the exact model-outcome body plus originalEpoch:uint64 and originalRecoveryGeneration:uint64. It follows [SU-04](../data-model/00-data-model-overview.md#rule-su-04) lock order and creates no Chat message before the actual turn output. Operator destructive-action execution likewise enlists the affected owner's existing operation family, while operator authorization/audit records are committed with the receipt; it never writes foreign module tables.

## 4. Workflow transitions and retry permission

| Durable state | Legal next action | Crash/retry outcome |
|---|---|---|
| created/queued | Claim, read immutable execution snapshot/current denial, assemble context | Missing CF workflow repaired by C# dispatch outbox with same ID |
| claimed, no intent | Admit model/tool; pause/cancel can release uncommitted holds | Safe to replay reads/admission by same ID |
| model intent committed | Workflow records fenced dispatch token before entering one external step | Configure model step retries=0; restarted/ambiguous step reconciles, never automatically calls again |
| model call complete, commit unacknowledged | Retry same model-outcome body/ID | C# returns same output; no new inference |
| output committed, settlement absent | Retry settle only | Durable parts survive; next model invocation waits for disposition |
| tools proposed | Persist typed proposals/intent; group by declared conflicts | Max4 independent tool calls; owner command records decide safe replay |
| waitingApproval/waitingDevice/waitingCapacity/paused | Workflow waits on wake with bounded timer; C# remains readable | Release lease; on resume claim new epoch, reauthorize and revalidate remaining context/approval |
| unknownEffect | Owner status/idempotency → available CF evidence → deadline → explicit user resolution | Never infer no effect from no result; automatic CF retry cannot override this |
| terminal intent | Finalize from durable iteration refs | Retry same terminal command; already-terminal mismatch rejects |
| succeeded/failed/cancelled | Read/export/retention only | New retry creates an explicit new Run; no hidden continuation of old attempt |

Waiting timer reconciles every 60 seconds; configure Workers Paid Workflow steps=25,000, guard total step count at 24,000 (including waits), reserve remaining steps for final receipts/reconciliation and never silently reset the counter. A single wait cycle uses at most one waitForEvent plus one reconciliation step; sleep itself need not count. At the guard pause further effects and finalize with execution-limit reason only if no effect is unresolved; otherwise retain unknownEffect for C# reconciliation. Seven-day maximum and active work budgets together bound this.  lost wake events do not lose progress. Approval expiry defaults15 minutes; current higher-risk/local-presence policy may shorten it. Agent run active execution wall time defaults15 minutes (hard60); suspended waits excluded from active budget, absolute lifespan7 days; after that cancellation and unresolved-effect reconciliation still run. Defaults/hard maxima: model calls16/64, tool invocations64/256, tool parallelism4/8, no-progress3/3, context256 KiB/1 MiB and200/500 items. Policy can narrow, never enlarge hard limits. Workflow results/checkpoints contain references, not a full prompt/response; stream tail 4 MiB remains outside step payload.

During every long model/tool await, renew the60-second lease every 20 seconds in that same step activity. Renewal failure stops new calls and output delivery; the already sent effect remains unknown and reports only through the prior-intent outcome/late-evidence path. Model external step gets120-second deadline; tool deadline is descriptor value capped120 seconds unless it returns a durable ProductJobRef. No automatic retry of any possibly-dispatched model request: Workers AI does not provide a promised per-call exactly-once API or universal status lookup. Before-dispatch refusal may retry at most twice with a fresh supplier-attempt identity after C# admission. After-dispatch uncertainty follows existing customer-hold deadline and supplier-liability rules; missing CF usage is not free inference or zero tokens.

Cancellation sets durable C# control revision before signaling CF. It prevents new admission, cooperatively stops running work and withdraws pending approvals/undelivered tools. An already delivered device command reports its actual effect. Terminal output can win the row-locked race before cancellation; then cancel returns that terminal receipt. Cancellation winning first permits only interrupted/no-answer finalization and settlement of already authorized delivered work. Stale epochs cannot publish; late immutable supplier receipts are accepted by a reconciliation port only when tied to the original intent, with no new effect authority.

Schedules are C# deterministic jobs: unique(definitionId, definitionRevision, occurrenceKey), Task/occurrence/outbox in one transaction. Cron uses five fields minute/hour/day-of-month/month/day-of-week; list/range/step and *, no seconds/names/extensions; simultaneous restricted day fields use OR. Interval seconds >=60, aligned to startsAt UTC; IANA zone retained. DST gap skips; overlap policy earlier(default)/later/both, with both distinguished by scheduled UTC instant. Ask creates NeedsAttention, RunNow never shifts schedule; CatchUp <=5 in24h, Queue <=10, Replace waits for safe cancellation outcome, AllowConcurrent <=4. Durable App/Device events are authenticated owner events, not arbitrary user text; deduplicate eventId and enforce causation depth8, self-loop suppression and period budget. Device-event upload after an outage preserves original occurrence time and applies missed-run policy. External integration events remain deferred.

## 5. Live presentation and client recovery

RunStream holds stream_state and stream_chunk, with the existing fields and [SB-01](../17-agent-harness.md#rule-sb-01)–[SB-09](../17-agent-harness.md#rule-sb-09) meaning. Append checks current fenced writer; chunk/read <=64 KiB, flush250 ms, max 4 MiB, tail TTL10 minutes, state marker24 hours. It receives no permission to commit Chat/usage. UTF-8 code-point boundaries define offsets; exact uint64 offsets use JSON decimal strings. New provider attempt creates a new streamId; no concatenation with a prior attempt.

Frames {kind:header|delta|state, taskId, streamId, attemptId, fromOffset, nextOffset, text?, originKinds?, streamState?, successorStreamId?}; header precedes deltas and includes origin kinds. DO appends chunk/state atomically before live send. Backpressure permits <=256 KiB queued per socket; slow clients close with a resumable gap, not memory growth. HTTP result {streamId?,fromOffset,text,nextOffset,streamState,taskState,taskRevision,attemptState?,currentStreamId?,iterationOutputRef?,finalMessageRef?,noAnswerReason?,retryAfter?}. Task/attempt/final references are read from C# on every range read. No live state/expired DO can fabricate Task completion or eviction of durable messages.

Proto EventService.Poll carries all existing17 hints; initial clients use unary bounded polling everywhere. Foreground active Task/bridge poll2s, other visible lists15s, idle60s; jitter20%, maximum one in-flight per scope, back off1/2/4/8/30s on transport failure. Native server-streaming hints may be added only as an equivalent optional transport; they are not a correctness prerequisite. Reconnect/auth change always reconcile authoritative cursors/snapshots; never resubmit a Task merely because presentation disappeared. Web/RN foreground transition refreshes session, then Task/status, then stream tail; background push contains IDs only.

## 6. R2 lifecycle and independent recovery

Bindings: OBJECTS (private immutable content), STAGING (private multipart), BACKUP (locked immutable primary backups). Bucket names are deployment inputs; keys are realm/<realmId>/workspace/<workspaceId>/<class>/<resourceId>/<sha256>; class attachment/export/simulator/ai/diagnostic/managed. No public bucket/custom public URL and no cross-workspace deduplication that leaks existence. resource.beginUpload reserves declared storage and issues a session-bound facade ticket for 10 minutes; resource.renewUploadTicket rechecks current admission without extending the24-hour upload session. multipart session lasts24h, Verified provisional pin24h, unreferenced staging removed after 24h. 8 MiB fixed parts (last shorter), <=10,000 parts, exact hash/length and signed part receipts; resume returns accepted part inventory. Do not interpret ETag as SHA-256.

Worker streams each part into R2 without whole-object buffering. Completion seals the part list and returns UploadStatus(verifying), then a durable object-verification Workflow performs streaming SHA-256/length/type validation and calls the verification port. GetUploadStatus reports eventual verified/failure without replaying completion. CF DigestStream supplies streaming SHA-256; bounded R2 range/multipart I/O avoids holding the object in memory. The verifier is a bounded Worker/Workflow activity separate from the AI decision loop; no model or AI debit. Whole-object SHA256 is computed over concatenated bytes, not hashes. R2 writes immutable final bytes before PG Verified status; owner references promote Verified→Committed with exact quota/pin/reference changes in the existing SU transaction. Failed owner commits leave a visible expiring pin; a sweeper cannot race a locked promotion. Reads require Committed or a specific authorized verifier/export job pin. Objects become inaccessible on logical release before physical deletion; tombstones prevent offline resurrection.

Transfer authorization checks each8 MiB part/range, not only ticket issuance. User download tickets never expose a directly reusable R2 presigned URL. Signed server-to-server S3 requests are permitted for C# backup/restore with restricted credentials. Resource controls quota; CF byte receipts supply metering facts. Native local transfer uses its local authenticated owner channel and the same bounds, not the CF facade.

Primary backup uses R2 bucket-lock rules by immutable backup prefix, configured at deployment; do not assume S3 ObjectLock per-object APIs exist on R2. Independent copy is AWS S3 in a separate provider/account, versioning + Object Lock COMPLIANCE 30 days, backup-writer with no delete/retention-shortening right. Primary backup protection30 days; PITR WAL/base backups30 days; user-history/trash and commercial retention remain their existing separate policy. C# streams SigV4 S3 PUT/GET/HEAD with explicit canonical signing and bounded HttpClient, while PostgreSQL backup tooling is one-shot infrastructure tooling, not a second business process.

Backup manifest {backupId,realmId,recoveryGeneration,dbBaseId,walStart,walEnd,publicationWatermark,objectRefs:[id,hash,size,versionId],workerVersion,contractVersions,configVersion,createdAt,retainedUntil,signature}. Pin referenced immutable objects until both copies are verified. A backup is complete only after DB recoverability and every referenced object hash are proven; save does not wait for copying. RPO metadata5min/object15min, RTO4h default operational target; alert on objective breach. Daily checksum samples, monthly small restore, quarterly full cross-provider drill.

Restore into fresh realm deployment infrastructure while preserving its logical realm/data IDs, bump recovery_generation, invalidate sessions/leases/tickets, rotate service secrets, recover PG+referenced objects, discard DO streams/Workflow checkpoints and search projections, reconcile all intents/usage/outboxes from PG, then create new recovery-generation Workflow IDs only for safe continuations. Never redial uncertain model/tool acts. Rebuild derived indexes before their ready flag. A deletion coordinator records CF Workflow/DO/R2/search/live/session purge separately; user content erasure completes only when online copies are purged and declared locked backup retention expires. It cannot promise immediate deletion of immutable backups.

## 8. Session bindings, inference jobs and deployment transitions

SessionBinding = {realmId:Id, workspaceId:Id?, userId:Id, sessionId:Id, authEpoch:uint64, deviceId:Id?, origin:string?, recoveryGeneration:uint64, expiresAt:Instant, bindingMac:bytes}. C# returns it only after validating the presented credential and signs it under a distinct service-binding key. CF retains this bounded reference instead of user cookies/refresh/access handles. Every frame/range presents it to C# for fresh row/policy checks; the MAC is not cached authorization. Session expiry blocks presentation and new interactive commands, but does not cancel an already authorized unattended automation solely because a browser went idle. Run admission rechecks its recorded owner/delegation/service/control state; device/session revocation cancels only work dependent on that revoked grant according to the existing lifecycle.

Embedding/reranking are bounded fixed-stage inference jobs in this same Worker deployment, not another planning loop. C# Search owns the queued job, source pins, index target and published result; Agent/Commerce/Entitlement supply their existing admission/usage ports under the explicitly enumerated inference-job transaction families. Search owns the platform-job authority; no customer settlement is created. Job identity replaces run identity on the explicitly inference-job ports; it never fabricates an Agent Task or makes keyword search depend on AI.

Lease/generation loss stops dispatch/publication; prior-intent late evidence can update supplier liability but cannot publish stale/unauthorized data. Terminal/safe recovery follows C# canonical job state, not CF checkpoint existence. Worker deployment admission/version observation is the same as for RunWorkflow.

Unknown outcome follows the existing supplier-liability reconciliation ladder without releasing uncertain exposure at a lease/period boundary. Keyword results remain available while semantic readiness is false. Partial/missing result cannot mark an index ready. There is no invented customer settlement prerequisite for a platform job.

Before CF code deployment, gate new dispatch through the C# configuration head while reads and current compatible runs continue. Publish the Worker artifact, observe the actual Worker/Workflow version IDs through CF deployment/instance APIs, test its HMAC/contract/config acknowledgement, then atomically switch the manifest/config and reopen admission. Passing requiredWorkerVersion in JSON cannot itself choose a CF code version. Dispatch verifies the deployed binding and persists the version actually returned by create/get; a mismatch rejects admission before inference. Existing instances must remain protocol-compatible for their seven-day maximum; retain the previous code/protocol/config until those runs are terminal or safely reconciled. Do not restart them to obtain new code. A breaking checkpoint/DO change requires the existing expand/contract and quiescence/restore procedure; no automatic old-code rollback after incompatible writes. WP06 and WP52 verify the real provider's observed behavior.

Object verification uses max 300,000 ms active CPU per step, <=8 MiB buffers and bounded range I/O; each idempotent copy-part checkpoint stores only part receipt/offset. DigestStream hash state is not serializable: after interruption the whole-object hash pass restarts from immutable staged bytes, at most two retries, never from concatenated part hashes and never reuploading client content. Deadline/CPU exhaustion returns a visible failed verification and retains the declared cleanup window; it never promotes partial data. WP06/WP25 must measure the largest admitted object against the selected limits before enabling that quota. Config cannot advertise a size/rate beyond the tested verifier envelope. This is an execution-capacity gate, not permission to invent another parser, hash algorithm or business upload state.

Workflow checkpoints/results contain refs only (<=128 KiB), and context/reconcile paging preserves one snapshot hash across pages. Lease loss invalidates its continuation; on new claim reauthorize/rebuild the same immutable source set or report a conflict. Never persist prompts/stream text merely to avoid a bounded result.
