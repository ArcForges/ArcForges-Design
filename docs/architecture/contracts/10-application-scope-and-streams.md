# Application Scope, History and Public Streams

Authority: P2-012. This annex extends [wire registry 04](04-protobuf-wire-registry.md), preserving existing operation behavior, field numbers and error codes. All new request/response names, tags and presence follow its method-envelope convention. Contracts implements the handwritten proto and generates NuGet/npm/Maven artifacts; no production proto is copied into Design.

## 1. Public transport and routing

Every first-party business client uses binary gRPC-Web over HTTPS at `/api/<proto-package>.<Service>/<Method>`. Desktop uses `GrpcWebHandler(GrpcWebMode.GrpcWeb)`; Web uses `createGrpcWebTransport` with binary messages; Android uses Connect Kotlin's gRPC-Web protocol. HTTP/1.1 and HTTP/2 are admitted. C# ASP.NET Core gRPC-Web middleware terminates public RPC; the Worker preserves request body, streaming response body, cancellation and encoded gRPC-Web trailers. It must not buffer the whole response or cache authenticated calls. Browser cookies/CSRF and native bearer sessions keep their existing rules.

Existing business methods remain unary. Add only the server-streaming methods below; no client-streaming or bidirectional business RPC, SignalR, first-party public AI WebSocket or custom event JSON protocol is required. OAuth/OIDC redirects and callbacks, passkey standard payloads, signed object upload/download bytes, supplier webhooks/APIs, FCM, and authenticated private C#/Worker binding calls are explicit protocol exceptions. They do not define a second business CRUD API. Public AI subscription/admission/read-control uses this same generated RPC surface.

Container public port 8080 stays private behind Worker ingress. The C# stream service authorizes the execution/scope, reads the private DO projection and emits generated public frames. Internal Worker/DO feeds use generated internal messages over an authenticated bounded HTTP stream; they cannot be opened by a public client. A server stream keeps its serving Container/DO resources active; no WebSocket hibernation cost assumption is allowed. Package-consumer tests must exercise real binary server streaming in C#/browser/Android, not substitute Connect's default wire protocol or unary Hello World.

TranscriptRole = 0 unspecified, 1 user, 2 assistant, 3 tool, 4 system. `CompactionRecord`: 1 compactionId:Id, 2 branchId:Id, 3 throughOrdinal:uint64, 4 sourceHash:Hash, 5 summary:Text, 6 modelId:ModelId, 7 policyVersion:Key, 8 createdAt:Instant, 9 summaryHash:Hash. Tool pairing is structurally verified but cannot prove an effect, approval or usage receipt.

Current Send text remains parts (tag 5); history uses exactly one of transcript/transcriptObject, both absent for an empty previous history. Object content is the same typed TranscriptWindow, ≤8 MiB, hash/length verified, bound to the originating installation/turn through a transientInput grant. Inline window plus envelope ≤256 KiB; max 2,000 messages and max 16,000 parts in either path. Above this bound the client builds a smaller eligible window or requests compaction; it never posts an unbounded unary request. Branch revision/hash changes refuse stale compaction attachment. Temporary mode cannot save a compaction record after its lifetime. See model 05 for the sole window algorithm and Harness HC-09 for protected content.

Append `RequestMeta.applicationScope` at tag 8, `ConversationView.applicationScope` at 10 and `historyMode` at 11, and `ToolRequest.targetApplication` at 16. Existing fields are not renumbered. `targetDeviceId` remains a compatibility projection matching the new target's device; new device tool requests require both to agree. Persist the application scope on every execution and derive scope for existing Task/Run/message/resource projections through the authenticated envelope/owner relation, not a client-supplied arbitrary row field. Older callers lacking scope are admitted only for realm/account APIs or an unambiguous server-bound installation; otherwise fail with the registered validation/upgrade reason, never route to a default unrelated product.

## 3. Exhaustive scope classification

Every operation in registry 04 belongs to one of these classes; WP03 emits the complete expanded manifest and rejects unclassified operations. Operation-specific authorization remains authoritative; this adds partition checks, not new permissions.

| Class | Existing services / operations | Required scope and owner |
|---|---|---|
| Realm/account | authentication/bootstrap, identity/profile/session/recovery, account commerce/entitlement/credits, policy/public configuration, support/account deletion, operations/admin | existing account/workspace scope; no assistant product filter imposed on an account-wide ledger or security view |
| Product data | Notes/Scope/Slate services, simulation, product sync/search/export/resource access | fixed owner product derived from service/resource; supplied scope must match; Notes queries cannot request Scope data |
| Assistant data | chat/conversation/branch/project/profile/skill/memory/automation, Task/Run/approval/tool execution and assistant search | mandatory ApplicationScope; owner rows and child resources inherit it; temporary/local bodies excluded from normal Cloud list/search/export |
| Device registration / tools | device installation/presence, remote action/claim/result/steering and device-targeted Task steps | ApplicationTarget and valid trust/delegation; no device-wide wildcard product grant; same product for all device steps in one execution |
| Events / content transport | EventService/ExecutionOutput methods, upload grants/download/export refs and notification links | scope copied from the authorized owner; mixed-product subscriptions rejected; account-security feed contains identifiers only and remains account-wide |
| Local application operations | former INotes/IScope/ISlate/IChat operations, context/artifact/lifecycle methods | in-process typed handlers of the current app; no product local gRPC endpoint or first-party peer discovery. Only the admitted device tool adapter may call them remotely through Cloud. |
| Helper/extension | LocalBootstrap, Sandbox, restricted Extension/Connector and parent resource grants | private parent-owned generated gRPC over Named Pipe/UDS; no public Cloud exposure or cross-app registry |
| Deferred | IHubRegistry/IHubRouting and DeviceSsoBrokerService discovery/routing/cross-app SSO and cross-product handoff/federation | excluded from current generated service registration, UI and tests; stable historical names reserved for the [future plan](../../future/cross-product-collaboration/README.md) |

For assistant retrieval, imported own-app uploads and explicitly authorized web-search sources are admitted; another product's source is not. Resource IDs still carry origin/owner/availability semantics. A caller cannot bypass this by placing another product's resource inside a generic context list. Account administrators do not gain implicit content access; existing support/break-glass rules remain.

## 5. Stream lifecycle and recovery

One events stream and at most two output streams per foreground application profile. Server closes normally after 5min; heartbeat every 15s, client reconnects after 45s silence. Reconnect exponential full jitter from 0.5s to 30s, resets after 30s stable connectivity. Background Android closes streams; FCM carries opaque attention IDs and reopening fetches current state. No persistent Android foreground service solely for chat connectivity. Browser hidden-tab throttling is tolerated by the same cursor protocol.

Authorization and scope are checked before open and at least every 15s against current authority; revoke/epoch/generation changes terminate with a typed frame/trailer without further body. Slow readers have≤256 KiB queued data; overflow emits reset/terminates, never drops bytes while reporting contiguous output. DO projection retention for normal events follows the existing24h/10,000-hint scope cap; execution output follows the normal/transient retention profile. Exact sequence/offset/hash rejects duplicates and gaps; duplicate identical frame is harmless, conflicting same-position content fails integrity.

No cursor: server returns a reset/snapshot requirement with a scoped high-water cursor; client obtains the authoritative snapshot and resumes after that high water so changes during snapshot are replayed idempotently by revision. Expired cursor: same snapshot path. Durable output uses readOutput and final hash; model token arrival is not an authoritative commit. An interrupted stream with no terminal outcome displays reconnecting/interrupted, never complete. Permission failures do not retry until a new authorized session exists; overload/unavailable retry within the bound; unknown command outcome is resolved by its command receipt.

## 6. Remote targeting and acceptance

Presence lists applications underneath each device. Selecting ArcNotes on deviceA creates a target-specific view; it does not retarget an existing conversation, automation, pending approval or command. Execution records freeze product/device/installation, and each delivered request includes the current instance epoch. The target rechecks local grants, current revision, resources, egress and presence-required risk. Another application on the same device cannot claim it. Restart requires re-registration with a new epoch; interrupted work reconciles its receipt instead of executing under the stale epoch. Offline commands retain existing bounded expiry/unknown-effect rules; no silent fallback to another device/product.

Contract fixtures include different products with identical titles, mismatched resource owner, forged target, stale epoch/approval, Cloud vs local/temporary history, promotion lost acknowledgement, large 64 bit cursor and partial binary stream/trailer. WP03 publishes schemas and three-language fixtures; WP06 proves transports; WP22–26 implement state; WP31/49/52 replace every named fixture with real deployed consumers. Publication means compatible immutable artifacts exist, not that all product runtime gates have passed.

## 7. History archive, scope and internal projection closure

`assistant-history.v1` is a length-delimited protobuf archive, not arbitrary JSON. Its first record is `HistoryArchiveHeader`: tags 1 formatVersion:Key,2 productId:Key,3 sourceConversationId:Id,4 sourceRevision:uint64,5 title:Name,6 branchCount:uint64,7 messageCount:uint64,8 resourceCount:uint64. Each following `HistoryArchiveRecord` is oneof tags 1 branch:HistoryBranch,2 message:HistoryMessage,3 resource:ResourceVersionRef; `HistoryMessage` tags 1 message:MessageView,2 ordinal:uint64,3 createdAt:Instant; `HistoryBranch` tags 1 branchId:Id,2 parentBranchId:Id?,3 forkMessageId:Id?. Trailing manifest is `HistoryArchiveEnd`: tags 1 recordCount:uint64,2 precedingBytesHash:Hash. Count/hash/order/UTF8/type/range limits are verified before visibility; max 1 MiB per record, resources follow existing verified upload limits. Within each branch, message ordinals are unique and contiguous from 0; archive ordering does not determine chronology. A branch graph must be acyclic and every fork/message/resource resolve within the declared snapshot or admitted owned resource set. No credential/grant/pending execution is imported.

Import derives fresh destination conversation/branch/message IDs deterministically from importId plus source ID using the existing canonical UUID profile; explicitly use UUIDv5 with importId as namespace and the canonical source UUID string as name, recording the mapping. An existing source UUID is never used to overwrite a destination object. Rewrite only declared internal references; preserve external provenance/anchors. Stage checked records in batches≤100 with unique(importId,sourceId), then activate one visibility pointer atomically. Delete/failed import unpins only its own staged objects; it cannot delete source data. Stale source snapshots are copied, not merged implicitly.

`IChatOperations.OpenArtifact`/preview/navigation opens inside the current owning application; the Handoff method is retired and reserved. Any requested different product is unsupported in the current service/tool allowlist. Parent-owned helper resource transfer is separate. No local discovery or cross-product content transport is enabled by retaining a compatibility type name.

Internal RunStream projection schema lives in Contracts internal proto and uses the same StreamFrame output/reset/heartbeat variants with authenticated ExecutionOwner/attempt/generation metadata. The Cloud Worker exposes it only through a service-bound private handler to C#; public routing rejects that path. Current C# owner authorization precedes opening and is refreshed as specified above. Internal bytes are not a second authoritative event schema.

The [scope manifest](11-operation-scope-manifest.md) fixes every existing mapped operation. `PreferenceService.Put` additionally validates the declared preference owner: account preferences keep account scope; product/device preferences require matching product/installation. ConnectorService management uses assistant application scope and current workspace/user connection permission; ConnectorBrokerService alone is a private helper boundary. Account-wide export/DataService and notifications resolve their actual owner without turning a global security event into a product grant.

## 8. Effective operation metadata

For all 13 added methods, `capability=absent`, `stepUp=no`, `localPresence=no`, and `actorKinds=human owner through the bound first-party client session`; none is an agent/automation/extension tool. Native background heartbeat/ack/recovery acts on that already authenticated installation without obtaining a new grant. Read paths enforce owner permissions; a future tool exposure would need an explicit catalogue change. The remaining effective fields and compatibility/retry classes are fixed below. These values feed catalogue 00 AZ-04/IR-01/CC-01 and the WP03 manifest.
