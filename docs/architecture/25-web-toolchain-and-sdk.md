# Web Toolchain, Generated SDK and Developer Workflow

> Status: **Authoritative** — Phase 2 (Detailed Specifications)
> Layer: Architecture
> Governing authority: [P2-021](../decisions/phase-2-specification-decisions.md#rule-p2-021) (C#-first Web: Blazor WebAssembly, C# static Site generator, NuGet SDK), [P2-023](../decisions/phase-2-specification-decisions.md#rule-p2-023), [D-009](../decisions/phase-1-foundation-decisions.md#rule-d-009), [D-021](../decisions/phase-1-foundation-decisions.md#rule-d-021). The React/TypeScript baseline of [P2-008](../decisions/phase-2-specification-decisions.md#rule-p2-008) is superseded 2026-10-08 by P2-021.
> Companions: [Web architecture](10-web-architecture.md), [solution layout](01-solution-and-project-layout.md), [build architecture](14-build-packaging-and-release.md)

This is the implementation contract for the Web boundary. Handwritten proto in Contracts is authored business wire authority; C# owns business behavior and the Web UI logic. The .NET build produces the public static Site at build time and the Blazor WebAssembly application assets; production assets are served by Cloudflare Workers Static Assets, and all dynamic business requests execute in the existing ASP.NET Core Cloud host. The thin Worker adapter runs on the Cloudflare Workers runtime, and Node.js runs only the wrangler deployment tooling; Node.js is not a build, test or runtime dependency of any Web profile.

**Source/configuration policy.** New C#, Razor and tooling source carries the applicable SPDX header. JSON manifests use their licence metadata; JSON cannot acquire invalid comment headers. Repository policy recognizes `.razor`, `.razor.css` and `.cs` sources explicitly. Shared `Directory.Build` imports are conditioned on project type so the Web projects never inherit settings intended for the Cloud host's Native AOT graph.

**Browser compatibility authority.** All outputs and generated clients consume [browser-support.v1](../requirements/12-quality-and-compatibility-contract.md#202-browser-supportv1). Web pins exact resolved browser/test versions at release freeze. The Chrome/Edge 134 and Firefox 136 build floors are carried from the superseded React baseline and are re-baseline-pending: they are re-derived for the Blazor build under browser-support.v1 by [PRF.11](../planning/delivery/lanes/runtime-proofs.md#task-prf-11) (P2-021 item 2; [P2-023](../decisions/phase-2-specification-decisions.md#rule-p2-023)) before they are a release claim. The Safari row and every macOS browser row are to be removed from browser-support.v1 under [P2-023](../decisions/phase-2-specification-decisions.md#rule-p2-023) decision 1; that removal is pending the requirements correction in [requirements/12](../requirements/12-quality-and-compatibility-contract.md), which still lists them. macOS is not a supported browser tier and is never claimed. Real current/previous-stable suites, capability-denial UI and Watch→Poll/ReadOutput recovery are required; no moving bundler default, security polyfill or unchecked in-app WebView is a supported fallback.

**Content Security Policy.** The application profiles are specified to serve `script-src 'self' 'wasm-unsafe-eval'` plus required hashes, never `unsafe-eval` or `unsafe-inline`, and `style-src 'self'`. This is a **proposal, not yet approved**: the user has not recorded approval of `wasm-unsafe-eval` or of the Virtualize consequence, and if it is not approved the Web app-profile build in WEB.40 stays blocked. The exact token set is asserted only after PRF.11 and that decision are recorded. Components that need inline styles are not used. The public Site serves a strict CSP without `wasm-unsafe-eval` ([P2-021](../decisions/phase-2-specification-decisions.md#rule-p2-021) item 2).

## 2. Independent Web repository

ArcForges-Web owns apps/site (the C# static public generator and its output), apps/app (Blazor WebAssembly account, chat, operations and ArcScope library/reports/simulator console route profiles of one standalone release set, per [P2-021](../decisions/phase-2-specification-decisions.md#rule-p2-021) item 2; status is an external-provider page/link, not an apps/app profile), packages/ui (AGPL Razor component library), tooling/, tests/ (xUnit and bUnit), the solution and project files, `Directory.Packages.props` and the NuGet lock files, and the thin `worker/index.js` with its wrangler manifest. It consumes the Apache-2.0 generated C# client packages from Contracts; there is no local SDK source tree, Cloud ProjectReference or native build dependency. Portable `dotnet` commands work without Visual Studio, and the IDE entry delegates to those same commands with an explicit restore, with no implicit restore/build race.

Development may start an exact released Cloud container or explicit built candidate from an independently checked-out Cloud repository. F5 identifies its image/endpoint and waits for health; no automatic second business host is launched. Account and Chat development origins are distinct hostnames, not only different ports. Only a reviewed dev profile permits dev certificates/hot reload; no dev proxy/CSP relaxation enters release.

## 3. Proto to C# (NuGet SDK)

Contracts handwritten public proto → pinned protoc/C# generation → released descriptors and compatibility fixtures → Apache generated C# NuGet client → Web/Android consumers. [Wire registry](contracts/04-protobuf-wire-registry.md) fixes every numbered field, method, exact value, error and previous/current case. Business proto is not generated from C# handlers/OpenAPI. The former protobuf-es (TypeScript) generation retires with `@arcforges/proto` under [P2-021](../decisions/phase-2-specification-decisions.md#rule-p2-021) item 4, after its consumers migrate.

### 3.1 Exact wire values

Use protobuf int64/uint64 for all 64-bit counters and integer microcredits, mapped to C# `long`/`ulong` with exact arithmetic; JSON exceptions use canonical decimal strings. Money uses exact decimal string (C# `decimal` with the scale fixed by the wire registry), capture time uses signed ticks and reduced rational, GUID uses canonical 16 bytes, scalar null/absent is explicit. No double-precision conversion is used for any 64-bit value; the display of integers beyond the safe range is exact int64/uint64/decimal, which replaces the former JavaScript safe-integer boundary with equal strength. These preserve the complete content-origin/Scope profile oracles. No number coercion or metadata-only OpenAPI transformer may change actual bytes. [Independent vectors](contracts/04-protobuf-wire-registry.md#2-exact-values-canonical-identity-and-evolution) are required in both directions.

### 3.2 Realtime and streaming

The Blazor client uses `Grpc.Net.Client.Web` with generated unary EventService.Poll plus authoritative reads. All 17 hints are optional and never commit state. CF output uses generated gRPC-Web server streams (binary server streaming is an unproven hypothesis until [PRF.11](../planning/delivery/lanes/runtime-proofs.md#task-prf-11) observes it; `application/grpc-web-text` on server-stream routes only if the binary proof fails) and durable unary recovery; Unicode offsets, supersession, truncation and final-message reference follow the shared CF contract. No SignalR package, client streaming, bidi streaming or mandatory fetch-streaming path remains.

## 7. Selected Web baseline

Web retains the existing visual design, accessibility requirements and design-token values, re-expressed as Razor components, scoped CSS custom properties and C# state. The Tailwind CSS, shadcn/ui-derived and Motion library choices of the superseded React baseline are not carried into the Razor Web; they are an **open design-system decision for [WEB.40](../planning/delivery/lanes/web.md#task-web-40)** under [P2-021](../decisions/phase-2-specification-decisions.md#rule-p2-021), matching the Design system row of section 1, and no design-system package is admitted until that decision is recorded. WP02 pins reviewed stable .NET versions and NuGet lock files in the producer; prose version numbers are not an alternate dependency lock. Outputs are site (static HTML), account, chat, operations and the ArcScope library/reports/simulator console (Blazor WebAssembly profiles; [P2-021](../decisions/phase-2-specification-decisions.md#rule-p2-021) item 2). Root paths are apps/site, apps/app, packages/ui, tooling, tests, the solution and project files, `Directory.Packages.props`, and the thin `worker/index.js`; Apache clients come from released Contracts NuGet packages. No npm UI workspace and no SDK source tree is introduced.

[Mobile](11-mobile-architecture.md#3-runtime-libraries-and-lifecycle-baseline) owns the .NET MAUI Android stack; Web consumes only its declared package/route profile. [Wire registry](contracts/04-protobuf-wire-registry.md) owns public schemas and adapters.
