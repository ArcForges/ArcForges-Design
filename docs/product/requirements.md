# V2 requirements

All rows are mandatory current requirements. Acceptance is observable; current implementation status belongs to the audit and Plan, not to this table. Source facts versus unproven platform combinations are in [platform capabilities](../verification/platform-capabilities.md).

| ID | Requirement | Acceptance | Design |
|---|---|---|---|
| R-PROD-001 | One general CLI Sandbox/Run product, no internal AI/tool interpretation. | Local and remote start use the same Core with no Task DAG/session/cache prerequisite. | [spec](../architecture/01-system-overview.md) |
| R-PROD-002 | Local operation works offline without account or subscription. | Unenrolled node can create/start/stop/delete; Center loss/expiry does not stop local runs. | [spec](../product/product-definition.md) |
| R-PROD-003 | Self-hosted remote management is free and independent of official entitlements. | Self-hosted Center and dashboard work with official service unavailable. | [spec](../architecture/11-identity-commerce.md) |
| R-PROD-004 | Only official hosted access is subscription gated. | Expired official account cannot create a hosted channel/command but local data and execution remain available. | [spec](../architecture/11-identity-commerce.md) |
| R-MXC-001 | Use pinned official stable MXC SDK/executor without fork or copied engine. | Admitted source, package, native payload hashes, license, schema and cohort are recorded. | [spec](../architecture/02-mxc-integration.md) |
| R-MXC-002 | Windows profile verifies process, path, network and resource composition before payload execution. | Official executor plus ConPTY and outer resource Job pass native positive/negative tests; no DACL fallback. | [spec](../verification/mxc-experiments.md) |
| R-MXC-003 | Linux profile verifies Bubblewrap, PTY and systemd/cgroup composition. | Native delegated cgroup limits/readback and deny policy hold for descendants; no direct-process fallback. | [spec](../verification/mxc-experiments.md) |
| R-MXC-004 | Unsupported combinations are explicit and fail closed. | Start returns capability reason before admission; profile support cannot be inferred from backend presence alone. | [spec](../architecture/02-mxc-integration.md) |
| R-SBX-001 | Persistent Sandbox CRUD with owner-scoped identity, revision and private root. | Concurrent creates/configures/deletes serialize; inspect returns exact policy and data identity. | [spec](../architecture/03-sandbox-run-model.md) |
| R-SBX-002 | Configuration snapshots and explicit host permissions govern every Run. | Access-changing configure requires stopped runs; an old Run cannot silently gain a new grant. | [spec](../architecture/03-sandbox-run-model.md) |
| R-RUN-001 | Run starts explicit argv/environment in one Sandbox and owns descendants. | No shell interpolation or automatic retries; identity snapshot and resources precede execution. | [spec](../architecture/03-sandbox-run-model.md) |
| R-RUN-002 | Genuine terminal mode supports TUI, stdin/output, signals and resize. | Native PTY/ConPTY probe, full-screen redraw, Ctrl+C and window resize pass on both profiles. | [spec](../architecture/06-local-node-cli.md) |
| R-RUN-003 | Attach/detach preserves lifetime with one writer and bounded replay. | Disconnect/lease expiry detaches; stale lease writes fail; lost spool interval produces GAP. | [spec](../architecture/07-lifecycle-recovery.md) |
| R-RUN-004 | Stop and natural exit reconcile whole owned group. | Raw executor exit is separate from authoritative group-empty; unknown ownership never kills a reused PID. | [spec](../architecture/07-lifecycle-recovery.md) |
| R-RUN-005 | Node restart, supervisor failure and machine reboot have distinct outcomes. | Node rebind does not replay Start; supervisor loss fails closed; reboot records interruption without auto restart. | [spec](../architecture/07-lifecycle-recovery.md) |
| R-RES-001 | Observe host, unmanaged and managed CPU/memory with units and freshness. | Unknown data is not zero; Windows commit and Linux cgroup memory are labeled accurately. | [spec](../architecture/04-resource-management.md) |
| R-RES-002 | Reserve host headroom and coordinate total and per-Sandbox/Run grants. | Sum of grants respects admitted budget and configured ceilings under concurrent starts. | [spec](../architecture/04-resource-management.md) |
| R-RES-003 | Expose requested, applied and OS-read-back limits and failures. | Failed/mismatched apply is never shown effective; unsafe increase is refused. | [spec](../architecture/04-resource-management.md) |
| R-RES-004 | Priority/weight and pressure responses are bounded and explainable. | Pure budgeting regressions retained; pressure actions honor preemptibility and avoid repeated victim loops. | [spec](../architecture/04-resource-management.md) |
| R-FILE-001 | Configurable private roots gather intended state without universal redirect promises. | Home/config/cache/temp/work data persists; host read/write grants and noncaptured writes are explicit. | [spec](../architecture/05-filesystem-data.md) |
| R-FILE-002 | Usage and import/export remain within owned Sandbox data. | Chunks and manifests reject traversal/reparse/ADS/case collisions and verify length/hash before commit. | [spec](../architecture/05-filesystem-data.md) |
| R-FILE-003 | Delete is previewed, revision-bound, use-locked and recoverable. | Running/deleting races refuse; no host grant, foreign root or unresolved journal is deleted. | [spec](../architecture/05-filesystem-data.md) |
| R-CLI-001 | Normal local CLI is the primary complete execution path. | CLI covers Sandbox, Run, resources, data and doctor with stable JSON/exit errors and no login gate. | [spec](../architecture/06-local-node-cli.md) |
| R-SEC-001 | Protected owner-authenticated IPC and secret minimization. | Wrong user/unauthorized caller rejected; payload cannot reach Node IPC/metadata or injected host credentials. | [spec](../architecture/08-security-trust.md) |
| R-SEC-002 | Remote grants default off and cannot widen host authority. | Revoked/stale grants, replayed channels and arbitrary methods fail at Node Core. | [spec](../architecture/08-security-trust.md) |
| R-SEC-003 | Mutation receipts expose certainty and stable idempotency. | Same ID/same payload replays receipt; conflicting payload fails; UNKNOWN requires reconciliation. | [spec](../contracts/README.md) |
| R-SEC-004 | Audit, redaction and retention protect activity data. | Control changes have correlation/effect records; logs/exports exclude secrets by default and have bounded retention. | [spec](../architecture/08-security-trust.md) |
| R-CTR-001 | Go Center retains identity, accounts, device enrollment and secure outbound channels. | Fresh and rotated enrollment, reconnect, revoked epoch and per-device visibility pass. | [spec](../architecture/09-go-center.md) |
| R-CTR-002 | Typed remote Sandbox/Run/Resource actions share local constraints. | Remote Start/Stop/configuration and resource bounds match local checks; offline command is not blindly queued. | [spec](../architecture/09-go-center.md) |
| R-CTR-003 | Remote observation/files are bounded and stale-aware. | Output cursors/gaps and transfer quotas are enforced; disconnect and unknown delivery are visible. | [spec](../architecture/09-go-center.md) |
| R-WEB-001 | Responsive Blazor shell, sign-in and device overview. | Overview/Devices and account routing work for self-host and official origins without browser secrets. | [spec](../architecture/10-blazor-dashboard.md) |
| R-WEB-002 | Complete Sandbox/Run and resource management pages. | List/detail/config/start/stop/delete previews/log/exit and budget actions invoke actual APIs and show pending/error/offline. | [spec](../architecture/10-blazor-dashboard.md) |
| R-WEB-003 | Security and account/subscription pages explain real authority. | Grant revocation, device security, entitlement/checkout state and self-host mode are accurate. | [spec](../architecture/10-blazor-dashboard.md) |
| R-WEB-004 | Accessible responsive UX and bounded live data. | Keyboard/focus/labels/contrast and narrow viewport flows pass explicit manual checks; reconnect does not duplicate commands. | [spec](../architecture/10-blazor-dashboard.md) |
| R-HOST-001 | Keep billing assets and build official provider lifecycle without guessed prices. | Signed idempotent webhooks/reconciliation, expiry/refund state and unconfigured-provider dark mode pass. | [spec](../architecture/11-identity-commerce.md) |
| R-HOST-002 | Self-host and official operations include deploy, backup, restore, audit and cost limits. | Existing guarded deploy path and PostgreSQL recovery exercised in approved venue; no official dependency in self-host. | [spec](../architecture/11-identity-commerce.md) |
| R-MIG-001 | Freeze old tasks/design and audit actual code and consumers. | Immutable snapshots retain original state/evidence; all active tasks are new planned AFV2 tasks. | [spec](../reuse/disposition.md) |
| R-MIG-002 | Published contracts are immutable; V2 is explicitly versioned. | No old field IDs/meaning repurposed; independent products build; finite caller cutover is documented. | [spec](../data/migrations.md) |
| R-MIG-003 | Node and PostgreSQL migration preserve applied history and unresolved effects. | Fresh, Node15, Center10 and Center11 upgrade/backup/restore paths pass without editing applied SQL. | [spec](../data/migrations.md) |
| R-MIG-004 | Retired runtime, routes, dependencies and live schema are actually removed. | Inventory detects no active Task/Attempt/MCP/AI/cache/worktree/mobile/desktop/C# Center path after cutover. | [spec](../reuse/disposition.md) |
| R-DIST-001 | Signed coherent native AOT distributions carry admitted MXC runtime. | Windows/Linux publish and install prove cohort integrity and prerequisites; no unexplained AOT/trim warnings. | [spec](../architecture/12-distribution-updates.md) |
| R-DIST-002 | Updates drain/rebind safely with honest schema rollback. | Live supervisor and incompatible-store cases fail or migrate safely; backup restoration is demonstrated. | [spec](../architecture/12-distribution-updates.md) |
| R-TEST-001 | Source facts, assumptions and real-host tests are distinguished. | Every unproven combination has evidence owner/procedure; no fake pass or substitute host status. | [spec](../verification/platform-capabilities.md) |
| R-TEST-002 | Plan and design are mechanically self-consistent and directly executable. | Task fields, DAG, required native evidence, removals, rollback, traceability and archive hashes validate. | [spec](../verification/acceptance.md) |
| R-TEST-003 | Full V2 acceptance requires both native profiles and remote/local/business journeys. | Mandatory engine, terminal, resources, files, recovery, self-host and official tests complete before activation. | [spec](../verification/acceptance.md) |
| R-PERF-001 | Record runtime cost instead of promising unsupported performance. | Measure cold/warm launch, idle Node/supervisor CPU/RSS, terminal throughput, sample overhead with OS/cohort/p50/p95. | [spec](../verification/acceptance.md) |
| R-CTR-004 | Bounded account recovery, export and deletion revoke server authority without harming local data. | Single-use proof/epoch/rate limits and durable lifecycle receipts pass; local Runs/data survive account deletion. | [spec](../architecture/11-identity-commerce.md) |
