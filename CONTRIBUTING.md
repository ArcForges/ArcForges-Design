# Contributing to ArcForges Design

All changes are reviewed through pull requests from a dedicated Git worktree and a focused branch.

## Change rules

1. Identify the owning document category before editing.
2. Use the appropriate template for new requirements, architecture specifications, decisions, or work packages.
3. Update every affected canonical document in the same pull request.
4. Update traceability when a requirement, boundary, decision, risk, or acceptance criterion changes.
5. Do not treat source material in `docs/inputs` as normative.
6. Do not claim implementation, test, deployment, or release completion without actual evidence from the implementation repository.
7. Keep each pull request focused on one coherent design change.

Accepted decision records are append-only. A changed decision requires a new record that supersedes the earlier record.
